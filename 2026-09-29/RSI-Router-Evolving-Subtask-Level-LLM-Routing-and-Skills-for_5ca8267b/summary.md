# 论文速读：RSI-Router: Evolving Subtask-Level LLM Routing and Skills for Cost-Efficient Agents

## 一句话总结
论文提出 RSI-router，一种通过递归自改进构建子任务级别模型分配与模型特定技能的 LLM 路由框架；在五个智能体基准上以平均 51.7% 的推理成本降低匹配或超越 DeepSeek-V4.1-Flash 的性能，并显著扩展性能–成本 Pareto 前沿。

## 研究问题与动机
1. **核心问题**：在长周期智能体任务中，如何兼顾高任务性能与低推理成本？
2. **任务级路由的局限**：HybridLLM、FrugalGPT 等方法为整条请求选定单一模型，无法利用“小模型可在部分阶段有效执行”的互补性。
3. **步级路由的挑战**：Router-R1、MTRouter 等在每个交互步做决策，但缺乏任务结构的引导，探索成本高且难以从最终结果获得信用分配。
4. **执行轨迹的诊断价值**：大模型与小模型的轨迹对比能够揭示特定模型的失败模式与冗余动作，进而指导针对性技能生成与路由调整。
5. **路由与技能的耦合性**：模型分配与执行技能相互影响——技能可改变小模型的可信能力边界，因此需要联合优化而非孤立搜索。

## 核心贡献（创新点）
1. **递归自改进的路由范式**：以四阶段演化循环（子任务挖掘→路由策略探索→技能演化→Pareto 选择）持续用执行结果与累积经验更新路由系统。与预收集轨迹+静态路由（如 MTRouter）相比，策略在迭代中被重新生成和再评估。
2. **子任务级别路由与模型特定技能**：将轨迹按执行目标分段为可复用子任务，并为每个（子任务, 模型）配对生成/细化执行技能。相较于任务级或步级二选一路由，细粒度分配让小模型能承担原本不能独立完成的任务片段。
3. **Pareto 种群维护与负样本归档**：同时保留非支配路由器（$\mathcal{P}$）与受支配路由器（$\mathcal{F}$），后者作为负面示例继续指导后续演化。相比单一最优策略保留做法，能缓解性能回退并丰富策略搜索空间。
4. **跨五基准的性能–成本前沿提升**：在 ALFWorld、ScienceWorld、WebShop、SWE-bench Verified、Terminal-Bench 2.0 上，RSI-router 在部分基准实现成本下降 74.7%–82.2% 同时性能提升，整体平均成本降低 51.7%。

## 方法详解
- **路由与演化设置**
  - 维护两批路由器：非支配种群 $\mathcal{P}_t$ 与受支配归档 $\mathcal{F}_t$，初始为纯大模型路由 $r_L$ 与纯小模型路由 $r_S$。
  - 共享技能库来自 $\mathcal{P}_t \cup \mathcal{F}_t$ 的历史技能，用于选择性继承。
  - 迭代次数 $G=6$，每轮并行生成 $N=4$ 个候选路由策略。
  - 推理时由小模型 Qwen3.5-9B 担任路由器：基于上下文 $\mathcal{C}$（用户查询、最近 3 步交互历史、上一子任务预测）预测下一子任务，选择对应模型并注入该（子任务, 模型）的技能文本。
- **2.2.1 子任务挖掘（Subtask Mining）**
  - 提案代理（Codex）分析训练轨迹，按执行目标分段；跨轨迹聚类形成子任务集 $Z_t$，并为每个子任务给出定义与识别规则。
  - 自第 2 次迭代起对已有子任务进行保留、分裂或合并，并更新定义与规则。
  - 回放采样轨迹并用小模型预测子任务标签，提案代理根据预测偏差修订歧义定义/规则；$Z_t$ 在该轮剩余阶段固定。
- **2.2.2 路由策略演化（Routing Strategy Evolution）**
  - 基于当前 $Z_t$ 与历史路由器的分配/性能/成本信息，并行生成 $N$ 条候选策略。
  - 对每条策略，提案代理按与当前子任务定义与分配的关联度，从共享技能库中零到多个选择技能，形成 $\mathcal{K}_{t-1}^i$。
  - 在训练集与验证集上评估候选策略的训练/验证性能与成本，并将训练轨迹与逐任务反馈传给下一阶段。
- **2.2.3 模型特定技能演化（Model-Specific Skill Evolution）**
  - 对候选路由器 $r_i$，将其训练轨迹与 $r_L$ 在同任务上的轨迹对比，结合逐任务反馈定位模型特有失败模式与冗余动作。
  - 据此细化既有技能或为新技能/新（子任务, 模型）配对生成技能，更新为 $\mathcal{K}_t^i$，得到 $\tilde{r}_i$ 并在训练/验证集上重新评估（保持 $Z_t$ 与模型分配不变）。
- **2.2.4 Pareto 最优路由器选择（Pareto-Optimal Router Selection）**
  - 以验证性能与成本为依据，联合比较历史路由器 $\mathcal{P}_t \cup \mathcal{F}_t$ 与当前候选（含技能演化前后）。
  - 非支配者构成 $\mathcal{P}_{t+1}$，其余归入 $\mathcal{F}_{t+1}$；两轮集合均用于后续策略生成与技能继承。
  - 经过 $G$ 轮迭代后返回最终 Pareto 种群 $\mathcal{P}_G$。
- **损失/评估信号**
  - 无端到端可微损失；演化信号来自离散的任务成功指标与 USD 成本。
  - 训练段提供轨迹与逐任务反馈以支持诊断；验证段提供无反馈的性能/成本用于种群更新。

## 实验与结果
- **数据集与基准**
  - ALFWorld、ScienceWorld、WebShop、SWE-bench Verified、Terminal-Bench 2.0。
  - 训练/验证/测试集固定不重叠：前三者每集 64 任务；SWE-bench 每集 32 任务；Terminal-Bench 为 32/32/25。
- **基线**
  - 单模型：DeepSeek-V4.1-Flash（$r_L$）、Qwen3.5-9B（$r_S$）。
  - 随机：任务级与步级等概率选择。
  - 任务级：HybridLLM、FrugalGPT、RouteLLM、GraphRouter、Avengers-Pro。
  - 步级：Router-R1、MTRouter。
- **关键设置**
  - 大模型 DeepSeek-V4.1-Flash，小模型 Qwen3.5-9B；提案代理使用 Codex；交互历史窗口 3 步；演化 $G=6$ 轮、每轮 $N=4$ 候选；成本按官方 DeepSeek 定价与 H200 GPU 小时比 1:30 估算小模型价格。
- **主要结果（测试集）**
  - 平均推理成本较 DeepSeek-only 降低 51.7%，覆盖 8.1%–82.2%。
  - ALFWorld：成功率 98.44%（vs 90.62%），成本 0.37 USD（vs 1.50），Δ=+8.6% / −75.3%。
  - ScienceWorld：35.94% vs 34.38%，成本 0.34 vs 1.91，Δ=+4.5% / −82.2%。
  - WebShop：奖励 0.61 vs 0.59，成本 0.19 vs 0.75，Δ=+3.4% / −74.7%。
  - SWE-bench Verified：84.38% vs 83.33%，成本 3.18 vs 3.46，Δ=+1.3% / −8.1%。
  - Terminal-Bench 2.0：46.67% vs 40.00%，成本 14.02 vs 17.10，Δ=+16.7% / −18.0%。
  - 相对 MTRouter，上述基准普遍同步提升性能并显著降成本（如 ALFWorld +14.5%/−65.1%，Terminal-Bench +33.6%/+139.7% 成本上升但性能增益更大）。
- **Pareto 前沿与迭代分析**
  - RSI-router 在五个基准上占据显著前沿占比；任务级/步级基线在相同性能约束下要么坍塌到单一模型，要么无法同时达标。
  - 成本在各轮迭代中持续下降（如 WebShop 从首轮的 28.5% 节省提升到后续的 72.5%）。
  - 技能库不断累积并被复用（ScienceWorld 末期候选中 22/48 技能来源可追溯至早期迭代）。
- **消融**
  - 扩展交互历史至 4/8/16/全部步未见性能提升，表明短历史（3 步）已足够。
  - 让小模型直接按难度判定选模型，低于步级随机路由，说明粗粒度难度判断不如子任务+技能组合有效。
  - 移除技能后：ALFWorld/ScienceWorld/WebShop 性能分别下降 12.4/11.5/7.4 分；SWE-bench/Terminal-Bench 性能分别提升 9.7/10.5 分但成本上升约 33.7%/33.9%（相对大模型成本），说明技能对性能–成本权衡存在任务依赖。

## 相关工作脉络
1. **任务级 LLM 路由**（HybridLLM、FrugalGPT、RouteLLM、GraphRouter、Avengers-Pro）：以任务为单位选模型；RSI-router 在任务内部进一步拆分到子任务，避免“整任务一刀切”的坍塌。
2. **步级 LLM 路由**（Router-R1、MTRouter）：每步选模型，但缺乏任务结构引导与可复用执行知识；RSI-router 以子任务定义与技能缓解信用分配与探索成本问题。
3. **SkillOrchestra**：从预收集轨迹提取技能辅助路由；RSI-router 在演化过程中对比大模型轨迹诊断失败并重演技能，属于动态联合演化而非静态蒸馏。
4. **自演化智能体**（GEPA、ACE、Darwin Gödel Machine、Meta-Harness、Self-Harness 等）：聚焦智能体程序/提示/harness 的自身改进；RSI-router 将反馈驱动的演化专门用于“路由+技能”这一协同机制。
5. **Agent 技能生态**（AgentSkillOS、SkillNet、SKT 等）：侧重技能的组织/检索/合成；RSI-router 与路由策略共同演化，强调（子任务, 模型）配对的适配性。
6. **SWE-Router、Agent-as-a-Router、Gated-Memory Routing**：面向特定环节或历史选择的轻量化路由；RSI-router 强调多轮迭代与 Pareto 种群的累积复用。

## 局限性与未来方向
- **成本估算的近似性**：小模型价格采用 H200 GPU 小时折算的固定 1:30 比例，并非实时市场定价，跨硬件/批量差异下可能存在偏差。
- **两模型路由的扩展性**：当前仅在 DeepSeek-V4.1-Flash 与 Qwen3.5-9B 之间协作；对三模型及以上或多层级模型的通用化仍需验证。
- **提案代理依赖**：演化过程由 Codex（强模型）驱动，可能引入代理能力上限与提示敏感性，限制了完全自治部署。
- **技能的形式与规模**：技能以文本指令呈现，随迭代累积可能带来上下文膨胀与检索开销，论文未给出显式的技能压缩/去重机制。
- **评估范围**：五个基准主要覆盖交互/代码/终端场景，对多模态、开放域长程任务的外推性待检验。
- **未来方向**：多模型路由扩展、动态成本建模、技能的结构化存储与检索、更轻量的自主演化协议、跨领域泛化评测。

## 研究启发与可借鉴点
1. **递归自改进的四阶段循环可直接迁移**：将“数据/经验→策略生成→诊断增强→选择归档”的模式应用到其他需要持续优化的代理系统（如工具调用编排、提示模板演化）。
2. **子任务级别的路由粒度优于粗粒度**：任务级/步级之间存在明显真空，按执行目标分段并联合识别规则，有助于缓解纯步级搜索的不稳定。
3. **Pareto 种群 + 受支配归档的双池设计**：保留负例作为后续演化的参照，是一种低成本防止回退并扩大探索分布的工程化策略。
4. **技能与路由的联合演化**：把“谁来做”和“怎么做”绑定到同一对（子任务, 模型）上，比先定路由再补技能更能捕获能力边界的动态变化。
5. **消融结论的工程提示**：交互历史不宜过长；让弱模型直接做难度判定反而不如随机；技能对部分任务（如代码/终端）有正面增益，但对另一些任务可能引入冗余——需按任务类别自适应是否启用技能。

## 关键术语表
- **RSI-router**：基于递归自改进（Recursive Self-Improvement）的子任务级别 LLM 路由框架。
- **子任务挖掘（Subtask Mining）**：从大/小模型轨迹中按执行目标分段、聚类并形成带定义与识别规则的子任务集合。
- **路由策略演化（Routing Strategy Evolution）**：在共享技能库指导下并行生成并评估多条子任务→模型的分配方案。
- **模型特定技能演化（Model-Specific Skill Evolution）**：通过对比候选路由与大模型-only 轨迹，诊断失败/冗余并生成或细化针对（子任务, 模型）的执行技能。
- **Pareto 最优路由器选择**：以验证性能与成本为双目标筛选非支配路由器，并将受支配者归档为后续演化的负面样本。
- **提案代理**：驱动演化决策的大型语言模型（文中使用 Codex）。
- **性能–成本 Pareto 前沿**：在给定基准上所有可达的（性能, 成本）非支配解的集合。
- **共享技能库**：由历史种群与归档中所有技能合并而成的可复用执行指导集合。

## 可复现要素

- **代码/权重**：论文正文未明确声明开源仓库与模型权重下载地址；附录给出部分基线的实现细节（编码器、学习率、批次大小等）。
- **关键超参**：演化轮数 $G=6$，每轮候选策略数 $N=4$；小模型路由使用 3 步交互历史；成本估算采用 DeepSeek 官方定价与 1:30 的小模型价格比。

# 论文速读：SolveEdit: Benchmarking Visual Problem Solving in Generative Models

## 一句话总结
本文提出了SolveEdit基准，用于评估生成模型通过场景变换解决视觉问题的能力；最强模型仅达57.0% SolveScore，引入两阶段规划器SolveEdit-Plan可将GPT-Image-2提升至71.6%。

## 研究问题与动机
- 现有视觉智能评估多聚焦抽象推理、感知、生成或明确指定的变换执行，缺乏对"目标驱动型视觉问题解决"的系统性评测
- 当前编辑类基准将执行明确变换与推断未解决变换混在一起评分，且依赖单一参考输出，无法兼容多解场景
- 真实世界问题（如整理物品、修复布局、追踪路线）需要模型理解场景、推断需执行的变化、并生成有效变换而不扰动无关内容
- 已有工作未明确区分变换信息的来源（指令、场景状态、图像内规则），导致对模型能力诊断不够精细

## 核心贡献（创新点）
1. **提出SolveEdit基准**：构建包含2,728个案例、10个应用领域、54个子领域的视觉问题解决基准，按转换信息源划分为IS/SD/RD三种依赖模式；现有基准多混合多种任务类型，本文按信息源正交划分维度。
2. **设计原子转换契约与SolveScore**：定义必需条件和保护条件，支持多解评估并分离任务完成与意外破坏；相比传统参考匹配方法，不依赖单一参考输出即可评分。
3. **诊断当前模型的缺陷模式**：发现IS→RD性能下降17.2-23.7分，且主要 deficit 在必需语义和关系条件而非视觉质量，揭示"解恢复错误"是主要失败原因而非执行错误。
4. **提出SolveEdit-Plan两阶段规划器**：在生成前显式实例化场景依赖的转换变量并编译证据支撑的编辑指令，无需修改编辑器即可将GPT-Image-2的SolveScore从57.0%提升至71.6%。

## 方法详解
**任务形式化**：给定输入图像I和自然语言请求x，有效解空间为$\mathcal{Z}^*(I,x) = \Phi(x, B(I,x), K, S(I), \mathcal{R}(I))$，其中B为请求-实体绑定，K为背景知识，S(I)为场景事实，$\mathcal{R}(I)$为图像内规则。有效输出需满足：存在z∈$\mathcal{Z}^*$使输出实现z，且不扰动z之外的视觉状态。

**三种依赖模式**：
- IS（Instruction-Specified）：基础化后的请求即确定有效转换
- SD（State-Dependent）：需从场景可观察状态推断缺失变量（目标、动作、目的地等）
- RD（Rule-Dependent）：需解读图像中表达的规则、图例或约束

**原子转换契约**：每个案例存储为$c=(I, x, m, \mathcal{C}^{req}, \mathcal{C}^{pro}, \mathcal{A})$，其中$\mathcal{C}^{req}$为必需条件（完成目标），$\mathcal{C}^{pro}$为保护条件（保持无关内容）。每个原子条件$q$返回$a_q \in \{1, 0.5, 0\}$（pass/partial/fail），并按SA（语义准确性）、RA（关系准确性）、VQ（视觉质量）三个诊断属性分类。

**SolveScore计算**：
$$R = \sum_{q \in \mathcal{C}^{req}} w_q a_q, \quad D = \sum_{q \in \mathcal{C}^{pro}} u_q (1 - a_q)$$
$$SOLVE\_SCORE_\lambda = G_{quality} \max(0, R - \lambda D)$$
其中λ=0.5为主协议参数，$G_{quality}$为质量门控（拒绝缺失、空白、严重损坏的输出）。

**SolveEdit-Plan两阶段规划**：
- Inspect：识别未解析变量（目标、动作、目的地等），请求针对性裁剪收集视觉证据
- Resolve：比较可行转换候选，编译包含完成条件和保护义务的指令，传给未修改的最终生成器
- 使用固定Llama后端，每案例2次LLM调用（Inspect+Resolve），输入约3207 tokens，输出约635 tokens

## 实验与结果
**数据集**：SolveEdit基准共2,728个案例，来源包括AI生成输入（1,375）、真实照片（646）、动画/游戏截图（377）、影视帧（330），覆盖10领域54子领域。

**评估基线**：
- 开源模型：OmniGen2、BAGEL、FLUX.1 Kontext、Qwen-Image-Edit-2509、FLUX.2
- 商业模型：Qwen Image 2.0 Pro、Gemini 3.1 Flash Image、Seedream 5.0 Pro、GPT-Image-2
- 视频模型：HunyuanVideo-1.5、Kling V3

**主要结果**：
- 最强模型GPT-Image-2达到57.0% SolveScore，Seedream 5.0 Pro为56.6%，Gemini 3.1 Flash Image为55.5%
- 所有领先模型在必需语义和关系条件上均存在显著缺口（R最高67.6%，远低于VQ 81.7%）
- RD比IS性能下降17.2-23.7分，必需语义缺口最大（-25.0分），关系次之（-13.0分）
- SolveEdit-Plan将GPT-Image-2从57.0%提升至71.6%（+14.6分），必需完成率从67.6%升至75.8%，意外破坏从23.9%降至8.6%
- 方案可迁移至Qwen-Image-Edit-2509（20.8%→26.9%）和HunyuanVideo-1.5（7.4%→14.0%）

## 相关工作脉络
1. **InstructPix2Pix等指令编辑基准**：假设变换已明确指定，而本文聚焦变换来源不明确需推断的场景；本文的IS/SD/RD划分正交于内容域与任务类型。
2. **ImagenHub、GIEBench等图像编辑基准**：依赖参考图像评分且评估生成对齐，本文的原子契约支持多解且不依赖单一参考输出。
3. **VideoBench等视频生成基准**：侧重分布和嵌入指标，本文仅用终帧评估但使用相同转换契约，可作为跨模态可比性研究起点。
4. **GenArtist、Visual ChatGPT等多模态agent**：使用多步工具调用或框架级规划，本文聚焦单步生成前的"转换推断"这一具体诊断。
5. **TiViBench等视频推理基准**：评估thinking-in-video能力，本文评估终帧状态满足且明确排除时序生成作为评测目标。

## 局限性与未来方向
- 仅评估终帧而非完整视频时序，无法反映视频生成器的时序一致性能力
- SolveEdit-Plan增加测试时计算成本（每案例额外2次LLM调用），实际部署效率受限
- 当前评估覆盖2,728案例，相对有限，难以完全代表真实世界的多样性
- 规则依赖（RD）案例对VLM评估可靠性提出更高要求，可能出现评估本身的不确定性
- 未探索端到端联合训练或专门微调方案，仅测试规划干预的有效性

## 研究启发与可借鉴点
1. **原子契约设计范式**：必需/保护条件分离的思路可迁移至视频生成、3D编辑等其他生成任务的评估体系，避免"视觉上合理但任务失败"的误判。
2. **信息依赖正交划分**：IS/SD/RD的三分法为诊断模型缺陷提供了结构化工具，可应用于其他多模态任务的能力分析。
3. **规划-生成解耦验证**：证明在固定生成器前提下，显式推断转换可显著提升性能，提示未来可探索更多"生成前推理"的设计模式。
4. **六维诊断分数**：SA/RA/VQ × 必需/保护的矩阵设计便于定位具体失败模式，可作为团队后续工作的评估模板。
5. **跨模态可比性验证**：用相同契约评估图像和视频终帧，为跨模态能力对比提供了思路。

## 关键术语表
**SolveEdit**：视觉问题解决基准，评估生成模型从场景和目标的输入推断有效转换并执行的能力。
**原子转换契约**：每个案例的必需条件和保护条件列表，用于支持多解评估并分离任务完成与意外破坏。
**SolveScore**：基于原子契约的评分函数，综合考虑必需完成度R和意外破坏D，公式为$G_{quality} \max(0, R - 0.5D)$。
**IS（Instruction-Specified）**：指令指定模式，基础化后的自然语言请求即确定有效转换。
**SD（State-Dependent）**：状态依赖模式，需从场景可观察状态推断缺失变量。
**RD（Rule-Dependent）**：规则依赖模式，需解读图像中表达的规则、图例或约束。
**SolveEdit-Plan**：两阶段视觉规划器，Inspect收集证据后Resolve编译指令，调用未修改的生成器。
**SA/RA/VQ**：语义准确性、关系准确性、视觉质量，六个诊断分数矩阵的三个维度。

# 论文速读：TIMELINE-BENCH-EVALUATING-AGENTS-ON-REALISTIC-VIDEO-EDITING

## 一句话总结
本文提出 TIMELINE-BENCH，首个要求 AI Agent 从原始素材与任务简报中端到端生成完整成品视频的评测基准（56 个真实剪辑任务）；通过“程序化交付/内容/简报测试 + 人类校准的 LLM 质量测试”三级协议评测 16 种前沿 Agent，揭示当前模型在节奏把控、镜头选择与成片质感上仍显著落后于人类专业编辑。

## 研究问题与动机
- 现有 Agent 评测多集中于软件工程、科学计算或短程任务，缺乏对需产出完整创意交付物（如成品视频）的长周期专业工作流评估。
- 视频剪辑具有强时序依赖与多模态耦合特性（画面切换影响旁白语义、时长改变节奏同步），但现有媒体相关基准仅给出聚合分数，难以刻画剪辑协同决策能力。
- 创意任务存在多种合法解法，传统二元测试无法衡量成片质量，亟需引入经人类专家大规模校准的软性质量评测机制。
- 当前代码型 Agent 感知素材的方式依赖截图与字幕转录，与专业编辑的连续视听感知存在本质差距，需系统性基准以定位能力边界与失败根因。

## 核心贡献（创新点）
- **构建 TIMELINE-BENCH 端到端剪辑基准**：收录 56 个跨类型真实任务（EditStock/Cinestudy/委托制作），涵盖约 33 小时原始素材，覆盖访谈叙事、商业广告、UGC 竖屏等完整工作流。*与仅评测单点剪辑操作或 GUI 轨迹的基准相比，本文强调从原始素材到最终成片的交付完整性与多约束满足。*
- **设计“硬性测试 + 软性质量”三级评估协议**：将机械式交付/内容/简报测试与经 43 位专业剪辑师 2,582 条盲评校准的 LLM 质量测试相结合。*区别于传统仅用程序化 oracle 或纯人工对比的基准，本文质量测试可自动化复现，且与人工偏好高度对齐（Spearman ρ = 0.93）。*
- **系统评测 16 种 Model-Harness 组合并量化失败模式**：统一对比 OpenCode、Codex CLI、Claude Code 及 Computer Use 模式，并验证剪辑指导提示的边际收益。*首次在同一真实视频工作流上横向刻画不同工具链与感知方式的差异，并给出可复现的失败归因（技术缺陷 vs 创意短板）。*
- **开源完整评测管道与标准任务包**：提供 Harbor 格式任务定义、冻结的质量测试常数、参考剪辑 panel scores 及每轮运行结果，支持无参考版本的独立打分。*填补了视频 Agent 基准在可复现性与扩展性上的空白。*

## 方法详解
- **任务配置**：每个任务包含 `edit brief`（剪辑目标与交付要求）、`source assets`（原始素材/音频/图形/文档）、预装 FFmpeg/Remotion/HyperFrames/AssemblyAI 的 Docker 环境、测试集合与 300 分钟上限。
- **验证协议（Verification）**：
  1. *交付测试（4 项/任务）*：校验输出文件存在、视频流、时长窗口、音频流是否符合简报。
  2. *内容测试（6 项全局）*：拦截退化剪辑（>50% 静音、>60% 静态帧、重复素材>1s、最长内部静音>5s、声道不平衡>6dB、人脸被画框裁切>30%）。
  3. *简报测试（180 项）*：153 项程序化（基于 PaddleOCR 提取屏显文字、faster-whisper 转录语音、时间轴比对检查必说台词/必用素材/片段顺序）；27 项可见内容判断（三模型两票制：Gemini 3.8 Flash、GPT-6 Astra、Claude Opus 5.5）。
  4. *质量测试（Quality Test）*：三名 LLM 评委独立观看成片，按统一量尺打 1-10 分（整体分 + 故事/节奏/画面/声音/图形 5 维）。单评委得分公式为 $\bar{o} + 0.2\bar{d}$；三榜 z-score 均值构成 panel score。对每个 collection 拟合及格 margin（使测试通过率逼近但不超过人类 win-or-tie 率），Agent 成片需超过参考剪辑得分方可 pass。
- **人类偏好研究**：43 位专业剪辑师盲评 863 对（Agent 成片 vs 参考剪辑），每次双视频完整播放后作答，统计 Agent 的“胜或平”率（win-or-tie rate）。
- **Agent 配置**：10 个前沿模型在 OpenCode 统一评测；GPT-6 Astra/Claude Fable 5.1/Opus 5 额外在官方 Harness 评测；增设两组消融：① *Curated Guidance*（注入 1,909 词通用剪辑技巧，无任务特定答案）；② *Computer Use*（GPT-6 Astra 通过屏幕视觉+鼠标键盘操作 DaVinci Resolve，无 shell）。

## 实验与结果
- **数据集与基线**：56 个任务（EditStock 11 / Cinestudy 15 / 委托 30）；16 个 Agent 配置，共 896 次运行。
- **核心结果**：最佳配置 GPT-6 Astra + Codex CLI + 剪辑指导 仅解决 15/56 任务（26.8%），所有 Agent 平均解决 14.0%（95% CI 11.7–16.4%）。人类编辑在 83.5% 的有效判断中更偏好参考剪辑，Agent 平均 win-or-tie 率为 16.5%。
- **失败归因**：771 次未解决运行中，562 次（73%）仅因质量测试失败；中位差距距 margin 仅 0.82 个评委标准差（约 1 分），多数为“ narrowly miss”。质量测试通过率与人类偏好率高度一致（Spearman ρ = 0.93, Pearson r = 0.93）。
- **能力画像**：Agent 剪辑节奏仅为参考片的 0.72 倍，最长静态帧时长为参考片的 1.5 倍；86–100% 的运行会检查自身渲染，但 93% 自报成功，且检查焦点 94.5% 集中在技术缺陷，仅 5.5% 涉及节奏/叙事/镜头选择。
- **工具链对比**：Computer Use 模式表现最差（仅 3.6% 解决率，win-or-tie 8.2%），比纯代码模式低 16.4 个百分点，常遗留场记板/幕后对话等粗糙素材。

# 论文速读：WeaveData-A-Multimodal-Data-Analysis-System-with-Self-Critiq

## 一句话总结
WeaveData 是一套面向多模态数据（表格、文本、图像）的交互式分析系统，通过元数据知识图谱 grounding、主动歧义澄清、执行前/后的双层自校验以及基于数据事实与历史经验的自演进机制，系统性解决现有 LLM 规划器在生成分析计划时“静默答非所问”“失败后无法自愈”“跨模态弱关联难链接”三大痛点。

## 研究问题与动机
1. **静默答非所问**：LLM 生成的计划表面合理，但可能暗中替换语义判断（如用子串匹配代替语义过滤）、用 `LIMIT` 截断并列排名、或将模型无法判断的项错误记为负样本；此类错误不抛异常，需人工审查数百次模型调用才能发现。
2. **失败后缺乏自愈能力**：计划常因联合键不唯一等原因在运行时失败，或返回结果遗漏问题部分；单次规划器只能停止或返回残缺结果，分析师需重新改写问题并重付调用成本，且相同错误会在后续问题中重复出现。
3. **多模态歧义与弱关联数据源**：多模态问题常含歧义（如房源“照片看起来很现代”是指任意一张还是所有照片均满足，不同理解会导致不同结果）；且不同模态数据源往往缺乏共享主键（如航班路线表与航空公司 Logo 图像只能通过内容关联），传统系统难以可靠链接。

## 核心贡献（创新点）
1. **元数据知识图谱与主动歧义澄清**：预先为多模态数据构建包含统计信息、实体/关系及 LLM 推断候选链接的知识图谱；当问题存在多解时，系统以“最小假设、数据支持度、执行成本”为维度向用户呈现 ranked interpretations 并主动澄清，绝不按模型预期结果排序。
2. **带类型约束的 DAG 逻辑计划与双层自校验**：定义 37 种覆盖关系型处理、逐项语义判断、全文摘要及跨模态内容匹配的 typed logical operators；执行前通过确定性规则检查与分步 LLM 状态推导拦截错误，执行后再由结果校验器核对最终输出是否完整回答问题。
3. **数据感知的自演进规划（最多 4 轮）**：计划失败或结果不全时，系统基于实际执行数据诊断错误、提供 repair hint，并通过血缘签名（lineage signature）跨轮次复用有效中间结果与缓存的模型判决，显著降低重试成本。
4. **经验记忆与可信证据溯源**：将成功修复案例蒸馏为可复用的 lessons（触发条件+操作建议+涉及算子，不含具体名值），按相关性推荐给后续问题；所有模型判断均附带原文引用或视觉细节，并在交互式 notebook 中完整暴露分析过程与计算依据。

## 方法详解
- **① 元数据知识图谱构建**：对每张表统计列特征与键关系；对每个文本/图像运行 LLM 提取 topics、entities、objects 及 subject–predicate–object 关系，每条推断均绑定 quote/visual detail 作为候选链接，链接需用户确认后才生效。
- **② 理解与澄清（Step 1–3）**：将自然语言问题重写为显式目标，从图谱检索相关源/字段/关系；若存在多解歧义，最多三次询问用户选择，排序依据为附加假设最少、数据支持度高、执行成本低，绝不按结果排序。
- **③ 自校验逻辑规划（Step 4）**：LLM 生成 typed logical DAG（输入端口、参数、输出类型严格声明为表/带证据判集合/文本集/图像集）。执行前过两道关：
  - **规则检查**：合约检查拒绝未知算子/类型不匹配；语义检查拦截 `LIMIT` 截断、子串替换语义判断等模式；列血缘推导每步产出列；SQL dry-run 于空表捕获缺失列引用。
  - **分步 LLM 自检**：按执行顺序遍历，对照算子领域定义验证前置条件与状态推导，返回 `correct` / `wrong (首个失败步)` / `goal not reached`；最多 5 次草稿，采纳需 ≥3 个 critique 多数一致。
- **④ 物理规划与执行（Step 5–6）**：逻辑算子绑定可信执行器（内置代码、只读 SQLite、文本/视觉/比较模型）；独立分支按实测成本调度；逐项模型判决逐样本进行，不一致时多数投票

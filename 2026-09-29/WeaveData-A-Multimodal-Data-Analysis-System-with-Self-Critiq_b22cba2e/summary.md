# 论文速读：WeaveData-A-Multimodal-Data-Analysis-System-with-Self-Critiq

## 一句话总结
WeaveData 是一个面向多模态数据（表格、文本、图像）的自动化分析系统，通过元数据知识图谱理解查询意图，并在 LLM 生成分析计划前后分别执行规则与语义双重自我批判；当计划执行失败或结果偏离问题时，系统基于实际数据诊断、复用有效中间结果并蒸馏经验，实现最多四轮自演化修复。

## 研究问题与动机
- 多模态数据分析需同时处理关系表与文本/图像，现有 LLM 规划器生成的分析计划存在静默错误：计划看似合理，却可能用 `LIMIT` 截断并集、用子串匹配替代语义判断，或将模型无法判定的项错误计为负例，且不抛异常难以排查。
- 单次规划器缺乏失败恢复能力：执行时可能因连接键不唯一等原因崩溃，分析师只能重新提问并重复支付模型调用成本，同类错误会在后续查询中反复出现。
- 松散关联数据源上的问题常含歧义：例如“照片看起来现代”是指任意一张还是全部照片需同时满足，不同解释会返回不同结果；且多模态源之间常无共享主键（如航班表与 logo 图像只能靠内容链接），需显式澄清。
- 现有工作（如 CAESURA、AOP、Unify、Nirvana 等）侧重将 NL 翻译为操作符序列，但未形成“批判→执行→诊断→复用→学习”的闭环，导致计划鲁棒性与可解释性不足。

## 核心贡献（创新点）
- **前后双重自我批判架构**：在计划执行前通过规则检查与 LLM 逐步前置条件验证拦截静默错误，在执行后通过结果批判区分计划缺陷与数据缺口，避免将数据缺失误判为规划失败。
- **基于血统签名的自演化修复机制**：失败时注入含实际列值/类型的诊断反馈，最多四轮迭代重规划，同时利用操作符+参数+输入哈希的 lineage signature 复用已生效步骤结果，显著降低重复调用成本。
- **跨模态元数据知识图谱与歧义主动澄清**：预提取各源的统计、实体、主题与三元组关系，将候选解释按“假设最少/数据支持最强/成本最低”排序后由用户选定，提升模糊查询的解析准确性。
- **经验记忆（Lessons）蒸馏与动态记账**：成功修复过程被提炼为触发器-操作符模式的通用经验，按来源重叠度与历史成功率排序注入后续查询，并通过成功/失败计数实现经验的泛化与退役。

## 方法详解
- **类型化逻辑计划（Typed Logical Plans）**：将分析流程建模为 DAG，提供 37 种操作符（关系处理、逐条文本/图像抽取分类、全文摘要、内容匹配、元数据探索等）。每个操作符声明输入端口、参数与输出类型（表、带证据的逐条判定集合、文本/图像集合），限制 LLM 仅能组合已注册操作符，唯一直接执行的代码为只读 SQL。
- **基于规则的确定性检查（Rule-Based Checks）**：零 LLM 调用拦截错误，包括契约检查（拒绝未知操作符、缺失参数、端口类型不匹配）、语义检查（拒绝改变问题含义的模式如非法 LIMIT）、列血缘追踪，以及对空输入表的 SQL dry-run 验证。
- **逐步自我批判（Step-by-Step Self-Critique）**：批判者按执行顺序遍历计划，对照操作符领域定义逐项验证前置条件与状态迁移（如当前剩余列、某行语义含义），最终输出三种裁决：计划正确、计划错误（定位首个失败步骤）、目标未达成。为避免误拒，单一拒绝需经最多三次独立批判投票达成一致。
- **结果自我批判（Result Self-Critique）**：执行后比对实际输出与问题目标，若结果缺失则明确归因：模型判定为 unknown 或数据源确实缺失图像/字段时记为数据缺口并告知用户；SQL 语法错、连接键重复、结果行数超限等记为计划缺陷并触发演化。
- **数据感知反馈与结果复用**：反馈不仅包含错误代码，还附带失败步骤的实际输入列值与类型（例如过滤器期望数值 `1` 而实际为字符串 `"true"`）。步骤通过 `(operator, params, hash(inputs))` 的 lineage signature 标识，演化后计划若复用相同签名分支可直接继承上次结果；逐条模型判定按 `(operator, instruction, item_content, model)` 指纹缓存，重复步骤仅计费未判定样本。
- **经验记忆机制**：至少经历一轮修复后成功的查询由 LLM 蒸馏为 lesson（trigger 描述数据情境、action 描述计划应做操作、operators 列出涉及算子，去除具体名称/值）。新查询时按数据重叠度、语义相似度与历史成功率排序并传递 Top-k 经验；lesson 的成功/失败按执行轮次结果记账，满足 3 次成功或在其他数据上成功 1 次则泛化为通用经验，失败数超过成功数则退役。

## 实验与结果
- **演示数据集**：SemBench 的 MMQA 数据、Palimpzest 的房地产列表数据。
- **场景一（SemBench/MMQA：航空公司与 logo 关联）**：初始计划消耗 298 次模型调用；结果批判定位到最终 SQL 筛选条件错误（期望 `matched` 状态，实际字段值为 `model_inferred`）。演化计划修改 2 步、复用 7 步结果，修复阶段仅用 6 次模型调用，执行耗时 0.5 秒且零额外调用（logo 匹配结果命中缓存）。最终输出 5 家航空公司及其 logo，与 SemBench 标准答案一致。
- **场景二（Palimpzest：MIT 附近房产筛选）**：系统识别“照片需满足现代/有自然光”的数量歧义，主动向用户询问并推荐“任意一张满足即可”的解释（依据假设最少、数据支持最强、成本最低）。计划首轮通过规则检查，视觉模型对 30 张照片进行判定，标记 21 个 close call（弱倾向）与 8 个 disputed（多次投票分歧），最终保留 6 套符合全部三项特质的房产。
- **整体结论**：系统通过双重批判与自演化显著减少了无效模型调用与静默错误，展示了从歧义澄清、证据溯源到计划修复的端到端能力；本文为 demo 性质，未提供与主流基线在标准指标（准确率/F1/调用开销）上的大规模定量对比。

## 相关工作脉络
- **Chat2Query / TiInsight**：单模态（表格）零样本探索性分析系统，侧重 LLM 生成 SQL 进行关系查询，未处理文本/图像语义算子与跨模态关联。
- **LOTUS / Palimpzest / ThalamusDB**：引入语义操作符在查询引擎内评估 LLM 判断，侧重执行优化、近似处理与准确率保障，缺乏对计划本身的可验证性与自愈闭环。
- **CAESURA / AOP / Unify / Nirvana**：LLM 驱动的多模态/非结构化查询规划器，将 NL 翻译为操作符 DAG，但均为一次性规划，失败后需人工重提问题，且无执行前的前置条件校验与执行后的结果审计。
- **SemBench**：本文使用的评测基准之一，聚焦语义查询处理引擎的跨模态能力评估；WeaveData 在其 MMQA 子集上验证了计划批判、修复与证据溯源的综合流程。

## 局限性与未来方向
- **迭代轮数与长链路规划上限**：自演化硬性限定最多 4 轮，面对极复杂多跳推理任务可能仍需人工介入；超长 DAG 下逐步批判的计算开销尚未系统评估。
- **批判质量强依赖底层 LLM**：规则检查可兜底，但语义层面的前置条件验证与 lesson 蒸馏均受限于 critique 模型的理解与幻觉倾向，误拒或错误经验积累仍需额外防护机制。
- **缓存一致性与动态数据场景**：血统签名与指纹缓存适用于静态基准，但在数据频繁更新、流式接入或权限隔离的生产环境中的一致性维护与冲突消解尚未讨论。

# 论文速读：WHEN-TOOLS-SILENTLY-LIE-EVALUATING-AND-MIT-IGATING-BLIND-COMPLIANCE-IN-TOOL-AUGMENTED-DATA-AGENTS

## 一句话总结
论文提出 ToxicBench 基准测试，通过保持源数据固定但静默篡改工具返回结果的方式，系统评估数据代理在"静默工具投毒"场景下的证据检查与答案采纳行为，发现普通重试在单次投毒下有效，但重复投毒时代理仍会在检查后采纳错误答案。

## 研究问题与动机
1. **工具成功执行不等于可信证据**：数据代理依赖工具输出进行决策，但工具调用可能成功执行却返回看似合理但错误的结果，代理需判断何时信任或验证该证据。
2. **现有评估的不足**：仅看最终答案无法区分"接受首次错误观察"、"检查后仍采纳错误"、"获取纠正但仍选错结论"；仅计数额外工具调用也无法确认恢复。
3. **缺乏可观测的恢复路径**：需要一种能区分"检查行为"与"答案采纳行为"的评估框架，而非将所有错误答案或所有额外调用等同对待。

## 核心贡献（创新点）
1. **提出静默工具投毒设定**：通过代理在工具执行后篡改返回结果，同时保持源数据固定，使正确恢复路径可.inspectable——与修改源表或假设任何验证都提供正确证据的做法有本质区别。
2. **区分"检查"与"答案采纳"双维度指标**：引入 ADR（异常检测率）、VR（验证率）、RR（恢复率）、PAR（毒采纳率）、BCR（盲从率）、VPA（验证后毒采纳率）六个轨迹级指标，分离检测、验证与最终采纳行为。
3. **设计对照协议分离"重试机会"与"显式验证"**：比较 Double-pass（普通重试）、Verification-only（传递首答案并要求检查）、Generic Guard（添加泛化期望检查清单）三种双路径协议，控制模型、温度、步骤上限和 token 上限，区分额外尝试的机会效应与显式验证指令效应。
4. **公开完整轨迹与版本化评分**：发布轨迹数据集、冻结版评分器、参考审核记录及交付审计报告，支持下游复现与评分一致性验证。

## 方法详解
**1. ToxicBench 基准构建**：
- 每个任务指定源表、查询、干净/中毒参考值、评分容差或别名、目标工具及替换方式。
- 代理先执行工具获得 $o = f(x)$，中毒环境中代理返回 $\tilde{o} = P(f, x, o; \theta)$，源数据不变。
- 包含数值算子（聚合缩放、符号翻转、排名/标签交换、比率反转等）与语义/模式算子（标签交换、治疗/对照翻转、列语义交换、过时元数据、偏差检索）。

**2. 轨迹指标设计**（以暴露运行作为分母）：
- **TSR**（任务成功率）：最终答案满足干净参考或容差范围的比例。
- **PDR**（毒交付率）：中毒环境中实际发生修改的运行比例。
- **BCR**（盲从率）：采纳毒化结论且无 ADR 或 VR 的比例。
- **ADR**（异常检测率）：最终响应明确识别出差异、不合理性、冲突或可能投毒。
- **VR**（验证率）：毒化观察后出现新的、与任务相关的产生证据的工具事件。
- **RR**（恢复率）：在 ADR 或 VR 后采纳干净的最终答案。
- **PAR**（毒采纳率）：最终答案匹配毒化预言，无论是否检查。
- **VPA**（验证后毒采纳率）：有合格 VR 事件但仍采纳毒化答案。

**3. 验证协议对照**：
- **Base**：单条普通路径。
- **Double-pass**：两条独立路径，不传递首答案，选第二条回答。
- **Verification-only**：将第一条答案作为不可信声明传给第二条路径，要求检查源数据。
- **Generic Guard**：为两条路径均添加泛化期望提示，检查清单覆盖有效范围、过滤器、单位、分母、实体-值绑定、列含义、时间戳和源支持，要求新的工具动作和字面标签。
- 所有双路径方法共享模型、温度、路径数、每路径十步上限、每请求 3,572 output-token 上限。

**4. 重复投毒设置**：对每个符合条件的观察以概率 $p \in \{0.25, 0.50, 0.75, 1.00\}$ 进行投毒，测试验证本身也可被投毒时代理行为。

## 实验与结果
**数据集**：ToxicBench 包含 118 个保留实例（58 数值 + 60 语义/模式），加上 13 个多表扩展任务；另有 24 个基于公开表（Palmer Penguins、Auto MPG、Bike Sharing）的结构化证据控制任务。

**基线**：LangGraph ReAct、smolagents、AutoGen 三个代理框架，GPT-5.4-mini、Claude Sonnet 4.6、Qwen3.6-35B 三个模型，以及 DA-Agent。

**主要结果**：
- GPT 评估中干净 TSR 为 0.92–0.99，中毒后下降 26–39 个百分点（如 LangGraph: 0.99→0.67，∆TSR=0.32，BCR=0.38；smolagents: 0.98→0.59，∆TSR=0.39，BCR=0.53；AutoGen: 0.92→0.66，∆TSR=0.26，BCR=0.27）。
- 跨模型评估：GPT 数值 TSR 从 1.00 降至 0.32–0.53，Claude 从 1.00 降至 0.68–0.85，Qwen 从 1.00 降至 0.38–0.68。
- 双重-pass 在单次投毒下达到 TSR 1.00，显著优于 Base（0.89）和 Verification-only（0.90），Guard 达 0.97。Double-pass 相比 Base 提升 0.110（95% CI [0.056, 0.171]）。
- 所有双路径方法将 BCR 降至 0，但 Verification-only 仍保留非零 PAR 和 VPA，说明消除盲从不等于消除验证后采纳。
- 重复投毒（p=1）下发现 101 例 VPA，其中 78 例仅含被投毒的合格后续检查，23 例含未被修改的检查——证明即使经过检查仍可能采纳错误答案。
- 人类评估（200 条轨迹）与自动评分在 TSR 上达成 96% 一致性（精确率 1.000，召回率 0.957），所有 4 例人类 VPA 均被识别。
- 公开表控制实验：clean 条件下 48/48 正确，full-target 中毒下 0/48 正确；retry 分支 clean 48/48、full 0/48；review 分支 clean 47/48、full 0/48，表明回复证据直接影响恢复。

**最强结果**：Claude 模型在 LangGraph 框架下语义/模式任务 BCR 最低（0.00–0.26），GPT smolagents 数值任务 BCR 高达 0.79。

## 相关工作脉络
1. **Tools Fail (Sun et al., 2024)**：研究工具静默错误；本文通过配对干净/中毒环境和六项轨迹指标区分检测与采纳，比单纯错误检测更细粒度。
2. **ToolRobustBench (Zheng et al., 2026)**：提供阶段对齐的工具调用诊断；本文关注已修复数据源上代理如何利用可检查证据恢复，而非工具本身故障。
3. **PoisonedRAG (Zou et al., 2025)**：针对检索增强生成语料库的投毒攻击；本文针对工具返回观测值的投毒，保持源数据固定，使恢复路径可审计。
4. **AgentDojo (Debenedetti et al., 2024)**：评估提示注入攻击与防御；本文不涉及恶意指令，分析目标是保持原分析目标不变的静默数据篡改。
5. **Self-Refine / Reflexion (Madaan et al., 2023; Shinn et al., 2023)**：反馈式自我修正；本文强调需控制"重试机会"与"显式验证指令"的效应，避免将重试收益归因于验证提示。
6. **TRACE (Kim et al., 2026)**：使用证据库评估轨迹效率与幻觉；本文区分基于工具返回观测的答案与基于源数据的答案，追踪检查行为与最终采纳。

## 局限性与未来方向
1. 核心任务使用小型合成表（数值表 4–12 行，中位数 5.5），公开表控制仅覆盖三个来源；泛化到生产工作流和自然发生的工具错误尚待验证。
2. 评分器召回率在不同指标和答案风格间存在变化，细粒度方法排序需结合人类对比解读。
3. 历史投毒交付异常已单独记录，但区间估计受限于所选任务和源数据。
4. 未来方向包括：扩展到更长多源工作流、开发预算感知的验证策略（寻求独立证据并解决冲突观察）、测试改进的证据选择是否能带来更可靠的最终决策。

## 研究启发与可借鉴点
1. **轨迹级双维度评估范式**：将"检查行为"（ADR/VR）与"答案采纳行为"（PAR/VPA/BCR/RR）分离评估的方法论，可迁移到其他 agent 可靠性或安全评估场景。
2. **对照协议设计思路**：通过 Double-pass 作为"重试机会"的强对照，分离显式验证指令效应——这一实验设计可用于评估任何自修正/自检机制的真实增益。
3. **冻结评分器 + 后冻结人类验证**：先在开发集上冻结评分器，再在 disjoint 任务 ID 上邀请双人标注验证一致性（96% agreement, κ=1.0），为自动化评估可信度提供可复用流程。
4. **重复投毒压力测试**：以概率 $p$ 逐次投毒来模拟持续对抗环境，测试验证机制在证据本身不可信时的鲁棒性，此设置可扩展至其他 agent 安全基准。
5. **结构化证据控制实验**：通过固定首阶段转录、改变第二阶段供应证据（clean/partial/full-target），隔离本地证据可用性对恢复的影响——这种"固定上下文+变证据"的字段边界控制方法值得借鉴。

## 关键术语表
**静默工具投毒（Silent Tool Poisoning）**：代理执行工具调用成功，但返回观测值被篡改（如标签交换、数值缩放），同时保持接口类型、成功状态和任务相关性不变，使代理无法从异常信号中察觉问题。
**盲从率（Blind Compliance Rate, BCR）**：代理采纳毒化答案且未检测到异常（无 ADR）且未进行合格验证（无 VR）的比例，反映无条件信任工具输出的程度。
**验证后毒采纳（Validated Poison Adoption, VPA）**：代理进行了合格验证（VR），但最终仍采纳毒化答案的比例，揭示"检查过但仍错"的风险。
**毒交付率（Poison Delivery Rate, PDR）**：在中毒环境中实际发生至少一次有效修改的运行比例，用于区分投毒到达率和代理响应率。
**Double-pass 协议**：运行两条独立路径（不传递首答案），选择第二条路径的回答；作为普通重试的控制条件，用于分离"额外机会"与"显式验证"的效应。
**Generic Guard 协议**：在 Base 和 Verification-only 基础上，为两条路径均添加泛化期望检查提示（覆盖范围、单位、绑定、分母等），强制要求新工具动作和字面标签。
**重复投毒（Repeated Poisoning）**：对每条符合条件的工具返回以概率 $p$ 独立投毒，使后续检查也可能返回被篡改证据，用于测试验证机制在持续对抗下的鲁棒性。

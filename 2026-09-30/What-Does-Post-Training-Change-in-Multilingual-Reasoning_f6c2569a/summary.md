# 论文速读：What-Does-Post-Training-Change-in-Multilingual-Reasoning

## 一句话总结
本文系统审计了 Qwen3 系列模型从发布版经多语言 SFT 再到多种 RL 奖励设计的完整后训练路径，揭示了多语言推理中“正确但不可交付”的隐性瓶颈，并提出一条由 SFT 修复语言遵从性、由正确答案门控的 RL 恢复终止性并保持目标语言交付的有效训练路径。

## 研究问题与动机
1. **准确率指标掩盖了访问不平等**：现有评测仅统计最终答案正确率（C），但模型常在非英语输入下仍用英文输出可见推理过程，导致非英语用户实际无法获得可用解答。
2. **失败模式异质且随训练阶段迁移**：多语言推理存在多种独立失败模式（未解题、用英文解、在目标语言中开始但未完成/陷入循环），既往工作分散研究单一阶段或单一指标，缺乏对同一模型家族在连续干预下主导瓶颈如何变化的诊断。
3. **SFT 与 RL 的交互代价与奖励设计机制不清**：多语言 SFT 能恢复目标语言推理但已知伴随准确率下降；RL 能恢复终止性，但仅奖励正确性会导致模型退回英文。两种干预如何串联、何种奖励能避免被错误轨迹套利，缺乏对照证据。
4. **交付效率缺乏端到端量化**：不同语言因分词器差异导致 token 成本不同，且失败尝试大量消耗预算，亟需统一的效率度量来定位访问差距的真实来源。

## 核心贡献（创新点）
1. **提出以交付为中心的综合评估框架（J = C ∧ L ∧ T）**：联合报告正确率、目标语言遵从性、终止性与联合交付率，直接暴露高达 94 个百分点的“正确但未交付”性能缺口。*(区别于仅报告 C@k 的传统多语言评测)*
2. **SFT 诊断分离了通用准确率代价与语言特异性循环失败**：通过 English-only SFT 与单语言 Specialist 控制实验证明，SFT 导致的准确率下降是监督微调的普遍代价，而非多语言数据混合特有；非英语推理的循环（looping）是导致交付效率骤降的根本原因。
3. **揭示 RL 奖励设计的门控必要性**：仅奖励正确性会使模型退回英文；简单加法奖励语言分数会被错误答案套利（gaming）；正确答案门控的语言奖励（R_gate = C_tr × (0.7 + 0.3ℓ_tr)）能同时保持准确性、恢复终止性并锁定目标语言交付。
4. **构建了一条可复现的分阶段后训练改进路径**：明确刻画了“发布版（语言遵从瓶颈）→ 多语言 SFT（终止性瓶颈）→ 门控 RL（准确率/语言保持瓶颈）”的缺陷转移规律，为多语言推理对齐提供标准化对照基线。

## 方法详解
1. **评估协议与联合指标**：在 70 道竞赛数学题上覆盖 11 种语言（中英西法阿俄 + 冰岛/瑞典/斯瓦希里/泰米尔/乌尔都），每题 16 次采样（temperature 0.7，24,576 token 预算）。对每个响应独立判定 C（最终答案正确）、L（可见推理痕迹符合请求语言）、T（正常终止且未触发循环检测），联合指标定义为 J = C ∧ L ∧ T。直接计算样本级联合成功率而非边缘概率乘积。
2. **训练阶段与对照设计**：
   - **发布版**：Qwen3-4B / 8B 原始 checkpoint。
   - **多语言 SFT**：基于 45K OpenR1 长 CoT 数学轨迹，用本地部署的 Qwen3-14B 翻译为 6 种语言，经结构对齐、答案保留、重复率等门控后过滤得 43,218（4B）/ 56,307（8B）条轨迹进行 token-level SFT。
   - **控制组**：English-only SFT（9,800 英文轨迹）、5 个单语言 Specialist（各 9K–10K 轨迹，共享源题目仅语言不同）。
   - **RL 阶段**：基于 PPO 在本地化 DAPO-Math-17K（16,754 条 prompt）上训练，设计三种终端标量奖励：
     `R_corr = C_tr`（仅正确性控制）
     `R_add = 0.7·C_tr + 0.3·ℓ_tr`（加法语言奖励，错误轨迹仍可获 0.3 语言分）
     `R_gate = C_tr · (0.7 + 0.3·ℓ_tr)`（正确答案门控语言奖励，错误时奖励强制为 0）
3. **交付效率与 Token 成本度量**：定义 `joint_per_lk`

# 论文速读：TRANSECT: RETAINING OBSERVABILITY FOR LONG-HORIZON LLM AGENT EVALUATIONS

## 一句话总结
论文提出了Transect——一个基于Inspect Scout构建的开源分析工具包，通过将长周期Agent评估的百万级token转录文本转化为可导航、带源链接的行为报告，帮助评估者在可扩展分析容量的同时保持可复现性、透明度和审计追踪，解决前沿AI评估中"观察性包络"收窄的核心困境。

## 研究问题与动机
1. **前沿评估范式的转变**：静态基准测试已趋于饱和，评估正转向开放式、多智能体、长周期的Agent任务，单次运行可产生数百万至数十亿token，最终分数掩盖了被弃置的策略、纠错过程、意外行为和博弈尝试。
2. **人类注意力瓶颈**：审核数百上千页Agent活动需要稀缺的领域专业知识，且要求跨远距离事件建立关联，而审核时间无法与转录规模或模型发布节奏同步增长。
3. **统计功效不足**：长周期评估在时间和计算资源上成本高昂，评估者只能负担少量重复，仅依赖最终分数的测量易受任务方差、随机性和孤立定性轶事的影响。
4. **设置归因不确定性**：观察到的性能由模型和其嵌入的评估系统（harness）共同决定，缺乏完整行为轨迹难以评估评估的构念效度——即评估是否测量了预期的能力而非工具或任务设置的产物。
5. **LLM辅助分析的双刃剑**：虽可用LLM判官辅助转录分析，但引入了判官模型、评估标准、分析单元和统计方法等重大研究者自由度，形成"分叉路径花园"，威胁可复现性。

## 核心贡献（创新点）
1. **提出Transect框架**：构建了评估家族配置化（Spec）的分析流水线，将行为词汇表和任务上下文定义为可复用配置，区别于Docent等交互式探索工具，强调跨样本和epoch的标准化分析流程。
2. **统一turn级时间轴设计**：将结构性事件（token使用、上下文压缩、人类干预）和LLM判官分类（行为阶段、子Agent角色）对齐到同一共享时间轴，支持多信号的共时解读和源链接回溯，区别于LangSmith等平台的应用监控视角。
3. **引入多维度可靠性诊断体系**：提供投票一致性、模型内稳定性（k-roll）、模型间一致性（cohort，含Krippendorff's α和Gwet's AC1）、验证器变更率等指标，使LLM判官输出的不确定性可量化，而非仅依赖单一判官的输出。
4. **结构化专家启发法的工程化落地**：通过编码助手引导评估者识别缺失的任务上下文和类别定义，减少研究者自由度带来的分析路径分叉，将风险分析领域成熟方法引入LLM评估分析。
5. **完整的可复现性纪律**：要求保留源转录、选择、家族配置、判官设置、自定义代码和软件版本，支持无模型调用的报告重生成，同时明确区分可靠性和有效性——高一致性不等于分类正确。

## 方法详解
Transect构建于Inspect Scout之上，包含五个阶段的处理流水线：

**1. 数据摄入 (Ingest)**：将支持的评估日志（Inspect .eval日志或OpenClaw JSONL导出）统一转换为Scout转录格式。OpenClaw导入器会去重累积导出记录并重建消息、工具调用和子Agent活动。

**2. 样本选择 (Select)**：选择要分析的评估样本和epoch。每个epoch代表一次任务尝试，默认选择最早的成功尝试，也可指定多个epoch进行比较。

**3. 扫描 (Scan)**：执行两类扫描器：
- **结构性扫描器**：无需调用LLM，从转录中提取已记录信息：
  - `token_timeline`：记录每次turn的token使用（输入、输出、缓存读写）
  - `context_flush`：提取上下文压缩事件
  - `human_intervention`：提取操作员消息和人类输入
  - `eval_setup`：提取初始系统提示和评估元数据
- **判官扫描器**：调用LLM对Agent行为分类：
  - `decision_phases`：将运行划分为连续行为阶段，使用预注册封闭词汇表
  - `subagent_classification`：对子Agent进行角色分类

判官模式支持三种配置：
- **solo**：单次调用单个判官模型
- **k-rolls**：同一模型重复调用k次，评估模型内稳定性
- **cohort**：多个模型独立判断，评估模型间一致性

**4. 存储 (Store)**：将扫描结果组装为pandas DataFrame，包含内置表（transcript_info, token_timeline, phases, subagents等）和可选的自定义表。

**5. 渲染 (Render)**：生成可导航的HTML报告，将行为阶段、token使用、子Agent活动和事件标记对齐到共享的turn级时间轴。报告支持源链接回溯，用户可追溯任何标签或事件到转录原文。

**关键设计原则**：
- **评估家族配置**：Spec定义行为词汇表和任务上下文，可在同家族的不同样本和epoch间复用
- **结构化专家启发**：通过编码助手引导评估者完善类别定义，记录专家贡献来源
- **可靠性诊断**：投票选择最频繁标签；置信度<0.6或一致性<0.6的分类被选为验证对象；均值k-roll一致性<0.80或>0.95发出琥珀警告；cohort α<0.66发出红色警告

**Token度量定义**：
- `context`：输入+缓存读写，表示重建的输入上下文大小
- `new_work`：输入+输出+缓存写（ capped at non-negative increase）
- `billable`：输入+输出+所有缓存写token（缓存读排除）
- `turn_total`：输入+输出+缓存写+缓存读

## 实验与结果
**案例研究：CRUX倡议的AI R&D影子评估**
- 使用TabPFN任务的单个样本，Claude Opus 4.7作为主Agent
- 评估产生了约1300万token，其中89%来自委托的子Agent工作
- 包含554次编排器工具调用、79次子Agent部署、57条操作员消息和8次上下文压缩

**主要发现**：
1. **研究过程分析**：
   - 将580次编排器输出分为129个连续阶段
   - 81.7%的输出获得一致的研究活动标签，82.1%获得一致的论文特定标签
   - 仅2/580次输出被标记为"假设提出"(Hypothesising)，而56次被标记为"反思"(Reflecting)
   - 研究过程中几乎没有持续的假设生成阶段

2. **Token分配分析**：
   - 自我审查和手稿撰写占总新工作token的约四分之三（780万+290万）
   - 解决方案构思仅占约22,000 token
   - 非研究性工程操作约占220万token
   - 文献引用子Agent消耗约500万token，但主要在手稿撰写阶段

3. **多Agent协调分析**：
   - 自定义扫描器识别922条共享文件访问记录，涉及131个会话
   - 其中346条记录连接不同的委托子Agent
   - 66.6%的记录发生在论文工作空间（paper/目录下）
   - 77.6%的判官标注记录在五轮Opus 4.7调用中获得一致标签

4. **相位转换分析**：
   - 观察到两种主要机制：构建-测试循环和撰写-审查振荡
   - 18/57条操作员消息后3步内开始新相位，28/57条后10步内开始新相位
   - Agent引用验证：46条引用中仅20条在OpenAlex/Crossref/arXiv中验证成功，而人类作者的69条引用中60条验证成功

**结论**：Transect成功将长周期评估转录转化为可导航、可审计的分析报告，揭示了Agent在研究过程中缺乏持续假设生成阶段的模式，支持跨事件的共时解读和源链接回溯。

## 相关工作脉络
1. **Inspect AI/Inspect Scout**：Transect的基础框架，提供评估日志访问、转录表示和扫描器抽象。Transect在此基础上构建了评估家族配置化和多扫描器共时解读能力。
2. **Docent**：使用LLM助手帮助用户交互式导航转录的分析工具。Transect强调可复现的、基于家族配置的流水线式分析，而非交互式探索。
3. **LangSmith/Langfuse/Arize Phoenix等追踪平台**：支持trace检查和调试。这些平台侧重于应用监控，而Transect专注于评估分析的可复现性和审计追踪。
4. **HiBayES**：分层贝叶斯建模框架用于AI评估统计。Transect提供构内证据结构，但不解决统计功效不足问题，两者互补。
5. **MLR-Bench/PaperBench**：评估Agent机器学习研究能力的基准。Transect提供分析这些评估转录的工具，但不直接参与能力评估本身。
6. **结构化专家启发法**：在风险分析领域成熟应用。Transect将这一方法引入LLM评估分析，通过编码助手引导评估者完善类别定义。

## 局限性与未来方向
1. **判官分类的有效性局限**：投票一致性高不等于分类有效，需要独立的人类专家标注来建立外部效度参照，论文未提供此类验证。
2. **统计功效不足**：长周期评估成本高，只能做少量重复，Transect不解决跨运行的统计推断问题，仅结构化构内证据。
3. **标记可用性限制**：缺失的标记可能是未记录、扫描器未运行或分类失败，不能等同于行为不存在，可能低估某些行为。
4. **因果推断局限**：时间线上的共现不等于因果关系，Operator消息和上下文压缩与行为转变的接近性只是相关性，非因果效应。
5. **案例研究单一**：仅展示了一个TabPFN任务的单次运行，未提供多个epoch或多Agent的系统比较，外部效度受限。
6. **未来方向**：需要多epoch多样本的验证、独立专家标注的建立、干预实验的设计来检验评估设置对行为的影响，以及将Transect与统计建模框架（如HiBayES）结合。

## 研究启发与可借鉴点
1. **统一时间轴设计可迁移**：将多源信号（token使用、行为标签、事件标记）对齐到同一turn级时间轴，实现跨信号的共时解读，这一设计可迁移到其他长周期系统分析场景（如安全事件分析、医疗流程追踪）。
2. **评估家族配置化范式**：通过Spec定义行为词汇表和任务上下文，支持同家族评估的可复用分析，降低新评估的配置成本，这一范式可推广到其他需要标准化分析的领域。
3. **可靠性诊断体系的设计**：引入投票一致性、模型间一致性、验证器变更率等多维度指标，使LLM判官输出的不确定性可量化，这一思路可应用于其他LLM-as-Judge场景，提升判官方法的可信度。
4. **结构化专家启发法的应用**：通过编码助手引导评估者完善类别定义，减少研究者自由度带来的分析路径分叉，这一方法可推广到其他需要专家知识的分析场景。
5. **源链接回溯的可审计性**：支持从聚合报告追溯到原始转录，保持分析的可审计性，这一设计对安全关键的评估场景（如AI安全评测）尤为重要。

## 关键术语表
- **Observability Envelope（观察性包络）**：评估者能从评估中可靠推断Agent行为的属性范围，包括Agent的能力、失败模式和倾向性，受转录、评估装置和分析方法的共同影响。
- **Transect**：本文提出的开源分析工具包，将长周期Agent评估转录转化为可导航、带源链接的行为报告，网址为https://github.com/AI-Safety-Institute/transect。
- **Spec（评估家族配置）**：定义行为词汇表、子Agent类别和任务上下文的复用配置，可在同家族的不同样本和epoch间复用，是评估家族标准化的核心载体。
- **Structural Scanner（结构性扫描器）**：无需调用LLM，从转录中提取已记录事件的扫描器，如token使用、上下文压缩、人类干预等，输出可复现且无模型变异。
- **Judged Scanner（判官扫描器）**：调用LLM对Agent行为进行分类的扫描器，支持solo、k-rolls、cohort三种判官模式，输出携带可靠性诊断指标。
- **Turn（回合）**：模型输出事件的基本单位，Transect将多个信号对齐到turn级时间轴进行共时解读，同一索引跨越不同数据源。
- **K-roll（重复判官）**：同一判官模型重复调用k次，用于评估模型内稳定性，结果以投票方式聚合，提供一致性证据。
- **Cohort（判官群体）**：多个不同模型独立判断同一输入，用于评估模型间一致性，结果以投票方式聚合，提供更 robust 的一致性估计。

## 可复现要素
- **数据集**：CRUX倡议的影子评估数据，来源于Kirgis等人（2026）的TabPFN任务评估，未公开但案例数据由作者提供
- **代码**：开源，位于 https://github.com/AI-Safety-Institute/transect
- **权重**：使用Claude Opus 4.7作为判官模型
- **关键超参**：
  - k-rolls默认值：1
  - 验证器默认开启（solo和k-roll模式）
  - 验证触发阈值：置信度<0.6或一致性<0.6
  - 空间检查比例：5%（最少3个阶段）
  - 文本限制：每条分类摘要300字符，提取的上下文2400字符，子Agent任务文本800字符
  - 阶段填充置信度：0.3
  - 响应缓存：默认开启，不同roll使用独立缓存作用域

# 论文速读：WORLDSOLVER-CAN-LLM-AGENTS-SIMULATE-THE-PHYSICAL-DYNAMICS-VIA-SOLVER-GENERATION

## 一句话总结
本文提出了 **WorldSolver**，一个包含 168 个物理仿真任务的评测基准，用于评估 LLM Agent 能否从自然语言描述中生成可执行的物理动力学求解器；评测涵盖执行检查、视觉保真度和物理合理性三个维度，实验显示前沿模型（GPT-5.6-Sol、Claude-Opus-5）的最高综合得分仅约 48%，表明该任务仍极具挑战。

## 研究问题与动机
1. **核心问题**：LLM Agent 能否将描述的物理现象转化为可执行的物理动力学求解器？求解器是仿真的核心组件，负责将物理模型的支配方程转化为数值迭代过程。
2. **现有工作不足一**：动态场景生成类工作（如 SimuScene、PhysCodeBench）要么采用无求解器的动画生成方式，要么依赖预置物理引擎，未评估模型选择与数值实现能力。
3. **现有工作不足二**：科学计算类基准（如 PDEAgent-Bench、CFDLLMBench）给定已知控制方程，侧重数值求解精度，缺少物理场景设定与渲染环境，未评估物理理解能力。
4. **动机**：构建物理仿真求解器需要三类能力的融合——物理理解（选择合适的模型）、数学推理（建立支配方程）和软件工程（实现为可执行代码），三者缺一不可，当前尚无统一评测框架。

## 核心贡献（创新点）
1. **首次将物理动力学求解器生成定义为 Agent 编码任务**：要求 Agent 在固定代码脚手架下独立实现求解器，同步考察物理建模、数值离散与代码实现能力；区别于已有工作仅评估函数级代码生成或预设方程的数值求解。
2. **提出 WorldSolver 基准（168 任务 / 61 篇 CG 经典论文 / 7 大物理域）**：涵盖流体、刚体、塑性材料、弹性固体、杆与弦、布料与薄壳、多物理耦合，每任务提供固定脚手架隔离求解器实现变量；区别于 SimuScene（5 域、无脚手架）、PhysCodeBench（3 域、无求解器生成）等。
3. **设计三维度统一评测协议（Execution × Visual Fidelity × Physical Plausibility）**：执行检查评估代码能否正确运行，视觉保真度通过 VLM judge 评估渲染视频中的现象复现，物理合理性通过确定性计算器验证轨迹满足质量守恒、动量-冲量一致性、非穿透等约束；三者互补，克服单一视觉或数值评估的盲区。
4. **系统评测 7 个前沿编码 Agent 并揭示行为模式**：发现 GPT-5.6-Sol 以最少 epoch（13.07）达到最高分 48.7%，而 Kimi-K2.7-Code 用 37.95 epoch 仅得 17.1%；Code Edit 工具调用比例与性能正相关，揭示了求解器生成的有效策略模式。

## 方法详解
**任务形式化**：每个任务给定现象描述 $d$ 和固定脚手架 $\mathcal{S}=(\mathcal{G},\mathcal{P},\mathcal{E},\mathcal{R})$，其中 $\mathcal{G}$ 为场景几何、$\mathcal{P}$ 为物理参数与边界条件、$\mathcal{E}$ 为执行协议、$\mathcal{R}$ 为渲染配置。Agent 在受限 workspace（仅可修改 `solver/` 目录，无网络访问，禁止使用预置仿真引擎）内生成求解器 $\Phi=\mathcal{A}(d,\mathcal{S})$，以时间步推进系统状态：$\mathbf{s}_{t+1}=\Phi(\mathbf{s}_t)$。

**三维度评测**：
- **Execution Checks**：求解器成功运行并输出合法轨迹与视频则 $E=1$，否则 $E=0$。
- **Visual Fidelity**：针对每任务定义 4 个维度的视觉判据（事件序列、交互响应、特征现象、时序连贯性），从渲染视频中均匀采样 20 帧，用 GPT-5.6-Sol 作为 VLM Judge 对每判据打分 $V_i\in[0,1]$（重复 5 次取平均），$V=\frac{1}{4}\sum_{i=1}^{4}V_i$。
- **Physical Plausibility**：对每物理域预设违规函数集 $\{\mathcal{E}_i\}$，对轨迹 $\tau$ 计算无量纲违规误差 $e_i=\mathcal{E}_i(\tau)\geq 0$（如质心一致性、动量-冲量平衡、非穿透等），归一化后映射为 $p_i\in[0,1]$，$P=\frac{1}{M}\sum_{i=1}^{M}p_i$。
- **最终得分**：$s_k=\frac{V_k+P_k}{2}$（若 $E_k=1$，否则为 0），基准总分为所有 case 的均值。

**脚手架设计**：每个任务配有标准模板（`config.yaml`、`scene.py`、`render_spec.yaml` 等），Agent 仅实现 `BenchmarkSolver` 类的 `initialize()` 和 `advance_to()` 方法，禁止硬编码动画或查表。

## 实验与结果
- **数据集**：168 个任务，源自 61 篇计算机图形学经典论文，覆盖 7 大物理域（流体、刚体、塑性/复杂材料、弹性固体、杆与弦、布料/薄壳、多物理耦合）。
- **评测模型**：GPT-5.6-Sol、Claude-Opus-5、Gemini-3.7-Flash、DeepSeek-V4.1-Flash、GLM-5.3、Qwen-3.8-Max、Kimi-K2.7-Code。
- **主要结果**：GPT-5.6-Sol 以 **48.7%** 最高综合得分领先，Claude-Opus-5 以 **46.7%** 紧随其后；其余模型分布在 17.1%~29.3% 之间。各领域差异显著：GPT-5.6-Sol 在 Rods & Strands 达 59.5%（较 Claude-Opus-5 的 33.5% 高出 26 个百分点），而 Claude-Opus-5 在 Cloth & Shells 达 60.1%（较 GPT-5.6-Sol 的 35.8% 高出 24.3 个百分点）。
- **分阶段成功率**：几乎所有模型提交率均在 88%–100%，但轨迹产出率差距大（GPT-5.6-Sol 82% vs. Kimi-K2.7-Code 38%）；达到 ≥60 分的通过率仅 41%（GPT-5.6-Sol）和 37%（Claude-Opus-5）。
- **物理 vs. 视觉互补性**：刚体领域视觉分普遍高于物理分（如 GPT-5.6-Sol 65.5% vs. 44.2%），塑性材料领域反之；VLM judge 与人类专家评分相关性 Pearson $r=0.730$，优于人类-人类一致性（$r=0.624$）。
- **成本效率**：DeepSeek-V4.1-Flash 成本效益最佳；GPT-5.6-Sol 以 8.89 分钟均时达到最高分；Kimi-K2.7-Code 因"过度思考"导致成本与耗时双高但性能最差。

## 相关工作脉络
1. **HumanEval / SWE-bench / Code generation benchmarks**：聚焦函数级或仓库级代码生成，WorldSolver 在此基础上增加了物理建模与数值离散要求，属于科学编码任务的延伸。
2. **SimuScene (Wang et al., 2026)**：基于代码生成评估动画物理行为，但无求解器生成（代码脚手架），WorldSolver 通过固定脚手架隔离求解器实现变量。
3. **PhysCodeBench / GS-Agent / PhysAgent**：利用预置物理引擎构建动态仿真，不要求 Agent 从零实现求解器；WorldSolver 禁止使用预置引擎，要求 Agent 从基础科学库出发自主构建数值方法。
4. **PDEAgent-Bench / CFDLLMBench / CodePDE**：给定已知支配方程进行数值求解，侧重求解精度与收敛性；WorldSolver 要求 Agent 自主选择物理模型并完成从建模到实现的完整链路。
5. **SimulCost (Cao et al., 2026)**：关注自动化物理仿真的成本评估，WorldSolver 在评测协议中同时报告 API 成本与运行时间作为辅助分析。

## 局限性与未来方向
1. **任务覆盖有限**：168 个任务仅覆盖 7 个物理域中的一部分现象，无法代表全部物理仿真场景。
2. **缺少训练支持**：目前仅为评测基准，未探索针对物理求解器生成的训练方法（如监督微调、RL 等）。
3. **VLM Judge 的隐含偏差**：视觉保真度依赖 VLM 评分，虽经人类校验证实一致性较好，但仍可能存在系统性偏差或判据覆盖不全。
4. **物理判据的非完备性**：确定性违规函数无法穷尽所有物理约束，部分错误（如刚体堆叠的整体稳定性）可能逃过检测但被视觉评测捕获。
5. **未来方向**：扩展任务覆盖范围、探索有监督/强化学习训练物理求解器生成 Agent、开发更多样化的物理判据。

## 研究启发与可借鉴点
1. **固定脚手架隔离变量的评测设计**：通过冻结场景几何、参数、渲染配置，仅让 Agent 修改求解器代码，有效控制实验变量，适用于任何"代码生成+物理/功能验证"场景的基准设计。
2. **视觉+物理双轨互补评估**：视觉保真度发现可观察的异常，物理合理性捕捉轨迹中的隐藏违反（如动量不守恒），二者结合避免单一指标的盲区；该方法论可迁移至机器人仿真、科学计算等其他领域。
3. **状态轨迹（State Trajectory）作为中间产物**：不仅输出渲染视频，还导出逐帧物理量（位置、速度、力等），使连续验证成为可能；可借鉴于任何需要数值验证的 Agent 评测框架。
4. **工具调用模式分析**：Code Edit 工具的高频使用与高性能正相关，说明迭代式代码修正比一次性生成更有效；可为后续 Agent 方法设计提供策略指导。
5. **VLM Judge 的人类一致性验证流程**：通过 231 个样本的人类标注验证，证明 VLM judge 相关系数高于人类间一致性，该方法可作为自动评测可信度的标准化验证手段。

## 关键术语表
- **WorldSolver**：本文提出的评测基准，包含 168 个从经典计算机图形学论文中选取的物理仿真任务，用于评估 LLM Agent 求解器生成能力。
- **Code Scaffold（代码脚手架）**：每个任务预置的固定仿真环境框架，包含场景几何、物理参数、执行协议和渲染配置，Agent 仅可修改其中的求解器模块。
- **Visual Fidelity（视觉保真度）**：通过 VLM Judge 在四维度（事件序列、交互响应、特征现象、时序连贯性）上评估渲染视频对目标物理现象的复现程度。
- **Physical Plausibility（物理合理性）**：通过确定性数值计算器验证生成轨迹是否满足质量守恒、动量-冲量平衡、非穿透等物理约束，以违规误差衡量。
- **State Trajectory（状态轨迹）**：求解器在每个时间步输出的物理状态序列（位置、速度、力等），是连接执行与物理评估的关键中间产物。
- **Execution Check（执行检查）**：评估求解器代码是否能无报错运行并导出合法轨迹与视频的布尔判据，是后续评测的前提。
- **Solver Generation（求解器生成）**：Agent 从自然语言描述的物理现象出发，自主完成物理模型选择、数值离散和代码实现的完整过程。
- **Multiphysics Coupling（多物理耦合）**：涉及两种及以上物理现象相互作用的仿真领域，如流固耦合、气固耦合等，是 WorldSolver 中最复杂的域之一。

## 可复现要素
- **数据集**：WorldSolver 基准，168 个任务，源自 61 篇 CG 经典论文；**已公开**（GitHub: https://github.com/sirujiang/WorldSolver）。
- **代码**：**已开源**（见上方链接）。
- **权重**：评测使用的是商业模型（GPT-5.6-Sol、Claude-Opus-5 等），无自训练模型权重。
- **关键超参**：Agent 生成时限 1,800 秒，求解器运行时限 600 秒；VLM Judge 每任务采样 20 帧，重复 5 次取平均；推理强度设为"high"（可用时）。
- **执行环境**：Debian Bookworm 容器，含 NumPy、SciPy、Numba、h5py、PyYAML、FFmpeg；离线渲染使用 pyrender + PyOpenGL + trimesh。

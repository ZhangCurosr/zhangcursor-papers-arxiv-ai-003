# 论文速读：Where-Rules-End-and-Judges-Begin-Measuring-the-Judgment-Boundary-in-Multi-Agent-Systems-Security

## 一句话总结
本文提出 **DEFER** 框架，将28条确定性检查按五原则级联编排，仅在必要时才交由4个开源LLM裁判裁决；在四个领域、300个攻击变体上验证发现：确定性规则拦截了78%的被拦截攻击，攻击成功率从≈30%降至≈3%，而仅靠裁判（无规则）的攻击成功率与无防御基线相当（34.7% vs 32.0%），证实"规则决策必须违反明确属性的攻击，裁判决策仅意图存疑的攻击"这一边界清晰可测。

## 研究问题与动机
- 现有MAS防御各自为战，通常每次只针对一类攻击或一个通道设计，组合使用时最终裁决权交给LLM裁判，但"裁决究竟有多大必要"仍无从度量。
- LLM裁判虽能推理意图、无需策略工程，但会读取攻击者可控内容、裁决不可审计、且每次调用带来延迟与成本，是最弱的检查类型。
- 纯设计强制执行虽安全但牺牲agent灵活性；纯裁判虽灵活但安全薄弱；实际部署必然处于两者之间，但"规则与裁判的边界在哪里"尚未被量化。
- 已有工作（如AgentTrust）针对单agent拆分威胁，但多agent流水线的规则本身还会查询策略与状态，边界的形状与代价未测量过。

## 核心贡献（创新点）
- **DEFER流水线与测试床**：将五类成熟防御原则实例化为28条检查的级联流水线，在四领域、300攻击变体+35个良性场景+第三方基准上评测。与已有工作本质区别在于：不是提出新防御机制，而是以"确定性优先、裁判兜底"的次序跨工具调用/共享内存/Agent间消息三层统一编排已有控制。
- **边界度量方法论**：提出"已裁决比例"（judged fraction）、离线裁判回放（judge replay）与"拒绝vs框架拦截"分离的oracle，首次可量化测量规则与裁判各自承担的比例。与已有工作本质区别在于：裁判决策可从日志离线复判，无需重跑agent即可比较任意裁判组合。
- **边界形状的实证发现**：规则拦截78%被拦截攻击；仅用裁判的攻击成功率不降反升（34.7% vs 32.0%）；风险评分自动审批门对攻击Proposal呈"反选择"（批90%攻击提案仅批36%合法提案）；同谱系裁判组合比多元组合弱3.5倍；"合理伪造的写入记录"同时绕过规则与裁判。
- **跨域泛化与第三方基准验证**：在CyberOps、医疗、金融、法律四领域保持0%-5.3%的攻击成功率；在Agent Security Bench（255例）上从28.8%降至1.8%，在TAMAS（250例）上从43.5%降至21.9%，证明模式具有跨域与跨基准的可迁移性。

## 方法详解
- **两条集成表面与五条注入通道**：不可信内容通过工具编排（Tool）与内存管理（Memory）两个表面进入MAS，对应C1任务输入、C2工具响应、C3内存内容、C4交接（Handoff）、C5提案理由（Proposal justification）五个通道。
- **五原则与28条检查**：
  - **P1 授权接口**（3条）：工具注册表白名单、响应schema/时序/重放校验、配置SHA-256启动快照与逐事件复核。
  - **P2 能力作用域**（3条）：每阶段manifest+动作上限、参数校验（通配符/资产关键性/每工具规则/目标-证据一致性）、输出敏感内容分类器。
  - **P3 验证执行**（11条）：交接校验、操作上下文、意图链监控、跨事件账本、重放检测、自适应同意、风险评分+自动审批/拒止门、LLM多模型裁判面板（4选3一致）、执行前哈希核对。
  - **P4 内存完整性**（6条）：写入schema/元数据校验、写入-证据余弦相似度（硬下限0.3/阈值0.5）、漂移检测、写入重放检测、基于规则的矛盾检测。
  - **P5 访问控制隔离**（5条）：阶段-存储静态策略、字段级脱敏、查询范围限制、读取模式侦察监控、读取结果指令文本剥离。
- **分级决策：四类层次**
  - 内容无关规则（13条）：仅凭结构与状态裁决，攻击者写入内容无法改变结果。
  - 内容相关规则（8条）：确定性但读取攻击者可控值，可通过措辞规避。
  - 相似度阈值（6条）：嵌入模型固定后确定，但阈值需学习/标定。
  - LLM裁判（1条）：唯一依赖判断的检查。
- **级联顺序**：按"最便宜、最确定→最昂贵、最不确定"排列（Algorithm 1-3）。非结论性调用可由consequentiality表直接放行（确定性批准），无需进入P3。
- **失败闭合**：每条检查失败即拒绝，validator错误计为拒绝；多数检查无状态，但账本/自适应同意/漂移质心/重放缓存/读取模式监控跨事件累积状态。
- **裁判面板LOCAL4**：Mistral-Small-3.2-24B、Gemma-4-31B-it、gpt-oss-120b、Llama-4-Scout-17B-16E，四来自四谱系，3/4一致即通过；每个裁判绝不评判自身模型的提案。

## 实验与结果
- **数据集**：自有4领域测试床（CyberOps/医疗/金融/法律），共300个攻击变体×3次重复=900次试验；另有第三方基准：Agent Security Bench（255例×2次）、InjecAgent子集（50例×3次）、TAMAS（250例×3次）。
- **评估基线**：FLAT（无防御）、ACL（仅连通性控制）、JUDGEONLY（每条提案均交裁判）、NOJUDGE（从不裁判，未通过者升级视为拒绝）、FULL（DEFER完整级联）。
- **主要结果**：
  - **四领域汇总**：攻击成功率从30.0%降至3.0% [1.3, 4.9]，各领域分别2.2%/0.0%/5.3%/4.4%。
  - **CyberOps边界**：FULL达成2.2%，JUDGEONLY为34.7%（与FLAT的32.0%无显著差异），NOJUDGE为1.3%。规则将攻击成功率从34.7%压至2.2%；裁判在无规则时无法降低攻击成功率。
  - **确定性拦截占比**：四领域汇总，77.9%的被拦截攻击首次由确定性检查拦截（CyberOps 97.8%，其余三域69.7%）。
  - **第三方基准**：ASB上28.8%→1.8%（DEFER），同一裁判下SINGLE judge为3.3%，LIN3同谱系组合为9.6%；TAMAS工具类攻击36.9%→0.0%（直接注入）、30.2%→5.3%（伪装）、40.0%→2.0%（合谋）；BYZANTINE/CONTRADICTING两类仅作用于回答的攻击型未被DEFER改变（因DEFER中介的是行动而非回答）。
  - **多主模型**：gpt-oss-120b在CyberOps FULL为6.2%，Llama-3.1-8B为8.4%。
- **最强结果**：Healthcare领域0%攻击成功率；ASB基准1.8%；CyberOps边界实验中26个JUDGEONLY失败的变体在FULL下全部成功拦截。
- **成本**：CyberOps合法提案拒绝率9.9%，其余三域19.5%-26.9%；持久状态下重放检测永不过期，导致88%例行重大工作被拒。

## 相关工作脉络
- **AgentTrust（Yang 2026）**：将单agent行动拆分为词汇型威胁（规则可决）与语义型威胁（仅裁判可决），边界形状与本文相似；本文扩展至状态化多Agent流水线，发现多数攻击必须违反可由规则检查的策略或状态，规则承担主要安全职责。
- **LlamaFirewall / MCP-Guard / CASCADE**：均为单agent内的分层/级联防御（分类器+推理审核员、模式匹配→LLM仲裁）；本文首次跨工具调用/共享内存/Agent间消息三层统一编排，并量化每条规则拦截的贡献占比。
- **符号护栏 / Policy-as-Code / 形式化验证护栏**：主张单侧方案（全规则或全设计），本文实证表明部署中必然处于两者之间，且边界可测且大部分验证可由规则完成。
- **Progent / FIDES / RTBAS / Datalog参考监视器**：在工具边界强制权限与信息流；本文借鉴其思想但侧重测量"强制程度与裁判依赖的 trade-off"而非提出新强制机制。
- **Agent Security Bench / InjecAgent / TAMAS / AgentDojo**：基准工作聚焦攻击枚举与单agent场景；本文在相同基准上做跨防御组合的对比评测，并提供"attempt vs block"的分离度量与裁判回放能力。
- **CaMeL / 设计模式目录**：以可证明隔离换取泛化性；本文走中间路线，证明"大多数场景下规则足以保证安全，裁判主要用于恢复被规则误拦的合法工作"。

## 局限性与未来方向
- **静态攻击假设**：未评估自适应攻击者，确定性层的安全性属于上界估计；自适应攻击可能绕过基于模式的检查。
- **覆盖与规模**：AP-3（confused deputy via forged response）无任何主模型尝试；每个攻击路径最多21次试验/配置/域；35个良性场景限制了成本估计精度。
- **单一架构**：仅验证了host-mediated垂直拓扑，水平拓扑、更长阶段链、多租户部署未测；主协调器为单点故障。
- **工具与数据合成性**：工具为stub、内存为合成数据，绝对速率不直接迁移到生产环境；比较结论（跨配置的相对提升）更具可迁移性。
- **裁判迁移性差**：在CyberOps训练提示的裁判在legal域仅批39.7%合法提案；跨域泛化需重新调参或领域适配裁判。
- **未来方向**：探索可证明的写入来源/出处（provenance）以应对"合理伪造写入"；引入状态过期机制（如skeleton key按事件数/时间窗口失效）缓解持久状态导致的良性拒绝；评估自适应攻击下的边界稳定性；扩展至水平拓扑与真实生产环境。

## 研究启发与可借鉴点
- **"裁判回放"（Judge Replay）方法论**：所有裁判输入可从日志重建，离线重判任意组合而不重跑agent，极大降低面板比较成本；可直接迁移到任何LLM-as-judge评估管线。
- **attempt/block分离oracle**：区分"模型本身拒绝"与"框架拦截"避免高估防御价值；对团队现有benchmark可复用该分离指标。
- **风险评分自动门的"反选择"警示**：基于攻击者可塑造证据的分数进行自动审批会偏向攻击提案（批90%攻击vs 36%合法）；团队若在agent流水线中引入风险评分gate，应改用结构化字段而非自由文本作为评分依据。
- **谱系多样性优于数量**：同谱系3裁判（LIN3）比单裁判弱3.5倍，多元4裁判（LOCAL4）显著更优；提示团队在设计多裁判面板时优先选择跨厂商/谱系的模型组合而非堆叠同架构模型。
- **确定性批准本身是安全的**：consequentiality表将非结论性调用直接放行，无任何攻击利用此路径；启发团队在策略明确时可优先走"分类式批准"而非"评分式批准"。
- **持久状态必须设有效期**：重放检测与账本若不设窗口，例行工作会被大量误拦；团队若实现状态化防御应同步评估持久模式下的良性成本。

## 关键术语表
- **DEFER（DEterministic-First Enforcement with Residual judgment）**：本文提出的级联执行框架，28条检查按确定性优先、裁判兜底次序排列。
- **Judgment Boundary（裁决边界）**：多Agent流水线上"规则可决"与"仅裁判可决"的攻击之间的分界线，本文核心测量对象。
- **Judged Fraction（已裁决比例）**：到达LLM裁判面板的工具提案占全部提案的比例，是衡量对裁判依赖程度的关键指标。
- **Attack Success Rate (ASR)**：执行成功的试验数除以总试验数；本文使用canary值追踪攻击效果而非仅看模型输出。
- **Agent Tier (T1/T2/T3)**：内容攻击者（控制输入数据）、被控Agent（控制某阶段输出）、基础设施攻击者（可篡改飞行中请求/配置）。
- **Judge Replay（裁判回放）**：从日志重建裁判输入后离线重判，用于比较不同裁判组合而不重跑agent。
- **Integration Surface（集成表面）**：不可信内容进入MAS的两个入口——工具编排（Tool）与内存管理（Memory）。
- **Anti-selective（反选择性）**：风险评分门因分数基于攻击者可操控的证据，反而对攻击提案给予更高通过率的性质。

## 可复现要素
- **数据集**：自有四领域测试床（CyberOps/医疗/金融/法律，300攻击变体+35良性场景）；第三方基准ASB、InjecAgent子集、TAMAS。
- **代码/权重**：实验代码开源於 `github.com/shaswata09/DEFER`；artifact包含测试床、所有域配置、攻击/良性套件、harness、每试验日志；所有裁判投票缓存在artifact中，可用单条命令`make paper-tables`和`make figures`从日志重生成所有表格与图片。
- **关键超参**：primary agents temperature=0.7（固定seed），validators temperature=0；P2.2余弦阈值0.5、硬下限0.3；P4.2余弦阈值0.5；P5.3查询相关性下限0.2；P4.4漂移距离阈值1.5×最大观察值、质心偏移≤0.05；P3.6重放检测key为（tool, argument names, action）骨架、不设过期窗口（主要缺陷）；裁判面板quorum=3/4。
- **硬件**：vLLM 0.19.1/0.21.0，5× NVIDIA H200 + 1× RTX 5090；Qwen3-235B BF16 TP=4，其余模型BF16 TP=1-2。
- **统计**：95% cluster-bootstrap区间（10,000次重采样，以variant为单位）；配置间配对比较；Holm校正跨攻击路径比较。

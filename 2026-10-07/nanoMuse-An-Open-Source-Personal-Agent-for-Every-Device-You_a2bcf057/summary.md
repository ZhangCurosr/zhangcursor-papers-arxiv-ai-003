# 论文速读：nanoMuse-An-Open-Source-Personal-Agent-for-Every-Device-You

## 一句话总结
本文提出并开源了 nanoMuse，一个运行在用户自有终端（Android、桌面、iOS、Web）上的 GPL-3.0 个人 AI 代理系统，通过可选中继服务实现多设备统一对话，以明文文件记忆、进程内 Sentinel 审批边界与本地化 Hands 屏幕操控，作为对闭源云端个人代理（如 Meta Muse）的完整开源替代。

## 研究问题与动机
- 商业个人代理（Muse、Today、Manus Cue 等）均托管于厂商云端虚拟机，核心代码、模型与数据链完全黑盒，用户无法自主检查、修改或带走代理行为。
- 现有手机/桌面 GUI 代理缺乏真正的原生屏幕控制权：iOS 系统禁止跨应用操作，Android 侧多依赖云端转发或无障碍服务，导致银行、政务等无公开 API 的原生 App 无法被代理触达。
- 代理的长期记忆、权限授予与主动沟通机制缺乏透明度，用户难以建立可持续的信任，且数据主权无法保障。
- 开源社区缺乏同时覆盖“多设备协同 + 本地 GUI 操控 + 透明记忆治理”的完整个人代理原型与统一评测基线。

## 核心贡献（创新点）
1. **提出完整开源个人代理架构 nanoMuse**：实现“一人一代理、每设备一双手”的本地化部署形态；与 Muse 的云主机架构本质不同，核心循环与执行环境全部置于用户自有硬件，而非受控 VM。
2. **设计进程内 Sentinel 策略边界**：通过固定决策顺序（黑名单→用户规则→污点追踪→风险模式→警告词）与范围限定授权（scoped approval）实现细粒度安全管控；相比 Muse 的硬件级特权隔离，本文以可审计的软件策略边界弥补单设备运行的权限局限。
3. **构建 Hands 本地 GUI 操控模块**：采用“技能→命令行→MCP→浏览器→原生屏幕”分层阶梯，并结合每截屏一次的动作循环与确定性文本标签检查；与纯视觉 GUI 代理（UI-TARS、OS-Atlas 等）相比，引入模型输出的“意图句子”作为确定性网关，降低视觉驱动的不可控性。
4. **确立记忆即文件（Memory as Files）的透明治理范式**：以 Markdown/纯文本行式存储承载 SOUL/USER/GLOBAL 记忆，配合人工优先覆盖、变更日志与语义召回；提出“模型置信度溯源 + 冲突时人工写入优先 + 定期交叉核验”的记忆治理原则，为长期个人代理提供可审计的基础设施。
5. **发布社区驱动的开发路线图与统一评测规划**：整合 AndroidWorld、OSWorld、MemGUI-Bench 与 OS-Harm，开源中继服务代码与隐私设计文档，推动个人代理从原型走向可复现的公共基线。

## 方法详解
- **多端架构**：Android 端基于 OpenMinis 改造（内嵌沙盒 Alpine Linux、Shell、浏览器与 MCP 服务器）；桌面端基于 DeepSeek Harness 的 Electron 壳；Web 端复用同一 Python 运行时；多端通过可选的 nanoMuse Relay 中继实现会话同步与跨设备工具调用。
- **Sentinel 审批流程**：任何工具调用必须经固定顺序过滤器。污点规则（taint rule）规定：一旦对话读取过私有数据，所有向外发送数据的调用自动触发审批，且该状态不可逆。授权粒度分为“单次/本会话/按目标（收件人/站点/文件夹/应用）/定时”，支付与密码类操作强制单次授权，所有决策写入用户可审计的日志。

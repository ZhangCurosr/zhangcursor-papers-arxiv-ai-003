# 论文速读：One-Skill-Too-Many: How Co-Installed Skills Conflict in Coding Agents

## 一句话总结
本文是首个针对编码代理中"共安装技能冲突"的实证研究，揭示了当两个功能相似的 SKILL.md 被同时安装时，模型常根据名称和描述选择错误技能，导致用户期望的"核心功能"悄然丢失——而任务仍能完成，使现有基准完全漏报。研究进一步定位冲突决定点位于首次读取技能时，并提出预工具钩子可将保真度恢复至基线水平。

## 研究问题与动机
- **核心问题**：相似技能共安装后，已安装技能的"核心功能"（即用户特意配置的行为约束）是否会丢失？任务完成度能否反映此类损失？
- **现有基准盲点**：SWE-Skills-Bench 等仅以任务是否通过测试计分，无法捕捉"用错了技能但结果正确"的情形；SWE-Skills-Bench 发现 49 个技能中 39 个的通过率提升为零，意味着技能丢失甚至不会降低通过率。
- **冲突隐蔽性三难题**：① 冲突藏在成功背后——相似技能都能完成任务，唯一痕迹是已安装技能特有的行为约束未被执行；② 冲突在暗中解决——模型仅凭数百字符描述选择，不告知用户；③ 冲突在运行时决定——需观察工具调用记录才能定位。
- **规模化证据缺失**：既往研究考察单个技能或假设性配对，缺乏从真实仓库快照中挖掘共安装冲突的大规模实证。

## 核心贡献（创新点）
1. **首次大规模实证揭示技能冲突普遍性**：从 20,947 个仓库快照中挖掘 822,109 个候选技能对，确认 1,639 对，实验 312 对——发现近 1/4 已安装技能已与同类技能共装，37% 的批量复制集合中的技能存在冲突。*与既往工作的本质区别：首次用真实安装列表而非合成配对量化冲突规模。*
2. **提出"核心功能+保真度"要求级评估框架**：将技能文本转化为可验证的"核心功能"清单，定义"独占核心功能"（仅由 A 要求的行为）和保真度（首批三个适用核心功能的完成率）。*与 SWE-Skills-Bench 等通过通过率评估的本质区别：前者捕获"正确任务、错误执行"的隐性损失。*
3. **定位冲突决定点并提出预工具钩子防护**：证明冲突在首次读取技能时即已决定（97% 情况发生在文件变更之前），并验证 deny-first-read 钩子可使保真度恢复到仅安装 A 的水平。*与工具选择偏差研究（BiasBusters 等）的区别：不仅报告选择偏差，还给出运行时干预方案。*
4. **开源完整实验资产**：释放 6,368 次运行日志、169,294 个工具调用记录、case 构建脚本与评判器。*填补可复现性空白，支持下游基准设计改进。*

## 方法详解
- **安装重建**：从 2026-07-18 的 GitHub 快照提取 55,698 个独特技能（105,302 副本），按 Claude Code 加载规则重建 5,106 个安装列表（A 池：项目/个人目录实际安装；B 池：其他仓库/插件市场可安装）。
- **候选检索与确认**：用 Qwen3-Embedding-0.6B 对名称+描述+when_to_use 文本做嵌入，余弦相似度>阈值（跨项目 0.72、项目内 0.52）保留 Top-10 候选；GPT-6 Astra 担任配对裁判，确认 1,639 对（召回率 96%）。
- **分层采样**：按配对类型×脚本携带×相似度带分层，3,754 对样本估计流行度；312 对进入实验（表 2）。
- **核心功能提取**：GPT-6 Astra 逐技能生成要求清单，通过三检验：(1) 胜任模型无技能时通常无法满足；(2) 原文逐字引用；(3) 可在输出中验证。按措辞强度排序，取前 10 条；标记"独占"（B 未要求相同行为）与"共享"。
- **Case 构建**：每个配对生成一个任务案例——请求（不透露技能名/描述词）、≤15 文件的初始仓库、核心功能适用性标注、脚本/LLM 评判器。
- **配置矩阵**（表 3）：Only-A、Only-B、A+B、Swapped（顺序反转）、Personal-scope、Plugin-scope、A+C（无关技能对照），每对×每模型运行一次；另做 Guard 实验（deny 首次读取 B 的 pre-tool hook）。
- **三模型 × 多次重复**：claude-sonnet-4-6 / haiku-4-5 / opus-5；512 个组合重复 2-3 次检验稳定性（ICC=0.78 使用一致、0.84 核心功能一致）。

## 实验与结果
- **数据集**：20,947 仓库快照 → 822,109 候选对 → 3,754 判定的 1,639 对 → 312 实验对 → 6,368 运行（542 小时代理时间、169,294 工具调用、6.3B 输入/1.1 亿输出 token，API 成本约 $5,550）。Codex 侧验 193 对（gpt-5.5/5.6-luna/5.6-sol）。
- **关键数字**：
  - 流行度：63.7%（95% CI [61.3, 66.0]）已安装技能有另一作者相似技能；23.5%（[21.2, 25.7]）在同一安装列表中有同类技能；复制集合中 37% 技能存在冲突（vs. 其他项目 19%）。
  - RQ1 影响：A+B vs. Only-A，使用 A 的运行下降 19.9 pp，保真度下降 2.6 pp，**独占核心功能**下降 5.6 pp（每模型显著）；任务完成率不降（+1.9 pp，不显著）。无关技能 C 仅降使用 5.9 pp、保真度 -0.2 pp。
  - 替代 vs 干扰：12.1% 运行仅用 B（替代），38.0% 两者皆未用；替代运行保真度损失 8.0 pp，承担 36% 总损失；无使用 Neither 承担 45%；干扰（A 被用但结果变）仅 20%。
  - RQ2 选择：同名技能时，个人作用域覆盖项目作用域——A 从 listing 消失，B 使用率上升 46.5%，但仍 29.2% 运行读取 A 的文件；插件作用域下 B 使用率仅 2.9%；反转 listing 顺序仅影响 +0.6 pp。最终回复命名所用技能仅 0.9%。
  - RQ3 决定点：首次读取技能即决定冲突；A+B 与 Swapped 对比显示，先读 B 使独占核心功能保真度下降 9.4 pp（p=0.004）；97% 先读 B 的运行尚未修改任何文件。
  - Guard 实验：deny 首次读 B 后，模型 96% 切换至 A；独占核心功能保真度提升 9.1 pp（+6.0, +12.1）；重定向运行与仅读 A 运行无差异（0.0 pp）。
- **最强结果**：预工具钩子在首次读取时拦截 B，使独占核心功能保真度完全恢复至 Only-A 水平，且任务完成率不降。

## 相关工作脉络
- **Skill benchmarks（SWE-Skills-Bench、SkillsBench、SLBench）**：仅以任务通过率或检索准确率计分；本文提出"核心功能保真度"捕获隐性损失。
- **SkillCoach、BiasBusters**：发现 verifier 成功可能掩盖重叠 distractor 技能选择、位置/描述偏差；本文进一步量化"正确任务、错误技能"的幅度并定位决策点。
- **Tool selection 研究（MetaTool、Faghih et al.）**：报告工具被选概率；本文强调技能注入的指令会改变整体工作方式，选择偏差直接导致行为偏离。
- **包冲突/依赖冲突（Artho et al.、Vouillon & Di Cosmo、Watchman）**：在编译/解析期通过元数据规则检测；技能冲突在运行时由模型基于自然语言描述决定，需运行时干预。
- **Skill 安全与可复用性（Liu et al. 2026、Zhang et al. 2026、Saha et al.）**：关注恶意技能、缺陷；本文聚焦"良性但相似"技能的静默冲突。

## 局限性与未来方向
- **平台局限**：主实验仅在 Claude Code 完成；Codex 侧验 193 对结果方向一致，但未覆盖 Gemini CLI/Copilot CLI 等。
- **可见性偏差**：公共仓库无法观测个人目录技能与插件，流行度估计保守；真实部署中冲突比例更高。
- **核心功能提取依赖 LLM**：GPT-6 Astra 提取的 26,198 条核心功能需人工抽样校验（Krippendorff's α 0.77-0.85），可能存在遗漏或误标。
- **Case 构建假设**：初始仓库与请求为通用模板，未必覆盖所有领域特定工作流。
- **未来方向**：推广至多平台；自动化核心功能抽取与验证；设计技能"锁文件"机制；将 guard 集成进代理运行时。

## 研究启发与可借鉴点
- **"核心功能+独占性"评估框架**：可迁移至其他 Agent 技能/插件系统，替代仅靠 pass/fail 的粗粒度评测。
- **分层采样+LLM 裁判校准**：按业务维度分层、设相似度阈值保召回率，适合大规模技能/工具冲突挖掘。
- **冲突决定点定位法**：通过对比 listing 顺序反转后的首次工具调用差异，可推广至任何"选择决定结果"的 Agent 组件冲突研究。
- **Pre-tool hook 干预设计**：deny-first-read 模式可抽象为通用"组件抢占防护"原语，适用于工具集、prompt 模板等场景。
- **团队可结合方向**：将本研究的 core-function extraction pipeline 接入团队现有的技能管理平台，实现 co-installation 时的自动冲突预警与 listing 优化建议。

## 关键术语表
- **Agent Skill**：包含 SKILL.md 的目录，其 frontmatter 描述用途与触发条件，body 包含指令，由编码代理按需加载。
- **Core Function（核心功能）**：从 SKILL.md 逐字引用的、胜任模型无技能时通常无法满足且在输出中可验证的要求。
- **Exclusive Core Function（独占核心功能）**：仅由已安装技能 A 要求、相似技能 B 未要求的特定行为约束。
- **Fidelity（保真度）**：运行中完成的首要三个适用核心功能所占比例，用于度量 A 的行为保留程度。
- **Substitution（替代）**：B 完全取代 A 被执行，A 未被调用的冲突情形。
- **Interference（干扰）**：A 被调用但 B 的指令/脚本改变了最终结果，使 A 的核心功能部分失效。
- **Pre-tool Hook（预工具钩子）**：在代理发出工具调用前执行的拦截逻辑，本文用于 deny 首次读取 B 并强制转向 A。
- **Listing Order（Listing 顺序）**：技能名与描述被截断后拼入模型上下文时的排列顺序，理论上影响选择但本文发现影响极小。

## 可复现要素
- **数据集**：20,947 个公开仓库快照（2026-07-18）、55,698 独特 SKILL.md、312 实验配对 case 文件——均随 replication package 开源。
- **代码/权重**：GitHub 仓库 https://github.com/ltroin/conflict 含数据规则、提示词、安装重建脚本、case 构建器、评判器、所有运行日志与分析脚本；技能内容依许可公开或提供 identifier 供重新抓取。

# 论文速读：SkillContrast-Diference-Guided-Text-Selection-for-Agent-Skil

## 一句话总结
论文提出 SkillContrast，一种**免训练的文本选择方法**，通过比较候选技能全文的差异内容并结合局部上下文，为预训练重排器构建紧凑输入，从而在 Agent 技能重排序中有效识别目标适用技能、避免将其高风险相似版本混入结果。

## 研究问题与动机
- **核心问题**：Agent 平台（如 GitHub）中多个技能可能共享相似的说明指令，但适用条件（先决条件、软件版本、输入格式等）不同，传统查询相关性选择（如 TF-IDF）倾向于保留共享指令而遗漏关键区分条件，导致重排器无法有效区分优劣候选。
- **现有方法不足**：Body-aware routing（SkillRouter）和任务特定检索器（SkillRet）改进查询-技能匹配，但在同族合理候选中，描述共享仍会模糊适用性；query-conditioned 监督（R3-Skill）和通用内容偏差校准（SkillSight）分别从标注或分数角度入手，但**未能利用候选间文本差异这一直接信号**。
- **关键研究问题**：① 在固定输入长度下，候选差异（candidate differences）能否比查询相关性选择带来更优重排效果？② 增益主要来源于差异文本本身，还是上下文辅助？③ 紧凑输入能保留多少重排质量，节省多少 token？

## 核心贡献（创新点）
1. **提出 SkillContrast 免训练文本选择框架**：通过候选两两对比保留差异块及前文上下文，直接用冻结预训练重排器评分，不修改检索器、不额外训练模型。
2. **揭示"差异文本"是重排质量提升的主因**：通过长度匹配的组件替换实验，证明替换差异块使 CH@3 下降 78 个干净命中，而替换开头块或前文上下文影响几乎为 0，确立差异内容为最核心贡献。
3. **在同等输入长度下全面超越查询相关选择**：在 4 种（2 检索器×2 重排器尺寸）组合下，相比 TF-IDF 查询选择分别增加 54–72 个干净命中；同时削减 51.1%–58.8% 的模型输入 token。
4. **在 4B 重排器上甚至优于或持平全技能体输入**：4B 模型下 CH@3 较完整体反而高出 10 个，HSR@3 减少 15 个，证明差异引导的选择能过滤噪声、提升信号信噪比。
5. **开源可复现**：代码与冻结分数表 replay 已发布，配套 SameCapRisk-Bench 精确数据身份记录，保证完整可复现性。

## 方法详解
### 3.1 候选差异选择
- **表示与聚类**：将每个技能全文用 TF-IDF（小写 unigram+bigram，最多 16 万特征，按库单独拟合）表示；计算余弦相似度，≥0.65 的候选连入同一连通分量，无需任何标注信息。
- **逐行对齐提取差异**：在同一连通分量内，将两个候选体的文档按行对齐，识别差异块 $\Delta_{ij}$；对当前候选 $c_i$，其差异集合 $D_i = \bigcup_{j \in \Gamma_i} \Delta_{ij}$。
- **保留前文上下文**：定义 $P(D) = \{b-1 \mid b \in D, b > 0\}$，保留每个差异块的前一个块，加上文档开头块 $0$，得到最终选中块集合 $A_i = \{0\} \cup D_i \cup P(D_i)$，去重后按原文顺序保留。
- **无邻居分支**：若候选无相近邻居，改用查询-单元 TF-IDF 评分段落/标题/句子，保留第一个单元作为上下文，再依次添加正分单元及前驱，目标上限 256 token；超出则回退到完整体。
- **差异过大则回退**：若差异块超过 768 token 上限，直接使用该候选完整体，确保兜底可用性。

### 3.2 冻结重排与 MMR 多样性选择
- **冻结 Qwen3-Reranker**：使用 Qwen3-Reranker-0.6B / 4B（bfloat16，SDPA），对 $(q, d_i')$ 独立打分，不微调。
- **MMR 重排序**：令 $r_i = (N - \rho_i)/(N-1)$，MMR 选取：
  $$\arg\max_{i \notin S} \lambda r_i - (1-\lambda) \max_{j \in S} G_{ij}$$
  其中 $G_{ij}$ 为全技能体 TF-IDF 余弦相似度，$\lambda = 0.75$，$N=20$，取 Top-3。
- **设计要点**：MMR 的冗余惩罚基于全技能体相似度（而非选中片段），避免片段级相似度低估语义相近度；差异选择与 MMR 解耦，前者保证候选内容差异化，后者保证列表多样性。

### 3.3 长度匹配与消融设计
- **Prefix 控制**：截取每个技能体前 323 token（与 SkillContrast 相同长度），作为位置敏感基线。
- **Query-selected 控制**：用 TF-IDF 查询相关性选相同长度文本，隔离"内容选择" vs "长度" 的效应。
- **Query-context 变体**：保留差异块，但将前文上下文替换为查询相关的上下文，比较上下文来源的贡献。
- **组件替换实验**：仅替换差异块、开头块或前文上下文等长替换为 BM25 查询相关文本，保持其余部分不变，精确归因各组件贡献。
- **BM25 控制**：借鉴 KeyB 的 KeyB 式选择，适配到本文单位和输入预算，作为纯词汇选择方法的对比基线。

## 实验与结果
### 数据集
- **SameCapRisk-Bench** 890-unit 版本：823 个主单元生成 **1,235** 个请求（411 operation-contract、774 sourcerole、50 caller-interface），67 个开发单元生成 79 个请求（排除主结果）。
- 评估指标：$\mathbb{R}@\!3 = \mathbb{E}[H]$（帮助命中）、$\mathrm{HSR}@\!3 = \mathbb{E}[B]$（有害兄弟率）、$\mathrm{CH}@\!3 = \mathbb{E}[H(1-B)]$（干净命中）。

### 主要结果（表 1，Pipeline 比较）
| 方法 | R@3↑ | HSR@3↓ | CH@3↑ |
|------|------|--------|-------|
| R3-Skill | 0.846 | 0.137 | 0.813 |
| SkillSight | 0.837 | 0.165 | 0.767 |
| **SkillContrast（本文）** | **0.867** | **0.113** | **0.837** |

### 主要结果（表 2，等长文本选择比较）
- **SkillSight + 0.6B**：CH@3 = 0.837，对比 Query-selected（0.794）+0.043，对比 Prefix（0.784）+0.053；Mean tokens **786→323（-58.8%）**。
- **SkillSight + 4B**：CH@3 = 0.906，超越完整体（0.898）+0.008；对比 Query-selected（0.860）+0.046。
- **SkillRet + 4B**：CH@3 = 0.886，匹配完整体（0.886）；tokens **620→303（-51.1%）**。
- 相对于完整体：0.6B 损失 10–18 个干净命中；4B **反而多出 10 个**（SkillSight），且 HSR@3 同步下降。

### 消融结论
- **差异块是主因**（表 3）：替换差异块 CH@3 从 1,034 降至 956（-78），替换开头块无影响，替换前文仅 +4。
- **协议分布**：增益集中于 operation-contract 请求；SkillRet/4B 在此协议获 +72 个干净命中，而 sourcerole 仅 −2。
- **在线推理**：SkillContrast 较完整体节省 **10.4% 时间（约 76.8 ms/请求）**（单一 Pass 计时，含输入构造+编码+20 次 forward+MMR）。

## 相关工作脉络
1. **SkillSight [12]**：校准通用内容偏差，改进重排分数；本文与其差异在于 SkillSight 校正分数层面，SkillContrast 从**输入内容选择**层入手，二者可互补。
2. **SkillRet [4]**：大规模 LLM Agent 技能检索基准；本文在其候选池上验证文本选择，并证明即使固定候选，内容选择差异也能带来增益。
3. **R3-Skill [11]**：引入查询条件兼容性监督；本文与其定位差异是**免训练**，不依赖兼容性标签，直接利用候选间文本差异。
4. **KeyB [5]**：查询相关性选择关键块；本文强调 KeyB 对相似候选保留的是共享指令而非区分条件，SkillContrast 通过对比弥补这一缺陷。
5. **SkillRouter [14]**：大规模技能路由；本文聚焦于同族合理候选的排序阶段，而非路由阶段，二者处于 Pipeline 不同位置。
6. **MMR [1] / SMMR [6]**：多样性重排序经典方法；本文保留 MMR 不变，将创新点聚焦于"选什么文本"而非"如何多样性选择"。

## 局限性与未来方向
- **评估局限**：仅使用技能文本与标注，**未在实际 Agent 系统中执行技能**，CleanHit 只排除"标记的有害兄弟"，不排除其他安全风险。
- **检测局限**：TF-IDF 差异检测依赖线性对齐，对大幅度重写或结构差异较大的技能可能失效；连通图构建依赖 0.65 阈值，不同库的最优阈值可能不同。
- **推广局限**：仅在一个基准（SameCapRisk-Bench）上验证，尚未在独立标注的不同技能库上测试优势的可迁移性。
- **未来方向**：在具备适用性标注的独立技能库上进行跨库泛化测试；将免训练选择与端到端微调方法结合；扩展至代码技能、函数签名等结构化文本的差异捕获。

## 研究启发与可借鉴点
1. **差异引导的内容选择范式可迁移**：该方法论（比较候选→提取差异→保留局部上下文→冻结重排器评分）可直接迁移到其他领域：如多文档问答中选择支持性段落、API 文档选择中与版本相关的差异化说明、代码片段检索中选择与目标版本相关的差异接口。
2. **组件替换实验的设计价值**：通过"等长替换差异块/开头块/前文上下文"隔离各组件贡献，这种消融策略严谨、可信，适合本团队后续在文本选择研究中复用。
3. **免训练方法在实际部署中的成本优势**：SkillContrast 完全不训练，仅需预计算 TF-IDF 和一次对齐，配合冻结 Qwen3-Reranker，部署开销极低，对工业场景有直接吸引力。
4. **与 SkillSight/R3-Skill 的方法融合机会**：Score 校准（SkillSight）+ 内容选择（SkillContrast）可形成双层筛选：先用 SkillContrast 选出区分性内容，再用 SkillSight 校准分数，可能进一步压缩 HSR@3。
5. **operation-contract 协议的集中增益**提示：差异选择对"明确条件型"请求（版本、配置、接口参数等）效果更显著，可针对性优先部署在类似场景。

## 关键术语表
- **SkillContrast**：一种免训练的文本选择方法，通过比较候选技能全文差异并保留局部上下文，为预训练重排器构建紧凑、高区分度的输入。
- **SameCapRisk-Bench**：评估 Agent 技能检索是否将有害相似技能混入结果的基准，包含 operation-contract、sourcerole、caller-interface 三类请求协议。
- **CH@3（CleanHit@3）**：Top-3 结果中包含帮助技能且不包含其标记有害兄弟的概率，本文核心评估指标。
- **MMR（Maximal Marginal Relevance）**：平衡查询相关性与结果多样性的重排序策略，本文固定 $\lambda=0.75$ 用于 Top-3 选择。
- **Qwen3-Reranker**：阿里云 Qwen3 系列的冻结重排模型，本文使用 0.6B 和 4B 两种规模，bfloat16 精度，不参与训练。
- **Query-selected**：基于 TF-IDF 查询-单元相关性得分选择等长文本的基线方法，与 SkillContrast 形成内容选择维度的对照。
- **连通分量聚类**：以 TF-IDF 余弦相似度 ≥0.65 为边构建候选相似度图，差异提取在同一连通分量内执行。
- **Component replacement 消融**：将差异块/开头块/前文上下文替换为等长查询相关文本，精确归因各内容组件对 CH@3 的贡献。

## 可复现要素
- **数据集**：SameCapRisk-Bench 890-unit 版本（823 主单元 + 67 开发单元），**论文未说明是否对外公开**，但配套发布包记录精确数据身份，可联系作者获取。
- **代码/权重**：代码和冻结分数表 replay 已开源至 https://anonymous.4open.science/r/SkillContrast-92C8/；Qwen3-Reranker 为公开预训练模型。
- **关键超参**：TF-IDF 最大特征数 160,000；余弦相似度阈值 0.65；MMR $\lambda = 0.75$；$N=20$，$K=3$；差异块目标上限 768 token；无邻居分支目标上限 256 token；reranker 使用 bfloat16、SDPA、microbatch=1。

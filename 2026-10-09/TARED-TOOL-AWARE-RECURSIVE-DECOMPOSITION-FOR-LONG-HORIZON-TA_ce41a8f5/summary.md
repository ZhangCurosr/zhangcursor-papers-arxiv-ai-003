# 论文速读：TARED: TOOL-AWARE RECURSIVE DECOMPOSITION FOR LONG-HORIZON TASKS

## 一句话总结
本文提出 TaReD（Tool-Aware Recursive Decomposition），通过将大型工具库组织成功能能力层次结构，并在执行过程中按需发现工具、基于能力边界递归分解长 horizon 任务，显著提升了多工具环境下复杂交互任务的端到端成功率。

## 研究问题与动机
- **长 horizon 任务执行可靠性不足**：早期 Agent 采用单一链式推理-行动交互方式，随着任务复杂度上升，中间依赖关系日益模糊，早期规划或执行错误容易级联传播至后续步骤，导致端到端成功率下降。
- **工具库过大难以完整暴露**：真实系统中工具数量庞大（如 AppWorld 含 457 个工具），将所有工具描述和契约注入上下文不仅消耗大量 token，还会干扰 planner 对任务相关工具的选择。
- **已有子集选择方案存在遗漏风险**：预测固定工具子集的方法虽能降低上下文开销，但可能遗漏必要工具，且平铺呈现工具信息缺乏结构化指导，难以帮助划分与执行能力对齐的子任务边界。
- **语义分解与执行能力脱节**：仅基于任务语义（目标、实体、流程）进行分解，不能保证每个子任务都能被系统当前可用的操作执行，可能产生不可执行的子任务或遗漏必要阶段。

## 核心贡献（创新点）
- **提出基于功能关系的工具能力层次结构**：将平铺的工具库组织为树形能力层级（内部节点为能力摘要，叶节点为完整工具契约），与已有工作在平铺列表或固定子集基础上引入结构化导航能力存在本质区别。
- **设计按需（on-demand）能力导航机制**：根据当前子任务目标与上下文，从预期能力区域出发逐层探索能力树，仅在需要时检索相关信息，避免全量工具注入与固定子集遗漏的双重缺陷。
- **提出能力对齐的递归任务分解框架**：利用能力树的结构关系引导任务分解为与可用操作边界对齐的功能阶段，而非仅依赖语义切分，使子任务粒度与执行能力自然匹配。
- **引入延迟契约绑定（delayed contract binding）与引用式值传递**：精确工具契约仅在阶段准备执行时才检索与绑定，并通过稳定引用在子任务间传递所需输出值，减少上下文冗余并保障状态依赖的可靠传递。

## 方法详解
- **层次化能力表示**：工具库被组织为树 $\mathcal{G} = (\mathcal{V}, \mathcal{E})$，根节点代表完整库，内部节点存储能力卡 $\text{cap}(v) = (\text{name}, \text{summary}, \text{children}, \text{scope})$，叶节点对应可执行工具的完整契约 $T_i = (\text{In}_i, \text{Out}_i, \text{Pre}_i, \text{Eff}_i)$。
- **按需能力导航**：对于任务节点 $h = (q_h, c_h, r_h)$，控制器调用 $\text{Navigate}(q_h, c_h, r_h; \mathcal{G})$，从预期区域 $r_h$ 出发逐层查询，直到获取足够规划信息；若当前区域不足，则搜索其他能力区域补全信息。
- **递归分解与执行协议**：
  - 判断当前节点是否可直接执行（$\text{Direct}(h) = \text{True}$）：若能，则计划并执行工具调用序列；否则，基于能力信息将其递归分解为有序子任务 $(h_1, \ldots, h_k)$，并记录依赖关系 $\mathcal{D}_h$ 与输入绑定 $B_{ij}$。
  - 深度优先处理子任务，前驱节点完成后且绑定可解析时再调度后继节点，避免提前暴露不必要工具信息。
- **延迟契约绑定与值存储**：仅在阶段准备执行时检索具体工具契约 $d_i$，从契约、阶段上下文及值存储 $\mathcal{M}$ 中绑定参数 $z_i$；每次执行后以稳定引用 $k_i$ 存储观测结果 $(o_i, \text{prov}(o_i))$，供后续调用或依赖子任务通过引用检索，而非复制完整响应。
- **算法流程**：整体以递归过程实现（Algorithm 1），从初始化任务节点 $h_0 = (x, c_0, \text{root}(\mathcal{G}))$ 开始，通过 $\text{HANDLENODE}$ 函数循环执行能力导航、充分性判断、直接执行或递归分解，并维护环境状态 $s$ 与值存储 $\mathcal{M}$。

## 实验与结果
- **数据集与环境**：AppWorld Challenge Set（Test-C），包含 9 个应用、共 457 个工具的交互式长 horizon 任务环境，配有官方程序化验证器。
- **评估基线**：ReAct（线性推理-行动）、Plan-and-Solve（两阶段计划执行）、ADAPT（executor-first 递归策略，使用一次预测工具子集）。
- **主要结果**（Table 1）：

| 方法 | TGC | SGC | ATVS |
|------|-----|-----|------|
| ReAct | 51.3% | 26% | 66.81 |
| Plan-and-Solve | 29.3% | 16% | 60.60 |
| ADAPT | 46.7% | 22% | 66.01 |
| **TaReD** | **69.3%** | **48%** | **80.28** |

- TaReD 在三项指标上均达最优，相对最强基线（ReAct）提升 **18.0 个百分点**，相对 Plan-and-Solve 提升 **40 个百分点**。
- **消融实验**（Table 2）：
  - Predictor subset：TGC 51.3%，SGC 32%，ATVS 66.52
  - Full tool injection：TGC 52.0%，SGC 22%，ATVS 71.81
  - Expandable tool subset：TGC 58.7%，SGC 42%，ATVS 77.78
  - Hierarchical tool awareness（TaReD）：TGC 69.3%，SGC 48%，ATVS 80.28
- 全量工具注入仅轻微提升，说明冗长描述会分散 agent 注意力；可扩子集通过执行期补救提升明显，但仍不及层次化能力导航；Hierarchical 方案以合理上下文开销取得最佳性能。
- **工具暴露分析**：平铺预测方案有 12% 任务存在阻塞性工具遗漏，占失败案例的 24.3%；TaReD 在运行中平均仅暴露 7.41% 工具的能力信息与 2.48% 工具的详细契约，实现选择性暴露。

## 相关工作脉络
- **Chain-of-thought / ReAct 系列**：Yao et al. (2023) 提出线性交互模式，将推理与工具调用交替执行于单一轨迹；TaReD 通过递归分解打破长链，降低状态追踪难度。
- **任务分解与分层规划**：Prasad et al. (2024) 的 ADAPT 采用 executor-first 递归策略；但其在固定扁平工具子集上分解，缺乏能力边界指导，且易遗漏工具。
- **Plan-and-Solve**：Wang et al. (2023) 先完整规划后执行，前期错误难以在运行时修正；TaReD 支持执行期递归反馈与重规划。
- **工具选择与检索**：ToolLLM（Qin et al., 2023）、ToolGen（Wang et al., 2025）等研究工具子集预测或检索；TaReD 通过层次结构导航保留全库可达性，避免子集预测的遗漏风险。
- **语义驱动分解**：早期方法（Press et al., 2022；Zhou et al., 2023）基于目标/实体/程序结构切分任务，不考虑环境可执行性；TaReD 将分解与能力结构对齐。
- **大工具库上下文管理**：ToolkenGPT（Hao et al., 2023）通过工具嵌入扩展 LLM 能力；TaReD 侧重在执行过程中按需导航能力树，控制上下文规模。

## 局限性与未来方向
- **层次导航开销**：逐层探索能力树可能引入额外的模型调用，增加执行时间；当前实现通过 toocache 复用已查询节点来缓解，但增大了工作上下文的信息留存。
- **上下文与发现的权衡**：缓存已发现节点减少了重复查询，却增加了上下文负担，两者之间的平衡机制仍有待优化。
- **静态树构建依赖人工/半自动标注**：能力树的构建依赖 AI agent（Codex）基于 API 文档策划分类体系，分类质量直接影响导航效果。
- **复合工具尚未支持**：当前树中内部节点不可执行，复合操作需要单独实现的节点类型与契约，限制了跨工具组合能力的表达。

## 研究启发与可借鉴点
- **能力层次结构用于上下文管理**：将工具库按功能关系组织为树，并在执行中按需暴露信息，可迁移至其他工具调用密集场景，有效控制 agent 上下文长度。
- **延迟绑定策略降低规划负担**：在分解阶段仅保留能力摘要而不暴露详细参数契约，直至阶段准备执行时才检索完整契约，减少规划决策中的参数噪声，适用于复杂多步工具编排。
- **引用式值传递替代上下文复制**：通过稳定引用 $(k_i, o_i, \text{prov}(o_i))$ 在子任务间传递依赖值，而非复制完整响应，有助于维持长 horizon 任务的记忆效率与依赖追踪。
- **能力边界引导分解粒度**：利用能力树中间节点的"功能范围"定义子任务边界，而非仅依赖任务语义切分，可为多工具环境下的任务分解提供结构化先验。
- **可扩展的实验设计参考**：消融实验中对比 predictor subset / full injection / expandable subset / hierarchical 四种工具暴露策略，为评估工具管理与上下文控制方法提供可复用的对照框架。

## 关键术语表
- **TaReD**：Tool-Aware Recursive Decomposition，本文提出的工具感知递归分解框架，结合能力层次导航与递归任务分解完成长 horizon 任务。
- **Capability Hierarchy（能力层次结构）**：将工具库按功能关系组织为树形结构，内部节点为能力区域摘要，叶节点为完整工具契约的可执行树。
- **On-Demand Navigation（按需导航）**：根据当前子任务目标从预期能力区域出发，逐层查询能力树以获取足够规划信息，避免全量工具注入。
- **Delayed Contract Binding（延迟契约绑定）**：精确工具契约（输入/输出/前置条件/副作用）仅在阶段被判定为可直接执行时才检索与参数绑定。
- **Task Tree / Stage（任务树/阶段）**：递归分解产生的有序任务节点，内部节点继续分解，叶节点绑定工具执行；每个阶段携带目标 $q_h$、上下文 $c_h$、能力区域 $r_h$。
- **TGC / SGC / ATVS**：AppWorld 三项评测指标——任务目标完成率、场景目标完成率、归一化任务验证平均得分。
- **Tool Contract（工具契约）**：工具的形式化描述 $T_i = (\text{In}_i, \text{Out}_i, \text{Pre}_i, \text{Eff}_i)$，包含输入/输出 schema、前置条件与状态变更效果。
- **AppWorld**：包含 9 个应用、457 个工具的交互式评估环境，用于评测 Agent 在长 horizon 多工具任务中的执行能力。

## 可复现要素
- **数据集**：AppWorld Challenge Set（Test-C），工具库含 457 个工具、137 个类别节点，环境官方提供程序化验证器。
- **代码开源**：TaReD 实现已开源，GitHub 地址：https://github.com/WeiXiang-Mao/TaReD
- **模型**：实验统一使用 GPT-5.6 Luna，temperature=0，单 episode 最多 100 步、600 秒上限，随机种子 42。
- **关键超参**：论文未详细列出分层树构建的具体超参；缓存策略细节论文未提及。
- **能力树构建**：由 AI agent（Codex）基于公开 API 文档策划版本化分类体系，再由确定性构建器生成，分类与工具映射为静态预处理步骤。

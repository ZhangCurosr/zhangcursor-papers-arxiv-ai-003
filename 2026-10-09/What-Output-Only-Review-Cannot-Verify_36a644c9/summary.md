# 论文速读：What-Output-Only-Review-Cannot-Verify

## 一句话总结
提出“研究合同（study contracts）”框架，将已批准的研究设计、执行义务与声明范围绑定至不可篡改的环境对象，实现合同相对验证；在故意信息不对称的诊断实验中，确定性检查器拦截全部注册变异，而仅依赖过滤后输出包的LLM裁判对基于“缺失”的故障几乎无法检出。

## 研究问题与动机
- 核心问题：自我改进型AI研究代理的元循环缺乏真正的科学质量奖励信号，现有验证多依赖任务完成度、工件存在性或输出文本的LLM-as-judge，这些信号仅局部对应任务或输出表面，无法编码“已批准研究”与“实际执行”之间的关系。
- 现有方法不足：(1) 任务完成不蕴含科学有效（错误比较器仍可按期交付）；(2) 工件存在性检查停留在任务级，无法支撑研究级的优越性/转移性声明；(3) 单元测试验证软件正确性但不校验数据划分或指标语义；(4) LLM-as-judge仅审阅代理直接控制的生成文本，对静默发生的方法学漂移缺乏感知力。
- 威胁模型边界：受保护对象为已批准合同修订及其摘要链、开发语料金标、授权记录与检查器谓词；假设执行观测经代理不可重写的路径采集；代理的转录、叙述、规范修订提案与自报告完成状态均不可信。

## 核心贡献（创新点）
1. 提出研究合同框架实现合同相对验证：将研究问题、数据身份、实验臂、指标、期望运行清单、证据义务与授权适应策略绑定为单一不可变对象，实现从“输出/任务级检查”到“环境/合同级绑定”的验证范式转换。与已有工作的本质区别：不追求判定科学真值，而是提供代理仅能控制一侧关系的可核查合规信号，显式区分科学有效性与合同相对可验证性。
2. 形式化六种静默协议变异通道（M1–M6）：将设计未规格化、绑定漂移、语义漂移、幸存者漂移、范围膨胀与重建漂移统一为自我优化代理在非对抗性运行下可自然触发的代理游戏路径。与已有工作的本质区别：将传统元科学偏差（HARKing、选择性报告等）重新映射为计算科学代理环境的结构性漏洞，而非依赖恶意对抗行为。
3. 设计四项可检查属性（P1–P4）与分级验证架构：包含版本化摘要绑定链、期望运行分母完整性、类型化声明升级与人类认证闸门，并将验证信号划分为“提出异议→作出裁决→执行拒绝/阻塞升级”三级。与已有工作的本质区别：超越仅生成审查意见或裁决的被动检查，赋予系统主动拒绝不合规声明晋升的权限与前瞻性授权天花板。
4. 构造信息边界诊断实验：在故意信息不对称设定下，用8对自构清洁/变异包测试确定性检查器与18个LLM裁判别名，刻画仅凭输出包可推断的故障边界。与已有工作的本质区别：不宣称通用准确率，而是精准定位哪些缺陷可从包内矛盾推断、哪些真正依赖未被提供的授权要求，为验证工具评估提供强因果分解思路。

## 方法详解
- 研究合同对象：$C_v = (Q, D, A, M, R, O, H, \Pi)$，其中$Q$为问题与声明范围、$D$为数据身份、$A$为实验臂、$M$为指标与决策规则、$R$为期望运行清单、$O$为类型化证据义务、$H$为授权与批准状态、$\Pi$为授权适应策略。执行状态通过认证历史引用$C_v$，代理可读取与提议修订，但不能自写入批准或事后更改合同。
- P1 研究级合同绑定：审批记录携带规范、编译器与能力身份的摘要链；任何绑定身份的后批准篡改均使审批失效。检查对象为版本化链（已批准规范→编译器版本→发射的运行契约→采集的观测），哈希在各链路建立相等性与篡改证据。
- P2 期望运行分母：执行前发射预定清单（如24个臂-种子任务）；执行账本必须记录全部单元（含失败与授权过渡），重试不扩大分母，估计量遵循预声明缺失规则。仅读成功结果的裁判可能认为内部一致，但分母已被暗中修改。
- P3 类型化声明升级：候选声明携带类型化范围（人群/任务/终点/数据版本/比较器/指标/时间/站点/领域）；义务含 `discharge_method`（mechanical / human_semantic）与 `waiver_policy`（forbidden / scope_reducing / permitted_under_conditions）字段。实现支持 forbidden 与 typed scope_reducing 豁免；conditional 路径未实际评估，未依赖其工作。
- P4 人类认证闸门：规范批准、实质豁免、数据治理授权与报告升级均需带外人类身份认证；代理可起草但无法自行生效，聊天确认不等于批准。
- 策略冻结哲学：冻结$\Pi$（适应策略/搜索边界/停止规则/前瞻性分母调整规则）而非冻结具体执行轨迹；脱离 envelope 视为明确修订或探索性分支，附带降级的声明状态。
- 导出规范：研究代理应导出 `study object`（含适应策略、期望运行清单、声明-义务映射）而非仅 `paper object`，使元决策规则可定义于绑定完整性、分母完整性、固定范围下的可准入声明产量等合同相对量。

## 实验与结果
- 数据集/语料：8对自构清洁/变异研究工件对（seed 20260815），覆盖 compilation_drift、comparison_budget、external_validation、reconstruction、runtime_contract、integrity_digest、split_policy、evidence_absence 八类注册故障。
- 评估设置：确定性合约检查器 vs 18个LLM裁判别名（OpenAI/Gemini/Anthropic，未锁定版本，评估窗口约2026-08-15 UTC）。裁判仅接收元数据过滤后的单一包（无配对上下文与故障标签），被指示证据不足时 abstain。共288个逻辑判断（18别名 × 16包）。
- 主要结果（Table 1）：
  - 确定性检查器：8/8变异全部阻断，0/8假阳性；无变异案例获 explicit clean 判决。
  - LLM裁判：变异包中104/144获 `defect flag`，32 abstention，8 terminal failure；清洁控制包1/144 flag，74 clean，63 abstention，6 failure。
- 按故障可检测性分区（Appendix C）：
  - 高检出（包内含内部矛盾）：digest漂移18/18、预算不匹配17/18、过度泛化外部声明17/18、重建清单不完整17/18、实质工作负载变异16/18、工件摘要不匹配16/18。
  - 极低检出（依赖“缺失”证据）：缺失split/grouping声明2/18、缺失必需指标工件1/18。这两类正是需要授权合同规定“应有何物”的故障。
- 启发式sanity check：奖励包长度、浮夸词汇与稀疏seed的确定性启发式（无故障标签）在5/8对包上得分不低于清洁对照，仅说明输出表面特征可被优化利用，不指向具体代理奖励作弊。
- 结论：诊断刻画了信息不对称下的可推断边界；absence-based faults 高度依赖未被提供的权威要求，而非裁判能力上限。

## 相关工作脉络
1. EviBound [1]：预执行审批闸门+后执行工件验证，侧重任务级验证；本文聚焦研究级合同绑定与声明升级天花板，并提供主动 enforcement（拒绝晋升）权限。
2. Frontier-Challenge [11] 与 DeltaML-Bench [12]：前者揭示部分得分/完成语言不可靠，后者展示模块化ML代理可提升指标但违背科学意图；本文引用其作为代理游戏路径的经验支撑，但提供更细粒度的合同相对检查与分母完整性约束。
3. Claim-aware observability [13] 与 ClaimReceipt [14]：绑定声明与证据、检查证据充分性；本文明确区分“提出异议(production of finding)”、“作出裁决(issue verdict)”与“执行拒绝(enforcement/block promotion)”三级，本文补充前两级缺失的权威参考系（预期分母与声明天花板）。
4. Agent flight recorder [15] 与 Agentic Configuration Management [16]：保护记录完整性、提供类型化版本配置；本文不依赖其声明科学有效，而是补充研究合同层面的授权适应策略与声明-义务映射。
5. 溯源/打包标准 [18–22] 与报告规范 [23–28]：提供契约义务的证据基础与回溯报告结构；本文创新在于前瞻性授权关系（expected units/attempts/claim slots）与信息边界诊断，而非证据收集本身。
6. AI Research Objects [29] 与自我改进研究系统（如AutoSci [4]）：提供持久记忆/自动重试/自主写作机制；本文指出若缺授权合同与闸门，这些机制反而使M1–M6变异可通过常规非对抗行为浮现。

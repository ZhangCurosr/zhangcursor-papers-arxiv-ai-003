# 论文速读：SEAR-Self-Evolving-Agentic-Robotics

## 一句话总结
本文提出了 SEAR 框架，用于系统评估自进化 Agent 在机器人任务中的真实学习能力，通过配对控制实验消除混淆因素，并揭示了当前方法在跨任务、跨模拟器和真实硬件上的泛化瓶颈。

---

## 研究问题与动机
- **核心问题①**：自进化提升成功率可能源于更多尝试次数、熟悉任务、特权信息、更大计算预算或运气，而非真正学到了可迁移的经验。
- **核心问题②**：即使 Agent 在某任务上表现提升，所学内容在新任务、新模拟器（MuJoCo → Isaac Sim）、真实机器人上是否仍然有效？
- **单一学习曲线无法回答上述问题**，必须通过配对控制实验来区分"学习"与"捷径"。
- **现有研究缺乏严格的混淆控制**：多数工作仅报告最终成功率，未隔离尝试次数、特权信息等因素的影响。

---

## 核心贡献（创新点）
- **提出三项 Agent 运行模式（CaP/AaP/AR）**：区分代码驱动、LM 循环驱动、自主研究型三种范式，为对比实验提供结构化设计。
- **设计五项混淆控制机制**：Best-of-3、隔离初始状态、Sealed Judge、三次独立重复、预算匹配，系统排除非学习因素的干扰。
- **建立五级泛化评估体系（T1–T5）**：从同任务新初始状态到真实机器人部署的递进式泛化层次，填补了机器人 Agent 评估的系统性空白。
- **构建大规模评测基准**：覆盖 5 个模拟家族共 330 个任务 + 5 个真实物理任务，支持跨 LLM、跨模拟器的综合对比。
- **揭示"虚假进化"现象**：发现部分 Agent 的提升主要来自尝试次数增加或任务熟悉度，而非可迁移的抽象技能。

---

## 方法详解

### 三种 Agent 运行模式
| 模式 | 全称 | 说明 |
|------|------|------|
| **CaP** | Code-as-Policy | Agent 写代码程序作为策略；执行时无 LM 参与，快速、可重评 |
| **AaP** | Agent-as-Policy | LM 留在控制循环中，每次命令等待模型调用，较慢 |
| **AR** | Auto-Research | Agent 作为研究者收集 rollouts、微调 VLA π₀.₅，决定下一步实验 |

### 核心组件
- **Toolbox**：集成 SAM3（图像分割）、预训练 π₀.₅ VLA 模型、逆运动学接口、伺服接口。
- **Library（跨任务持久化）**：存储版本化代码技能与书面记忆，支持跨任务复用；AR checkpoint 和数据不跨任务。
- **Sealed Judge**：Agent 容器与评判容器完全隔离；DEV/VAL/TEST 种子严格划分；冻结策略由外部 judge 独立评分，防止信息泄露。

### 五项混淆控制
| 混淆来源 | 控制方法 |
|----------|----------|
| 更多尝试次数 | Best-of-3：比较三段短尝试 vs 一段长尝试 |
| 熟悉任务 | TEST 初始状态从未展示给 Agent |
| 特权信息 | Sealed Judge：Agent 无法访问评判逻辑 |
| 运气 | 三次独立重复运行 |
| 更大预算 | 所有对比开发时间匹配；记录 tokens/环境步数/GPU 时间 |

### 泛化层级（T1–T5）
- **T1**：实践任务的新的初始状态
- **T2**：相同任务，场景变更或硬件故障
- **T3**：同模拟器中的新任务（需 self-exploration）
- **T4**：新模拟器 + 新 action API（MuJoCo → Isaac Sim）
- **T5**：真实机器人部署

## 实验与结果

### 数据集与任务
- **模拟任务**：5 个家族，共 330 个任务
  - Robosuite：7 任务
  - LIBERO：40 任务
  - LIBERO-PRO：160 任务
  - LIBERO-RIG：18 任务（含隐藏硬件故障）
  - RoboLab（Isaac Sim）：105 任务
- **物理任务**：5 个任务（Banana into Bowl、Push-T、Cup Upright、Block Stacking、Spell "SEAR"）
  - 平台：双臂 YAM-Ultra + 固定俯视相机 + 双腕相机
  - 每次额外需学习一个 reset 任务；最多 12 小时/任务；连续 10 次成功停止

### 测试 Agent 配置
- **模拟环境**：Claude Opus 5、GPT-5.6-sol、Gemini-3.6-flash、Kimi-k3、DeepSeek-v4-flash（纯文本）
- **硬件环境**：Claude Fable 5.1、Opus 5、GPT-6-astra
- DeepSeek-v4-flash 为纯文本模型，通过 SAM3 + 深度图工具获得视觉信息
- 每个条件 3 次重复（部分例外）

## 局限性与未来方向
- **真实机器人数据规模有限**：仅 5 个物理任务，难以支撑统计显著性结论。
- **AR 模式的计算开销高**：微调 VLA + 多轮实验设计耗时较长，限制大规模应用。
- **Library 的跨任务迁移效果待验证**：当前设计支持持久化，但实际复用效率未充分测试。
- **未来方向**：扩展至更多真实机器人场景；探索更高效的技能压缩与检索机制；研究 T4/T5 泛化的理论边界。

- **混淆控制设计**：五项控制机制（Best-of-3、Sealed Judge、预算匹配等）可直接复用于其他 Agent 学习研究，提升实验严谨性。

- ** Library 设计思想**：跨任务持久化技能存储与版本管理，值得在其他多任务学习场景中借鉴。
- **与团队方向结合机会**：若团队关注低资源机器人学习，可借鉴 AR 模式的自探索策略；若关注评估，可引入 SEAR 的控制实验设计。

## 关键术语表
- **Self-Evolving Agent**：能通过试错和自我反思不断提升性能的 AI 系统。
- **Code-as-Policy (CaP)**：Agent 生成可执行代码作为策略，推理时无需 LLM 参与。
- **Agent-as-Policy (AaP)**：LLM 保留在控制循环中，每步决策实时调用模型。
- **Auto-Research (AR)**：Agent 作为研究者自主设计实验、收集数据并微调模型。
- **Sealed Judge**：与 Agent 隔离的独立评判器，防止信息泄露导致的虚假提升。
- **泛化层级 T1–T5**：从同任务新初始状态到真实机器人部署的五级递进泛化能力。
- **VLA (Vision-Language-Action)**：融合视觉、语言与动作输出的机器人策略模型。
- **混淆控制**：排除非学习因素（如尝试次数、熟悉度）对评估结果的干扰。

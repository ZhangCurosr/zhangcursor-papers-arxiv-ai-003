# 论文速读：SolBehave: Evaluating the Behavioural Correctness of LLM-Generated Smart Contracts

## 一句话总结
本文提出 SolBehave，一个面向 LLM 生成 Solidity 智能合约的行为正确性评估基准。通过差异模糊测试、历史交易重放和 DCR 图引导的合成交易重放三种互补预言机，揭示编译成功仅是正确性的必要而非充分条件。

## 研究问题与动机
1. **现有评估范式不足**：当前 LLM 智能合约生成的主流评估仅关注编译成功率（Compile@k），无法检测语义层面的行为偏差。
2. **智能合约不可修补性**：一旦部署至区块链，合约代码永久不可修改，单个潜在漏洞可能导致真实经济损失。
3. **单一测试源覆盖盲区**：历史交易重放仅覆盖链上实际发生过的调用序列；模糊测试虽探索大量输入但测试函数孤立，无法覆盖需特定调用顺序才能到达的状态。
4. **缺乏大规模行为级基准**：现有工作（SolBench、SolContractEval）在测试深度与广度之间存在权衡，缺少统一的行为保真度评估框架。

## 核心贡献（创新点）
1. **提出三种互补的行为保真度预言机**：O1 差异模糊测试、O2 历史交易重放、O3 DCR 图引导的合成交易重放，三者分别针对函数级、历史行为和预期生命周期进行验证。
2. **引入 DCR 图驱动的合成交易生成方法**：首次将 Dynamic Condition Response 图用于 LLM 生成代码的行为测试序列合成，结合神经（LLM 提取图）与符号（图遍历算法）方法。
3. **构建 250 个可复现的以太坊真实合约基准**：所有合约均经过"重新部署后复现链上历史"验证，确保测试基准的可靠性与可复现性。
4. **揭示编译率与行为正确性的巨大鸿沟**：即使编译成功率高达 92.7%，经差异模糊测试仅有 31.4% 的编译成功函数与原始等价。

## 方法详解
1. **基准构建**：从 Etherscan 爬取 2023-01-01 以来的合约，筛选有验证源码、非代理合约、积累≥200 笔历史交易的候选者（8,360 个）；重新部署后验证能复现≥80% 历史行为的合约；按非平凡函数数（1-20 个）过滤得到 250 个最终基准合约。
2. **代码生成**：采用 stub-and-complete 协议，删除函数体后保留签名、可见性、修饰符和 NatSpec，模型按源码顺序逐个补全函数体；每个合约生成 k=10 个样本。
3. **O1 差异模糊测试**：为每个可模糊函数（状态修改函数且参数均为原始类型）构建 harness 合约，同时部署原始合约 $C^*$ 和生成合约 $\hat{C}$，使用 Echidna 在 10,000 次调用、120 秒超时内搜索使两者行为不一致的输入。
4. **O2 历史交易重放**：取原始合约的前 1,000 笔链上历史交易，以相同顺序和发送者在本地 Hardhat 节点上重放至两个合约，比较交易状态（成功/回退）。
5. **O3 DCR 引导的合成交易重放**：
   - **DCR 图提取**：LLM 从合约源码和 ABI 提取包含 4 种关系（Condition、Response、Inclusion、Exclusion）的 DCR 图，可为关系添加守卫条件。
   - **已验证序列生成**：算法遍历 DCR 图，在每步评估守卫条件，按优先级（义务 > 前提 > 探索）选择事件，执行于原始合约并仅保留成功调用，累积至预算。
   - **关键设计**：所有权转移事件最后执行；每个守卫直接从部署合约读取状态值计算。
6. **比较维度**：主要标准为调用状态匹配率（status match rate），次要观察 gas 消耗（±10% 阈值）和事件输出。

## 实验与结果
- **数据集**：250 个从 Etherscan 筛选的以太坊主网真实合约，每个生成 10 个样本，共 7 个开源权重模型。
- **编译成功率**：修复后范围为 26.4%（DEVSTRAL-24B）至 92.7%（GEMMA-4-31B）。
- **O1 差异模糊测试结果**：所有模型中位数为 31.4% 的编译成功函数与原始等价；GEMMA-4-31B 达到 33.4%，DEVSTRAL-24B 仅 2.0%。
- **O2 历史重放结果**：GEMMA-4-31B 状态匹配率 99.6%，DEVSTRAL-24B 为 88.2%；6 个模型有 13%-31% 的生成合约产生分歧。
- **O3 DCR 重放结果**：GEMMA-4-31B 状态匹配率 98.4%，其他模型 81.8%-96.1%；13%-44% 的生成合约产生分歧；仅 GEMMA-4-31B 低于 3%。
- **三种预言机互补性**：每种预言机均发现其他两种接受为正确的合约存在分歧，覆盖盲区互不重叠。
- **DCR 图提取质量**：GEMMA-4-31B 提取的条件关系精确率 0.96，总体精确率 0.72、召回率 0.88。
- **最强模型**：GEMMA-4-31B 在编译率和行为正确性上均最优。

## 相关工作脉络
1. **SolBench [10]**：对 7,604 个合约进行差异模糊测试，但测试函数孤立调用，无法保证需要特定前序状态才能触发的行为被覆盖。
2. **SolContractEval [11]**：重放真实主网历史交易，覆盖真实使用模式但受限于历史交易记录，未覆盖链上从未发生过的合法调用序列。
3. **SolEval [9]**：结合编译率、Pass@k、gas 消耗和漏洞率评估，但未进行执行级行为比较。
4. **Sequence-aware fuzzing（IR-Fuzz [29]、MuFuzz [30]）**：探索调用顺序以覆盖更多分支，但目标是在单一合约中找 bug，而非比较生成合约与原始合约的行为一致性。
5. **Static analysis 工具（Slither [18]、Mythril [19]）**：无需执行即可分析代码，但无法观察生成合约的实际运行时行为。
6. **HighGuard [34]**：同样使用 DCR 图，但由开发者手动编写规范用于运行时监控，本文首次自动提取 DCR 图用于测试序列生成。

## 局限性与未来方向
1. **基准合约类型偏向**：当前基准以 token 类合约为主，DeFi 协议、桥接合约和治理系统等更复杂的合约尚未覆盖。
2. **初始状态限制**：重新部署从构造函数状态开始，可能遗漏仅在合约生命周期后期才显现的漏洞。
3. **DCR 提取误差**：存在系统性错误（inclusion 误判为 condition、可恢复归零误判为 exclusion），可能导致过度约束。
4. **参数值探索不足**：D3 测试序列的调用参数由 LLM 提取而非搜索，17.1% 的调用因守卫条件不满足被丢弃。
5. **单一标注者验证**：DCR 图提取质量验证仅由一位标注者完成。

## 研究启发与可借鉴点
1. **神经符号结合范式**：LLM 提取约束图 + 确定性图遍历生成测试序列的模式可迁移至其他代码生成评估场景。
2. **多预言机互补策略**：不同测试源（历史、合成、模糊）的组合可有效消除单源覆盖盲区。
3. **DCR 图作为智能合约抽象**：将合约生命周期建模为事件关系图的方法可用于合约验证、监控和文档生成。
4. **编译率与行为正确性的分离分析**：建立了编译成功不等于行为正确的证据，对评估框架设计有方法论启示。

## 关键术语表
- **DCR graph（Dynamic Condition Response 图）**：一种声明式过程模型，用事件及四种关系（Condition、Response、Inclusion、Exclusion）描述系统的合法调用顺序。
- **Differential fuzzing（差异模糊测试）**：同时对原始合约和生成合约施加模糊生成的输入，寻找行为不一致的测试用例。
- **Status match rate（状态匹配率）**：生成合约与原始合约在相同调用下返回相同成功/回退状态的比例。
- **Compile@k**：k 个生成样本中成功编译的样本比例，衡量代码生成的语法正确性。
- **Stub-and-complete**：删除函数体后由模型按顺序补全的代码生成协议，保证后续函数可见前序函数的实际实现。
- **Neuro-symbolic（神经符号）**：结合神经网络（LLM 提取 DCR 图）和符号计算（确定性图遍历）的混合方法。

## 可复现要素
- **数据集**：250 个合约及元数据已公开于 https://github.com/disi-unibo-nlp/sol-behave（MIT 许可证）

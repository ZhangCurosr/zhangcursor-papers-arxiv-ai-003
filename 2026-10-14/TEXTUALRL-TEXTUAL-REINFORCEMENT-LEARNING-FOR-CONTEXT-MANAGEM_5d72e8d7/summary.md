# 论文速读：TEXTUALRL: TEXTUAL REINFORCEMENT LEARNING FOR CONTEXT MANAGEMENT

## 一句话总结
本文提出 TextualRL，一种无梯度的强化学习框架，通过将同一任务下相同上下文的多个 rollout 组合作为策略批判的基本单元，利用收益结构生成并审查上下文编辑提案，从而在不更新模型参数的情况下优化 LLM agent 的共享文本上下文，提升其在多类基准上的任务准确率。

## 研究问题与动机
1. **固定模型 agent 的适应性问题**：LLM agent 的参数通常不可优化，需通过文本上下文（指令、程序）来引导行为，但如何将执行奖励转化为可复用且不会过度泛化的上下文更新仍具挑战。
2. **单条轨迹比较证据有限**：孤立轨迹难以提供充分的成败对比，任务特定的修复在跨任务共享上下文时可能过拟合或泛化不当。
3. **收益仅标识结果而非指令**：同一任务下所有 rollout 均成功或均失败时，缺乏内部对比信号，需要借助跨任务证据来识别值得保留的行为或构建修复假设。
4. **提案与证据需分离审查**：单一组的提案可能仅适用于特定条件，需通过跨组证据审查其内容适用性，避免无效或有害更新。

## 核心贡献（创新点）
1. **提出 TextualRL 框架**：将同任务 rollout 组作为策略批判的基本单元，实现基于收益的无梯度上下文优化闭环。 *与已有工作相比，本文不以模型参数为优化变量，而是直接编辑共享文本上下文。*
2. **设计 Groupwise Policy Critique**：根据 rollout 收益模式（混合、全成功、全失败）路由至不同分析策略，分别进行任务内对比、跨任务保留或修复假设构建，并分离返回编辑提案与轨迹证据卡。 *区别于 SkillOpt 等仅聚合提案的方法，本文通过收益模式感知区分分析路径，且证据与提案独立保存。*
3. **开发 Cross-Group Policy Update**：对合并后的提案进行跨组证据审查，根据支持、限制或矛盾关系保留、收窄或修改提案，再经留出验证集收益门控选择最终上下文更新。 *与 Trace2Skill 等直接合并局部教训的方法不同，本文引入独立的证据池进行全局适用性审查，避免局部成功导致的过度泛化。*

## 方法详解
1. **上下文空间策略优化**：目标函数为最大化期望任务收益 $J(C) = \mathbb{E}_{x \sim p_{task}} \mathbb{E}_{\tau \sim \pi_\theta(\cdot|x,C)}[R(\tau)]$，其中目标模型参数 $\theta$ 固定，仅优化文本上下文 $C$。
2. **Groupwise Policy Critique**：
   - **收益路由**：对每个任务 $x$ 收集 $K$ 个 rollout，计算成功数 $n_x$，按 $0<n_x<K$（混合）、$n_x=K$（全成功）、$n_x=0$（全失败）路由至不同分析组。
   - **混合收益分析**：对单一任务，对比成功与失败 rollout 的最早行为分歧，提出至多一条原子修复或保留规则。
   - **全成功/全失败跨任务分析**：将同类任务块分组（每批至少两个不同任务），识别共享的值得保留的行为或故障机制，提出保留或修复假设。
   - **提案与证据分离**：每个分析组返回编辑提案 $P_g$ 和证据卡 $E_g$（记录观察到的条件、行为、效应及引用），两者独立汇聚为 $P_t$ 和 $E_t$。
3. **Cross-Group Policy Update**：
   - **提案合并与审查**：层次化合并提案以消除冗余和冲突；随后用 $C_t$ 和 $E_t$ 审查每个合并提案，比对相关观察，决定保留、收窄（添加可观察条件）或修改内容。
   - **文本补丁构建**：每个审查后提案指定文本操作（追加、插入、替换、删除），按优化器排名选取至多 $L_t$ 条编辑（编辑预算余弦衰减），移除依赖执行时不可用信息的编辑，形成补丁 $\Delta C_t$，应用得候选上下文 $C_t' = C_t + \Delta C_t$。
   - **收益门控选择**：在留出验证集 $\mathcal{V}$ 上评估 $C_t'$，若验证成功率 $\widehat{V}(C_t')$ 高于当前参考分 $s_t$，则接受更新并刷新参考分，否则保留原上下文。
4. **epoch 内反馈**：验证后共享缓冲池记录 rollout 失败模式及被拒编辑组合，供同 epoch 后续批判调用参考，避免重复无效提案。

## 实验与结果
- **数据集**：六个 benchmark，包括 SearchQA、Spreadsheet、OfficeQA、DocVQA、LiveMath、ALFWorld，使用 SkillOpt 发布的划分（训练/验证/测试集见附录 Table 8）。
- **评估基线**：Base Model、Human skill、LLM skill、Trace2Skill、TextGrad、GEPA、SkillOpt。
- **主要结果**（Table 1）：
  - 在五个目标模型（GPT-5.5、GPT-5.4、Qwen3.5-4B、Qwen3.6-35B-A3B、Qwen3.8-27B）上，TextualRL 均获得最高六基准平均分。
  - 相对 Base Model，GPT-5.5 平均提升 **24.4** 个百分点（从 58.8% 到 83.2%），Qwen3.8-27B 平均提升 **15.3** 个百分点（从 55.6% 到 71.0%）。
  - 相对最强基线 SkillOpt，提升幅度为 0.9–3.2 个百分点。
  - 最佳单项提升：Qwen3.5-4B 在 ALFWorld 上从 30.6% 增至 82.1%，提升 **51.5** 个百分点。
- **消融实验**（Table 2，Qwen3.8-27B）：
  - 移除收益路由使平均分下降 1.5 个百分点；单 rollout（K=1）下降 2.5 个百分点。
  - 仅使用组内证据卡下降 1.2 个百分点；移除无提案证据卡下降 1.7 个百分点；禁用提案审查下降 2.7 个百分点。
- **其他实验**：
  - **稳定性**：三次独立运行平均 70.68%，标准差小（Table 3）。
  - **rollout 数量 K**：K=4 时达 71.0%，K=8 仅增 0.1 个百分点（Table 4）。
  - **Agent harness 泛化**：在 Codex 和 Claude Code 中均显著提升（Table 5）。
  - **技能迁移**：从 Qwen3.8-27B 学到的上下文迁移至较小模型时保持整体有效性（Table 6）。
  - **优化器选择**：用 Qwen3.8-27B 作为优化器略低于 GPT-5.5（整体 69.7% vs 71.0%），但仍有效（Table 7）。
  - **训练动态**：大部分测试提升发生在前两 epoch，后续验证得分与测试得分可能出现泛化差距（Figure 3）。

## 相关工作脉络
1. **Prompt/Context Optimization**：如 APE、DSPy、MIPRO 等自动优化提示或上下文，但未利用同一任务下多 rollout 的收益对比进行组级策略批判。
2. **Trajectory Feedback Learning**：Trace2Skill 从个体轨迹提取局部教训并层级合并；TextualRL 改为按收益模式分组批判，并将证据与提案分离以支持全局审查。
3. **Comparative Experience Learning**：ExpeL 和 ReasoningBank 从并行执行中提取可复用洞察；本文进一步将组内对比与跨任务证据整合，并通过编辑预算和验证门控控制更新幅度。
4. **Parameter-Space RL**：GRPO 等基于组相对奖励更新模型参数；本文将其思想迁移至上下文空间，保持目标模型冻结，实现无梯度文本编辑。
5. **Skill Evolution**：EvoSkill、SkillOpt 等通过失败轨迹提议技能并验证；本文强调收益模式感知的路由（混合/全成功/全失败）和跨组证据审查，避免过度泛化。
6. **Reflective Prompt Evolution**：GEPA 结合反思与进化搜索优化 prompt；本文不使用演化搜索，而是基于组级批判和证据驱动的提案修改。

## 局限性与未来方向
1. **对验证集的依赖**：更新接受度严格依赖留出验证集收益，若验证集过少或分布偏差，可能导致更新不稳定或泛化受限（训练动态部分指出验证与测试得分出现分化）。
2. **跨任务证据假设**：全成功/全失败分析假设跨任务存在共享行为或故障机制，但实际中可能因任务异质性而难以识别有效模式。
3. **编辑预算限制**：每步最多应用 $L_t$ 条编辑，可能无法充分表达复杂上下文修改，且编辑预算余弦衰减策略需调优。
4. **计算开销**：相比单轨迹方法，收集 $K$ 个 rollout 及并行批判调用增加训练 token 消耗（Table 9 显示迭代 token 为 SkillOpt 的 2–3 倍）。
5. **未来方向**：可探索动态 $K$ 值调度、更高效的证据压缩表示、跨 agent harness 的上下文迁移机制，以及将验证门控扩展至多任务联合评估。

## 研究启发与可借鉴点
1. **收益模式感知的组级分析**：根据 rollout 收益均匀性（混合/全成功/全失败）路由至不同批判策略，可推广至其他基于反馈的上下文优化场景。
2. **提案与证据分离设计**：将编辑提案和轨迹证据独立汇聚，使无提案的观察也能约束其他组的提案，增强更新的可解释性和鲁棒性。
3. **跨组证据审查机制**：在提案合并后引入独立证据池进行内容/适用性审查，避免局部成功导致的过度泛化，值得用于其他提示优化或技能演化框架。
4. **文本补丁与收益门控结合**：将候选上下文更新定义为有限编辑补丁，并通过留出验证收益进行步级选择，提供了清晰的优化闭环和早停机制。
5. **epoch 内历史反馈**：记录被拒编辑组合及失败模式供同 epoch 后续批判使用，可减少重复无效提案，加速收敛。

## 关键术语表
- **TextualRL**：一种无梯度的强化学习框架，通过优化共享文本上下文而非模型参数来提升固定 LLM agent 的任务表现。
- **Groupwise Policy Critique**：根据同一任务 rollout 的收益模式（混合/全成功/全失败）分组，进行任务内对比或跨任务保留/修复假设构建，并分离返回编辑提案与轨迹证据卡。
- **Cross-Group Policy Update**：对合并后的编辑提案进行跨组证据审查，根据支持、限制或矛盾关系决定保留、收窄或修改，再通过验证收益门控选择最终上下文更新。
- **Evidence Card**：记录可观察的条件、行为、效应及支持引用的轨迹卡片，独立于编辑提案保存，用于后续审查。
- **Outcome Routing**：基于任务 rollout 成功数 $n_x$ 将分析组路由至混合、全成功或全失败处理流程。
- **Bounded Textual Patch**：由至多 $L_t$ 条文本编辑操作构成的上下文修改集合，每次更新视为对原上下文的有界修改。
- **Held-out Validation Gate**：使用留出验证集收益评估候选上下文，仅当收益高于当前参考分时才接受更新。
- **Within-epoch History**：同 epoch 内记录的 rollout 失败模式及被拒编辑组合，供后续批判调用以减少重复提案。

## 可复现要素
- **数据集**：六个 benchmark（SearchQA、Spreadsheet、OfficeQA、DocVQA、LiveMath、ALFWorld）使用 SkillOpt 发布的划分，公开可用。
- **代码**：已开源，见 https://github.com/ECNU-ICALK/TextualRL。
- **权重**：目标模型为固定商业/开源模型（GPT-5.5、GPT-5.4、Qwen3.5-4B、Qwen3.6-35B-A3B、Qwen3.8-27B），未提供自定义权重；优化器默认使用 GPT-5.5。
- **关键超参**：每任务 rollout 数 K=4，训练 epoch 数 4，batch 大小 40 任务（共 160 轨迹），批判/合并 minibatch 大小 8，编辑预算 $L_t$ 余弦衰减从 4 至 2，温度 0.7（训练 rollout），0（验证/测试），随机种子 42。

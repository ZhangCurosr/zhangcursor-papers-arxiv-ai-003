# 论文速读：What-Coding-Agents-Leave-Unsaid-Measuring-Task-State-Gaps-Be

## 一句话总结
本文提出 CTXGAP，一种用于量化编码 agent 在例行用户报告中遗漏多少任务状态信息的配对视角测量基准；核心发现是 agent 对任务的按需可回答率达 93.6%，但仅凭累积报告只能恢复 52.0% 的任务状态（与完整执行上下文相差 40.7 个百分点），且该差距在已修复任务、监督相关状态及跨 harness 场景中均持续存在。

## 研究问题与动机
- **报告渠道的信息衰减问题**：人类监督者依赖 agent 的例行报告评估进展与风险，但 agent 可能省略失败尝试、变通方案或未解决风险，导致监督者无法察觉本应关注的异常事件。
- **现有评测缺乏"报告可恢复性"维度**：SWE-bench 等基准衡量任务结果成功率，但不反映 agent 通过报告向监督者传递了多少可操作的任务状态信息。
- **"成功完成≠可监督"**：一个 agent 可以在最终修复后回答所有执行相关问题（按需 93.6%），但其累积报告却不足以支撑监督者主动发起提问——成功性与可监督性是分离的。
- **终端可见性 ≠ 报告质量**：即使给予完整的 terminal scrollback（73.6%），仍距完整上下文（92.7%）有 19.1 点差距，说明问题不仅是"是否可见"，更是"如何报告"。

## 核心贡献（创新点）
- **提出"任务状态可恢复性"（task-state recoverability）作为新评估维度**：与任务成功率、按需可回答性严格分离，首次将例行报告的信息传递能力作为独立评测目标。
- **构建配对视角测量方法**：在同一批执行 grounding 探针上，分别评估从累积报告（U）、完整终端回滚（V）和完整执行上下文（T）视角的信息可恢复性，直接量化 $Gap_{view} = Acc(T) - Acc(U)$。
- **发现系统性报告缺口及其解剖结构**：主样本 37 任务 4,799 探针，$Gap_{view} = 40.7$ pp；30 个已修复任务的最终检查点仍保持 34.8 pp 差距；人工标注表明最大未恢复类别是"提及但支持不足"（55.4%~59.2%），而非完全未提及。
- **系统性有效性检验**：交叉 harness（Claude Code / Pi / DSH）、独立 DeepSeek 执行与独立 DeepSeek 测量管道三条路径均复现正差距，证明发现的稳健性。
- **证明上下文感知改写可有效缩小报告缺口**：在匹配总报告长度的条件下，基于完整执行上下文的自然改写和定向改写均将可恢复性提升约 8.3~8.5 个百分点，且定向改写未显示出显著优于自然改写的优势。

## 方法详解
- **任务与轨迹定义**：从 SWE-bench Verified 的 76 个 issue 中选取 37 个代表性任务，每 issue 选一条执行轨迹，设置 4 个检查点（k1=调查不修改；k2=实现修复；k3=运行测试并报告；k4=评估剩余风险）。
- **原子（Atom）提取**：用 HY4-preview 从每个检查点的执行记录中提取任务状态原子，每个原子标注类别（failure/progress/risk/decision 等 10 类）和重要性级别（1–3），仅保留重要性 ≥ 2 的原子。
- **探针（Probe）生成**：为每个采样原子生成一个问题及参考参考答案，通过有效性过滤器保留 4,799 条"全上下文可部分恢复且非仅从任务描述可完全回答"的探针。
- **三类视角对比**：
  - $U_k$（报告视角）：累积用户指令 + agent 例行报告；
  - $V_k$（终端回滚）：$U_k$ + 默认可见的终端滚动输出；
  - $T_{full}$（完整上下文）：$V_k$ + 推理块、工具调用、工具输出等全部记录。
- **加权评分**：按类别赋予逆采样权重 $w_i = N_{rkc} / n_{rkc}$，得分取 full/partial/none（1/0.5/0），加权均值即准确率；指标 $Gap_{view} = Acc(T) - Acc(U)$，$Gap_{actor} = Acc(A) - Acc(U)$。
- **置信区间**：主估计采用 10,000 次 issue-clustered percentile bootstrap；跨 harness 比较使用 per-issue Student t 区间（df=11）。
- **辅助检验**：人工mention/support标注（195个分层原子，$\kappa=0.632/0.638$）、跨模型探针/观察者因子实验（HY4 vs DeepSeek）、独立 DeepSeek 端到端测量管道复现。

## 实验与结果
- **主样本**（37 任务，4,799 探针）：$Acc(U)=52.0\%$，$Acc(T)=92.7\%$，$Gap_{view}=40.7$ pp（95% CI [37.3, 43.8]）；actor 自回答 $Acc(A)=93.6\%$。
- **已修复任务终检点**（30 任务，1,172 探针）：$Acc(U)=57.1\%$，$Acc(T)=91.9\%$，$Gap_{view}=34.8$ pp（95% CI [28.2, 41.3]），28/30 任务差距为正。
- **终端回滚效应**：$Acc(V)=73.6\%$，较报告提升 21.5 pp，但仍落后完整上下文 19.1 pp；只读结构化摘要（3,015字符）仅恢复 45.2%。
- **监督相关状态**：HY4 标注的决策相关探针 $Gap_{view}=35.3$ pp，DeepSeek 标注为 36.4 pp，双方共同认定相关子集为 36.1 pp。
- **提及≠可恢复**：人工标注中"提及但支持不足"占未恢复质量的 55.4%/59.2%；仅在报告中添加提及不产生可检测增益（$\Delta=-0.002$, CI [-0.027, 0.025]）；添加参考引导的前置证据可提升 18.9 pp。
- **报告改写**：在匹配总报告长度下，上下文感知自然改写提升 8.3 pp，定向改写提升 8.5 pp，两者无显著差异（$C-B=+0.20$ pp, CI [-1.48, 1.78]）。
- **跨 harness**（12 共享 issue）：Claude Code $Gap=40.7$ pp，Pi $Gap=39.0$ pp，DSH $Gap=49.0$ pp，均显著为正。
- **独立 DeepSeek 执行**（DSH harness）：DeepSeek-v4-flash 独立生成轨迹的 $Gap=52.7$ pp，与 HY4 的 52.2 pp 一致。
- **独立 DeepSeek 测量管道**（原 37 轨迹）：重跑全链路测量得 $Gap=39.8$ pp（95% CI [34.8, 45.6]），与 HY4 的 40.7 pp 高度一致。

## 相关工作脉络
- **Kraishan & Jitkajornwanich (2026)**：分析 5,851 个 agent 会话中行动如何在自报告中呈现；本文延伸至"报告能回答多少任务状态问题"，聚焦可监督性而非仅动作提及率。
- **MED-OMIT (Schumacher et al., 2025)**：将医学摘要中的缺失事实与下游决策损失关联；本文在编码场景中使用探针式问答替代决策模拟，测量维度更细粒度。
- **QAEval / QuestEval (Deutsch et al., 2021; Scialom et al., 2021)**：用问答评估摘要内容质量；本文借用 QA 作为测量工具而非提出新指标，核心在于配对视角的差异比较而非单视角绝对分。
- **FActScore (Min et al., 2023)**：评估原子事实支持精度；本文在此基础上增加"提及 vs. 充分支持"的人工地面标注分层，区分字面提及与信息充分性。
- **SWE-bench (Jimenez et al., 2024)**：衡量 issue 解决结果；本文明确区分任务成功与报告可恢复性，指出通过 SWE-bench 的任务仍可能存在大幅信息遗漏。
- **AgentLens (Podivilov et al., 2026)**：审查 agent 轨迹与通信；本文提供可自动化的定量测量框架，而非仅做定性轨迹审查。

## 局限性与未来方向
- **模型依赖性**：主要管道使用 HY4-preview 进行原子提取、探针生成、观察和评分，可能偏向执行底层细节；尽管跨模型检验支持稳健性，但尚未使用纯人工标注验证。
- **干预的外推限制**：报告改写实验使用完整执行上下文作为改写依据（反事实场景），不是 agent 自主报告策略的效果；模拟监督实验仅测量指令变化，未测量实际代码结果改进。
- **样本代表性**：37 个任务是有意选择而非随机抽样，偏向较简单的 SWE-bench Verified 任务（<15分钟难度占 40.5%，高于全量 23.7%）。
- **公开数据集不含推理内容**：原始 $T_{full}$ 含私有推理，公开发布版 $T_{public}$ 不等于原始输入，限制了外部研究的直接复现。
- **未来方向**：需要人类监督者参与的实地研究；探索自主的、预算受限的 agent 报告策略优化；将测量扩展到非 SWE 任务（如 research agent、数据分析 agent）。

## 研究启发与可借鉴点
- **配对视角测量范式可直接迁移**：同一探针在两种信息视图下对比，避免了单一视角评估的偏差，可作为 agent 通信质量评测的通用模板。
- **"提及≠充分支持"的区分具有重要方法论价值**：本报告证明了仅统计"是否提到"会严重高估报告质量，建议在后续工作中增加证据充分性（sufficiency）标注层。
- **上下文感知改写作为强 baseline**：在匹配总长度条件下，利用完整执行上下文进行自然语言改写可稳定提升约 8 个百分点的报告可恢复性，可作为后续报告格式优化的下界基准。
- **跨 harness/跨模型验证设计值得借鉴**：独立执行+独立测量两条路径同时验证，能有效区分模型依赖与现象真实性，建议在新 benchmark 中同样采用。
- **可与本团队方向结合**：若团队研究 agent 自我反思、报告生成策略或人机协作监督界面，CTXGAP 提供的配对探针框架可直接用于评估不同报告格式/频率/结构的可恢复性收益。

## 关键术语表
- **CTXGAP**：本文提出的配对视角测量基准，量化编码 agent 累积报告与完整执行上下文之间在任务状态可恢复性上的差距。
- **Atom（原子）**：从执行记录中提取的、带有类别和重要性级别的可验证事实命题，构成探针的基础单元。
- **Probe（探针）**：基于原子生成的问答对，用于从不同视角（报告/完整上下文）测试特定任务状态信息的可恢复性。
- **Gap$_{view}$**：主要评估指标，定义为 $Acc(T_{full}) - Acc(U)$，即完整上下文视角与报告视角的加权准确率之差。
- **Gap$_{actor}$**：辅助指标，定义为 $Acc(A) - Acc(U)$，衡量 agent 自身在被隔离 forks 下自回答相对于报告视角的优势。
- **Reading Ladder（阅读阶梯）**：从仅报告（U）逐步叠加叙述、执行头、工具输出、终端回滚（V）直至完整上下文（$T_{full}$）的多种视角集合。
- **mentioned but insufficient**：人工标注分类，指报告中提及某状态但未提供足够证据支撑完整回答问题，是未恢复信息中占比最大的类别。
- **SWE-bench Verified**：包含隐藏测试集的 GitHub issue 解决基准，本文选用其 37 个子集作为任务来源。

- **代码/权重**：Benchmark 和代码开源：https://github.com/Kaguraaaaaa/Ctxgap；包含数值复现脚本 reproduce_all.py 和模型调用评估器 evaluate.py。

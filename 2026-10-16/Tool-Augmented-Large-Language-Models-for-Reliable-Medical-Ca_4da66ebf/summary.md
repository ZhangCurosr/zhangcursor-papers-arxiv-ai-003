# 论文速读：Tool-Augmented-Large-Language-Models-for-Reliable-Medical-Ca

## 一句话总结
本文提出了一种工具增强型大语言模型框架，通过将医疗计算器的规则检索、可执行代码合成与验证、模式约束参数提取、确定性执行相解耦，从自由文本患者病历中实现可靠的医疗计算。在修正版 MedCalc-Bench Verified v1.0.7 上达到 86.73% 最终答案准确率，显著优于直接提示和纯 SFT 基线。

## 研究问题与动机
- **医疗计算任务的独特挑战**：医疗计算器需从自由文本中提取多种变量（数值、类别、布尔、日期、时间间隔、单位），并精确应用公式、评分规则、边界条件和输出格式；任一遗漏或误解都会改变最终结果。
- **纯 LLM 直接提示不可靠**：公式回忆、参数提取、算术推理和输出格式化被耦合在单一生成步骤中，公式幻觉或微小算术错误会无声地污染最终答案且难以定位故障来源。
- **现有工具增强方法的局限**：多数方法依赖固定的手工实现计算器库，覆盖范围有限；参数提取与工具调用仍在同一推理循环中，难以区分临床理解错误与工具实现/输出格式化错误。
- **MedCalc-Bench 原始版本的评估问题**：审计发现原始 MedCalc-Bench 中大量标签存在错误、歧义或不可计算，需使用经过医生监督修正的 Verified 版本进行公平评估。

## 核心贡献（创新点）
- **提出解耦架构**：将规则检索、可执行工具合成与验证、模式约束参数提取和确定性工具执行分离，有效缓解公式幻觉和算术错误，并支持预定义工具库之外的计算器构建。
- **迭代式工具合成与执行验证修复**：工具由检索到的规则证据生成，在 8 个同计算器训练示例上验证，执行失败/输出不匹配反馈给工具生成模型进行最多 4 轮修复，确保工具忠实实现计算器规则。
- **模式约束的专用参数提取模型**：针对高频提取任务微调轻量 Qwen3-8B 模型，利用计算器特定模式（328 个字段覆盖）和贪心选择的多示例进行 Few-shot 提取，降低计算成本并支持本地部署。
- **建立标准化评估基线**：使用修正版 MedCalc-Bench Verified v1.0.7 的统一数据划分和官方指标，对比提示基线、多种工具生成系统和提取模型，避免跨基准版本的聚合比较偏差。

## 方法详解
方法分为三个阶段，对应以下公式化表达：

**(1) 基于规则的计算器规格检索**
输入问题 $q$，系统检索 MDCalc 等资源找到目标计算器 $c$，通过规则策展 LLM 将其结构化：
$$r_c = \{\text{name}, \text{inputs}, \text{formula}, \text{conditions}, \text{output}\}$$
同时生成参数模式 $S_c$，定义所有必需输入的值的类型、允许单位、允许的类别取值。规格存储在内存中以供复用。

**(2) 可执行计算器工具合成与验证**
工具编写 LLM（GPT-5.5）根据 $r_c$ 和 $S_c$ 生成 Python 函数 $\tau_c = \text{calc}(z)$，实现公式/评分逻辑、条件分支、单位换算、边界情况和舍入规则。工具通过以下迭代流程验证：
- 从训练集中随机抽取 8 个同计算器示例进行测试
- 返回运行时失败、缺失字段错误、输出不匹配信息
- 最多进行 4 轮验证与修复
验证后工具被缓存复用。

**(3) 模式约束参数提取与工具执行**
每个患者病历 $n$，系统先检索 $k=3$ 个同计算器示例 $K_c$（通过贪心选择覆盖未表示的必需字段），将 $n, q, c, K_c, S_c$ 输入微调后的提取模型（Qwen3-8B-SFT），输出受限 JSON：
$$z = \{s_1 : v_1, \ldots, s_m : v_m\}$$
最终通过工具执行 $y = \text{Execute}(\tau_c, z) = \text{calc}(z)$ 得到确定性结果，LLM 不再参与公式应用或算术运算。

## 实验与结果
- **数据集**：MedCalc-Bench Verified v1.0.7，包含 55 个医疗计算器，10,538 训练实例，1,100 测试实例。
- **评估指标**：最终答案准确率（Final-answer accuracy）、参数匹配率（PMR）、工具级准确率（Tool-level accuracy）。
- **实验配置**：工具生成使用 GPT-5.5，参数提取使用 Qwen3-8B-SFT（LoRA rank=16, alpha=32, dropout=0.05, lr=5×10⁻⁵, epochs=5, batch size=8, max seq len=8192）。
- **主要结果**：
  - 本文方法达到 **86.73%** 最终答案准确率，参数匹配率 **97.47%**
  - 超越 One-shot prompting（62.73%，+24.0pp）和 SFT-only（69.46%，+17.27pp）
  - 超越外部报告的 Open-book guided prompting（82.00%）、Code agent（86.24%）
- **工具质量影响**：Retrieval + Repair + GPT-5.5 达到工具级准确率 94.91%；移除检索和修复使工具级准确率下降超过 10pp。
- **消融结果**：移除工具（No tool）→ -17.27pp；移除模式/Few-shot（No schema/few-shot）→ -7.55pp；移除提取模型 SFT（No extractor SFT）→ -3.00pp。
- **推理效率**：1,100 例测试总耗时约 47-48 分钟，平均每例约 2.6 秒（排除工具构建时间）。

## 相关工作脉络
- **MedRaC [23]**：将医疗计算分解为公式选择、实体提取、计算和答案检查，但检索和 Python 执行仍在每例推理流水线中进行，公式选择、代码执行和答案格式化错误仍可传播到最终答案；本文通过工具缓存和模式约束提取降低了这种耦合。
- **MedCalc-R1 [24]**：结合 SFT 与知识引导的 GRPO 奖励，计算器更新或答案合同变更需重新训练；本文工具方法无需重新训练即可适应新计算器。
- **RiskAgent [26] / MeNTi [27] / MedMCP Calc [28]**：通过检索、嵌套工具调用或 MCP 协议连接 Agent 与计算器，提升数值稳定性但仍假设目标计算器已手工实现为工具；本文从规则证据自动生成可执行工具。
- **Toolformer [21] / PAL [18] / Program-of-Thoughts [19]**：通用工具学习/程序辅助推理方法，未针对医疗计算器复杂的边界条件、单位换算和输出合同进行专门设计；本文聚焦医疗领域的特定需求和验证机制。
- **MedCalc-Bench 审计研究 [13][14]**：指出原始基准标签错误和开放书籍评估的重要性；本文采用修正版 Verified v1.0.7 并使用统一数据划分和官方指标进行公平比较。

## 局限性与未来方向
- **提取错误**：系统必须在隐含信息推断（如药物相关病情、否定、时间性）上做得更好，当前在临床语义判断类计算器上仍存在困难。
- **工具生成错误**：当参数容易识别但正确评估依赖于特定公式分支、归一化规则、舍入程序、单位惯例、日期边界或答案表示时，工具仍可能出错（如 Case C 中 cortisone 子串匹配顺序错误）。
- **泛化能力未验证**：评估仅限于工具构建期间使用的 55 个计算器，对新计算器的泛化和临床部署能力尚未测试。
- **未来方向**：通过强化学习奖励准确提取关键字段和正确最终计算；智能 Agent 验证不确定参数、在边界案例上测试生成工具、在关键信息缺失时请求澄清。

## 研究启发与可借鉴点
- **解耦架构设计**：将"语言理解"（参数提取）与"规则执行"（工具计算）分离的思路可迁移至其他需要精确结构化输出的领域（如财务计算、科学实验数据处理），降低 LLM 在数值任务上的幻觉风险。
- **执行反馈驱动的工具验证与修复**：基于少量测试示例的执行结果迭代修复生成代码的方法，适用于任何需要生成可执行代码的任务（如 SQL 生成、数据处理脚本），提升代码可靠性的同时减少人工审查成本。
- **模式约束 Few-shot 提取策略**：基于计算器模式贪心选择多示例以覆盖所有必需字段的策略，可作为结构化信息提取任务的通用范式，尤其适用于字段多样、类型复杂的场景。
- **工具缓存复用机制**：同一计算器只需构建一次工具并缓存，后续病例复用，大幅降低推理开销——该设计对具有有限工具库的高频应用场景（如企业级计算系统）具有实用价值。
- **多层评估指标设计**：同时报告最终答案准确率、参数匹配率和工具级准确率，可从不同粒度定位错误来源，这一评估策略值得在其他分解式任务中借鉴。

## 关键术语表
- **MedCalc-Bench Verified**：经过医生监督审计修正的 MedCalc-Bench 版本，包含修订标签、答案合同、计算器规格和可执行参考实现。
- **Parameter Matching Rate (PMR)**：提取模型正确匹配的必需计算器参数占全部必需参数的比例，用于评估参数提取质量。
- **Tool-level Accuracy**：使用金标准参数评估生成计算器工具的正确率，用于隔离工具实现质量与参数提取质量。
- **Schema-constrained Extraction**：基于计算器特定参数模式（类型、单位、类别取值）约束的结构化信息提取方法。
- **Retrieval-and-Repair**：先检索规则证据生成工具，再通过执行验证结果反馈进行迭代修复的工具合成流程。
- **Cockcroft-Gault**：用于估算肌酐清除率的经典肾脏功能计算公式，本文成功案例研究中的示例计算器。
- **HEART Score**：用于评估疑似急性冠状动脉综合征患者风险的综合评分系统，包含多个布尔和类别变量。
- **MedMCP Calc**：基于 Model Context Protocol (MCP) 集成医疗计算器的基准测试方法。

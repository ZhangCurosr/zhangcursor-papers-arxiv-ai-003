# 论文速读：TriGeoBench: A Multimodal Mathematical Geometry Benchmark with Figures and TikZ

## 一句话总结
本文构建了 TriGeoBench，一个基于中国初高中数学试题的**几何中心多模态基准**。它采用 **{问题–答案对(LATEX)，光栅图像，TikZ 代码}** 三元组统一表示几何题，以评估多模态大语言模型（MLLMs）在精细几何结构与图文对齐方面的推理能力。

## 研究问题与动机
1.  **现有基准缺乏精确结构表示**：多数数学基准使用光栅化图像，无法显式保留几何拓扑、关系和符号标注，难以判断模型是在进行真正的几何结构推理，还是依赖浅层视觉模式。
2.  **几何知识领域与问题格式覆盖有限**：已有数据集往往只覆盖几何子集，平面与立体几何涉及不广，问题类型（如选择、填空、证明、解答）单一，评估较为粗略。
3.  **统一且可执行的几何表示缺失**：现有工作多停留在光栅图或特定任务标注，缺乏既便于机器处理又保持人类可读性、可编译执行的几何结构表示。
4.  **评估几何特有挑战的需求**：几何推理要求将文本条件、图形视觉信息和符号逻辑紧密融合，现有基准在此方面的评测深度和广度不足。

## 核心贡献（创新点）
1.  **提出 TriGeoBench 基准**：从真实中国中学数学试题出发，构建了包含 7000 个问题–答案对和 12235 个几何图的基准，覆盖平面、立体、解析几何、函数、向量五大领域及四种答题格式。*与已有工作本质区别在于其来源的真实教学分布和全面的几何知识覆盖。*
2.  **采用 {LATEX, 图像, TikZ} 三元组统一表示**：每个实例均由 LATEX 存储的文本、RGB 图像和可编辑的 TikZ 代码组成。TikZ 代码显式保留了拓扑结构、符号标注和几何关系。*区别于仅使用光栅图或固定格式标注的工作，提供了可编译的语义化结构表示。*
3.  **提供统一的评测探针与广泛评估**：设计了图像到 TikZ 生成和 multimodal 数学推理两大统一评测协议，并对多款主流开源与闭源 MLLMs 进行了系统性评估，揭示了当前模型在精细结构理解和图文对齐上的持久性挑战。*系统性地评估了通用 MLLM 在此新基准上的表现，并引入了人工评估来弥补自动指标的不足。*

## 方法详解
1.  **数据收集与预处理**：来源为公开的中文初中、高中数学考试卷及解析。经过标准化数学符号、去除无关元数据、近重复过滤、与公共基准比对以减少泄漏等步骤。
2.  **三阶段人工标注流程**：
    *   **收集与预处理**：提取含图几何题，分割为题干、答案、解析、图像等结构化组件。
    *   **手动转换为 LATEX 和 TikZ**：标注员根据原图，手动转录 LATEX 并创作对应的 TikZ 代码，需保持数学符号、几何拓扑、隐藏边、标签和相对位置准确。通过编译对比迭代修正。
    *   **独立人工验证**：另一位审核员检查 LATEX 语义正确性和 TikZ 可编译性、视觉保真度及结构一致性，发现错误则退回修改。
3.  **分层标注体系**：依据知识领域（平面、立体等）、问题类型（选择、填空等）、以及由答案长度（难度）和 TikZ 代码长度（图形复杂度）初始聚类后经专家校准的等级，对数据进行多维度分层。
4.  **评测协议**：
    *   **图像到 TikZ 任务**：评估模型生成可编译且符合原图几何结构的 TikZ 代码的能力。
    *   **多模态数学推理任务**：评估模型结合不同输入模态进行推理和求解的能力。
5.  **评估指标**：
    *   生成准确性 (Gen Acc)：代码成功编译的比例。
    *   图像指标 (SSIM, KID, CLIP, DINO)：评估渲染图与参考图的视觉一致性。
    *   TikZ 指标 (cBLEU, Token F1, Tree Edit Distance)：评估生成代码与参考代码的词法、token 级和树结构相似度。
    *   人工评估准确性 (Human Acc)：由人工判断渲染图是否在视觉和数学意义上忠实于原图。
    *   推理准确率：采用 LLM-as-Judge 方法，与参考解答比对后得分。

## 实验与结果
*   **评测模型**：8 个开源 MLLM 家族（如 Qwen3-VL, GLM-4.5V, Llama-3.2-Vision, InternVL3 等）和 4 个闭源模型（Gemini-3.1-Pro, GPT-5.4, Seed-2.0-Pro, Qwen3.5-Plus）。
*   **评测集**：从 TriGeoBench 中按难度分层采样 1000 个样本（500 Easy, 300 Medium, 200 Hard）。
*   **图像到 TikZ 结果 (Table 2)**：
    *   **最强结果**：**Gemini-3.1-Pro** 在生成准确性 (96.1%) 和人工评估准确性 (73.7%) 上均达到最佳。
    *   **关键发现**：GPT-5.4 生成准确性高 (95.6%) 但人工评估准确性较低 (43.9%)，表明自动指标不能完全反映几何正确性。闭源模型整体优于开源模型，尤其在 Medium 和 Hard 难度上差距显著。
*   **小模型微调结果 (Table 3)**：LoRA 微调后，各模型的 Gen Acc 和 TikZ Metrics (cBLEU, MTE, TED) 有显著提升，但 Gen Acc 并非全部提高（如 Qwen3-VL-2B/4B），且图像指标提升不一致。
*   **多模态推理结果 (Table 4)**：
    *   **最强结果**：**Seed-2.0-Pro** 在 Text-only 设置下取得 81.76% 的最高准确率。
    *   **TikZ 的 Oracle 诊断效果 (Figure 4)**：引入人工编写的参考 TikZ 代码 (Text+TikZ) 后，所有模型的推理准确率均有提升（如 Seed-2.0-Pro 从 81.76% 提升至 84.88%），但在 Text+Figure+TikZ 下并非总是最优，说明当前模型在融合冗余的视觉和符号输入方面仍有困难。
*   **探索性跨基准检查 (Table 5)**：在 MathVerse, MATH-Vision, VisioMath 上加入 Text+TikZ 后，Seed-2.0-Pro 的准确率分别提升 +13, +9, +3 个百分点。

## 相关工作脉络
1.  **数学推理基准 (MATH, MathVista, Math-Verse)**：从纯文本推理发展到多模态评估，但多依赖光栅图，缺乏可编译的结构化表示。TriGeoBench 通过 TikZ 三元组弥补了这一空白。
2.  **几何专用基准 (GeoEval, SOLIDGEO, VisioMath)**：关注几何理解，但通常仍基于光栅图或特定标注，知识领域和表示形式不如 TriGeoBench 全面和结构化。
3.  **早期几何问答与程序表示 (Geometry3K, GeoQA 系列, PGPS9K, UniGeo)**：引入了形式语言或程序标注，但大多数保留了光栅图，且并非所有表示都是可编辑、可编译的通用格式（如 TikZ）。
4.  **图形程序合成基准 (DeTikZify, GeoGramBench, DaTikZ, SciTikZ, InternSVG)**：侧重于从图像生成图形程序（如 TikZ, SVG），但主要目标是图形重建而非数学推理评估。TriGeoBench 将图形生成与结构感知的推理任务紧密结合。
5.  **多模态大模型评测**：本文在广泛的通用 MLLMs 上评估，揭示了其在几何这一特定数学子领域的能力边界，丰富了 MLLM 评测的图谱。

## 局限性与未来方向
1.  **数据集范围限制**：专注于中文初高中数学试题，评估分数混合了中文理解能力，可能难以直接迁移到其他语言或课程体系。
2.  **数据泄漏风险**：尽管进行了去重和比对，但由于无法获知闭源模型的训练数据，不能完全排除样本已存在于训练集中。
3.  **自动评估的局限**：不同的有效 TikZ 代码可能对应同一张图，导致代码级指标（如 cBLEU, TED）不能完全反映几何语义的正确性，仍需人工评估。
4.  **模态融合挑战**：实验表明，即使提供 Oracle 级别的 TikZ 代码，模型也无法始终最佳地融合多种模态信息，如何有效提升模型的几何结构理解和多模态融合能力仍是开放问题。
5.  **未来方向**：评估自动图像到 TikZ 转换流水线、开发针对此任务的专用模型、扩展数据集的覆盖范围（如更高难度、更多语言）、以及加强结构感知评测。

## 研究启发与可借鉴点
1.  **统一结构化表示的价值**：对于需要精确空间或结构理解的领域（如几何、科学图表、电路图），引入可编译、可编辑的程序化表示（如 TikZ, SVG, JSON Schema）作为评测和训练数据的一部分，能有效区分浅层模式匹配与真正的结构推理。
2.  **多阶段人工标注与验证流程**：对于高质量结构数据的构建，采用“采集预处理 -> 手动转换 -> 独立验证”的三阶段流程，并结合自动化编译检查与人工审核，是保证数据质量和一致性的可靠方法。
3.  **分层难度与复杂度标注**：利用辅助信号（如答案长度、代码长度）进行初始聚类，再经领域专家校准，可以有效构建具有梯度难度的评测基准，便于更细致地分析模型能力边界。
4.  **结合自动指标与人工评估**：在生成任务中，单一自动指标（尤其是词法重叠）往往不足，结合可编译性检查、视觉相似度、结构相似度以及必要的人工评估，能更全面地衡量生成质量。
5.  **利用 Oracle 辅助诊断**：通过提供理想的结构化输入（如参考 TikZ）作为 Oracle 实验，可以诊断模型在信息接收层面的潜力，以及区分模型的性能瓶颈是源于生成、理解还是融合。

## 关键术语表
*   **TikZ**：一种基于 LaTeX 的绘图宏包，用于创建精确的矢量图形，其代码可编译生成图形，能显式编码几何对象的坐标、关系和样式。
*   **Figure-Grounded Reasoning**：指推理过程必须基于图表中提供的、非装饰性的几何信息进行，图表信息与文本条件相互补充、共同用于解题。
*   **TikZ Triplet (三元组)**：TriGeoBench 中每个实例的统一表示形式，包含问题-答案对（LATEX）、几何图像（RGB）和对应的 TikZ 代码。
*   **Gen Acc (Generation Accuracy)**：图像到 TikZ 任务的评估指标，指模型生成的 TikZ 代码能够成功编译成图像的比例。
*   **Human Acc (Human Evaluation Accuracy)**：图像到 TikZ 任务的人工评估指标，由人工判断生成的图形在视觉和数学意义上是否忠实于原始图形。
*   **TikZ Metrics (cBLEU, MTE, TED)**：用于评估生成 TikZ 代码与参考代码相似度的指标，分别衡量词法重合度、token 级 F1 和语法树编辑距离。
*   **LLM-as-Judge**：使用大型语言模型作为裁判，根据预设的评分规则和参考解答，对模型的回答进行自动化评分的评测方法。
*   **Oracle Experiment**：在推理任务中直接使用人工编写和验证的参考 TikZ 代码作为输入，而非由模型从图像生成，用于诊断结构化信息对推理的上限增益。

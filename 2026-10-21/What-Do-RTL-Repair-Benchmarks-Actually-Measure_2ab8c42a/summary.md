# 论文速读：What-Do-RTL-Repair-Benchmarks-Actually-Measure

## 一句话总结
本文构建了 RTLRepairDataset（5,784 对训练数据）与 RTLRepairBench（459 个保留用例），并通过审计发现两个测量混淆问题：仿真与形式化验证评分在重置/首轮比较语义上显著分歧，以及正确输出可能源于规范重新生成而非对损坏 RTL 的实际修复，进而提出四项评估控制规范以提升可复现性。

## 研究问题与动机
1. **RTL 行为修复难以准确衡量**：候选 RTL 即使编译通过也可能与预期设计不一致，其得分受 oracle 合约与输入条件的双重影响。
2. **仿真与形式化验证结果可能相反**：已有基准（如 VerilogEval、RTLLM）依赖仿真匹配，但未充分考虑重置序列与首轮比较语义对评分的干扰。
3. **正确输出无法区分"修复"与"重新生成"**：模型输出的正确性不能证明其使用了提供的损坏 RTL，可能只是基于规范重新生成了等效代码。
4. **缺乏对测量混淆的显式审计**：现有工作聚焦生成与语法修复（如 RTLFixer、AutoChip），但未系统分析评估设置如何改变测得的行为修复效果。

## 核心贡献（创新点）
1. **构建并公开 RTLRepairDataset 与 RTLRepairBench**：提供 5,784 对配对训练数据与 459 个持有集用例，并通过工具门控分离语法失败与行为失败；与现有工作（VerilogEval、RTLLM）的本质区别在于引入了明确的 oracle 合约与行为/语法故障分类。
2. **实证识别两个测量混淆因素**：发现仿真与形式化等价评分对同一干预（提供规范）可能给出相反符号效应，且规范-only 恢复与规范条件修复的差异可达 8.5–18.3 个百分点；与已有基准的本质区别在于首次将此混淆显式量化。
3. **将审计发现转化为四项评估控制规范**：要求报告初始化/重置/首轮比较/未知值语义、披露 oracle 覆盖率与未决案例、引入规范-only 基线；其创新性在于将诊断协议嵌入基准评估流程，而非仅提供数据集。
4. **开源完整可复现基础设施**：包括基准、训练集、构造代码、 sanitized 聚合证据与 reproduction 材料（https://github.com/Evaaaz/RTLRepairBench）；相比仅有模型或数据的先前的工作（如 CRAFTRTL、CodeV），本文提供了端到端的审计工具链。

## 方法详解
1. **工具门控构造管线**：训练种子来自 MG-Verilog，保留集与去污染池使用 VerilogEval 与 RTLLM；每个 broken/fixed 对仅在其类别特异性门控确认注入故障时保留，确保数据集与基准使用不相交的源种子（1,895 vs 130 个种子，零重叠）。
2. **双层 Oracle 定义**：
   - **Tier S（仿真）**：使用 verilator 进行 lint，用 iverilog 对候选与 golden 模块运行 200 周期相同采样激励，逐周期比较输出；观察到的不匹配即为该 trace 下的 counterexample。
   - **Tier F（形式化等价）**：根据设计类型匹配合约——穷举组合检查（17 例）、声明的复位序列（60 例）或指定前导序列（8 例），随后在明确初始化和未知值语义下使用 Yosys SAT、ABC PDR 与 SMT 归纳进行等价证明。
3. **三臂消融实验（区分修复与重新生成）**：对 274 个挖掘出的模型失败案例，分别提供三种输入：(1) 损坏 RTL 无规范、(2) 损坏 RTL 带规范、(3) 仅规范；通过比较 (3) 与 (2) 的回收率差异（$\Delta_{c1}$）量化规范重新生成的潜在干扰。
4. **重置感知重评分**：应用双沿复位启发式方法对 Tier S 结果重新评分，发现几乎所有仿真-形式化分歧可由重置与首轮比较语义解释（79 个案例中 Tier-S-fail/Tier-F-proved 的 39 个案例全部被清除）。

## 实验与结果
- **数据集**：RTLRepairDataset 含 5,784 对训练数据；RTLRepairBench 含 459 个保留用例（374 个语法变异 + 85 个行为变异），包含 4 个训练中未见的语义操作符。
- **Oracle 敏感性实验（79 个案例，GPT-5.5）**：
  | 评分合约 | 诊断组 | +规范组 | 配对对比 |
  |---|---|---|---|
  | Tier S, cycles 0–199 | 60/79 (75.9%) | 51/79 (64.6%) | **-11.4 pp** |
  | Tier S, cycles 1–199 | 72/79 (91.1%) | 78/79 (98.7%) | **+7.6 pp** |
  | Tier S, reset-aware | 71/79 (89.9%) | 78/79 (98.7%) | **+8.9 pp** |
  | Tier F, per-design | 71/79 (89.9%) | 78/79 (98.7%) | **+8.9 pp** |
  - 跳过首轮比较使对比从 -11.4 反转为 +7.6；reset-aware 初始化与 Tier F 完全一致。
- **修复 vs 重新生成实验（274 个挖掘失败案例，6 模型）**：
  | 模型 | n | 无规范 | +规范 | 仅规范 | $\Delta_{c1}$ |
  |---|---|---|---|---|---|
  | GPT-5.5 | 260 | 57.3% | 81.5% | 76.9% | -4.6 pp |
  | Claude Opus 4.8 | 271 | 34.3% | 71.6% | 69.0% | -2.6 pp |
  | GPT-5.4-mini | 274 | 29.6% | 51.5% | 56.9% | +5.5 pp |
  | GPT-4.1 | 271 | 27.3% | 46.5% | 38.0% | -8.5 pp |
  | GPT-4o-mini | 274 | 19.0% | 39.1% | 41.2% | +2.2 pp |
  | Claude Opus 4.6 | 273 | 9.5% | 51.6% | 70.0% | **+18.3 pp** |
  - 最强提升：Claude Opus 4.6 的规范-only 比规范条件修复高 18.3 个百分点，表明其可能更多依赖规范而非损坏 RTL。
  - 全部模型在规范-only 条件下均优于无规范条件，但相对规范条件修复的差异方向不一致。

## 相关工作脉络
1. **RTLCoder / OriGen / CRAFTRTL / CodeV / VerilogDB**：聚焦规范到 RTL 的生成，本文补充了配对修复数据与行为修复评估。
2. **RTLFixer / OriGen self-reflection**：使用编译器反馈修复语法/编译失败，本文聚焦 lint-clean 的行为故障修复。
3. **AutoChip**：同时使用编译器与仿真反馈迭代修订，本文的 Tier S/Tier F 双层 oracle 提供了更细粒度的评估分离。
4. **VeriReason / CodeV-R1 / Wang et al.**：利用测试bench奖励或偏好改进功能生成，本文强调评估协议本身需要审计而非仅优化生成。
5. **VeriDebug / ARSP / VeriRAG**：分别针对对比学习调试、语义分区修复、DFT 合规修复，本文的独特定位是公开配对修复资源并审计测量混淆。
6. **VerilogEval / RTLLM**：已有基准依赖仿真匹配，本文指出其未报告重置/首轮语义，并提出规范-only 基线作为诊断工具。

## 局限性与未来方向
1. **发现具有描述性**：实验基于单一定向采样（greedy decoding）与历史模型快照，非随机重复采样。
2. **队列规模有限**：评估用例数量（79/274）限制统计效力，且案例在 112 个源任务间聚类，非独立重复。
3. **模型覆盖有限**：仅测试 6 个历史模型端点快照，未涵盖更广泛的模型生态。
4. **未来方向**：需要重复采样、更广模型阵容、更大规模与更多样化的 RTL 设计来验证发现的泛化性。

## 研究启发与可借鉴点
1. **规范-only 基线作为诊断工具**：可在任何生成/修复任务中引入"仅条件基线"臂，以检测模型是否真正利用输入而非依赖条件重新生成，适用于代码生成、硬件描述语言等场景。
2. **评估语义显式化**：重置序列、首轮比较、未知值传播等评估细节应作为基准的正式组成部分而非隐式假设，此思路可迁移至软件基准测试（如单元测试启动顺序、全局状态初始化）。
3. **双层验证架构**：Tier S（高效仿真）+ Tier F（严格形式化）的分层 oracle 设计可在资源受限场景下平衡覆盖率与严谨性，适用于安全关键代码验证。
4. **工具门控数据构造**：通过类别特异性门控（如 lint gate、simulation gate）筛选有效训练对的方法，可推广至其他需要精确故障-修复配对的领域。
5. **审计协议嵌入基准**：将测量混淆的审计转化为可执行的报告控制项（初始化语义、oracle 覆盖率、未决案例），为基准社区提供可复用的评估标准化模板。

## 关键术语表
**RTLRepairDataset**：包含 5,784 对 (broken, fixed) 训练数据的硬件描述语言修复数据集，源自主 MG-Verilog。
**RTLRepairBench**：包含 459 个保留用例（374 语法 + 85 行为变异）的评估基准，支持仿真与形式化等价验证。
**Tier S（仿真验证）**：基于 iverilog 的 200 周期采样仿真 oracle，逐周期比较候选与黄金模块输出。
**Tier F（形式化等价验证）**：基于 Yosys SAT、ABC PDR 与 SMT 归纳的形式化证明 oracle，支持穷举组合、复位序列与前导序列三种合约。
**$\Delta_{c1}$**：规范-only 恢复率减去规范条件修复率的差值，用于量化规范重新生成的潜在干扰。
**Reset-aware 重评分**：应用双沿复位启发式方法对仿真结果重新评估，可消除由初始化语义导致的仿真-形式化分歧。
**Oracle 覆盖率**：成功获得确定裁决（pass/fail）的用例比例，未决案例指形式化验证无法得出结论的情况。
**Specification-only baseline**：仅提供设计规范而不提供损坏 RTL 的基线实验臂，用于诊断模型是否真正执行修复。

## 可复现要素
- **数据集**：RTLRepairDataset（5,784 对）与 RTLRepairBench（459 用例）已公开，GitHub: https://github.com/Evaaaz/RTLRepairBench
- **代码/工具**：工具门控构造管线、评估 harness（支持 verilator、iverilog、Yosys、ABC）已开源；训练文件已发布。
- **模型权重**：论文使用历史模型端点快照（GPT-5.5、Claude Opus 4.6/4.8、GPT-5.4-mini、GPT-4.1、GPT-4o-mini），未提供自定义模型权重；标注为"historical endpoint-output snapshots"而非不可变版本。
- **关键超参**：仿真周期数 200、输出预算 4,096 token、greedy decoding；论文未提及其他训练超参（因聚焦评估审计而非模型训练）。

# 论文速读：What-Does-Now-Mean-to-Your-Computer-Use-Agent-Stale-screenshots

## 一句话总结
本文首次系统性量化了计算机使用（computer-use）智能体在真实网页上的"计划点击过时"（stale click）风险，发现核心风险来自**页面加载**而非规划延迟，并提出一个基于像素比较的快速预检方法——在三分之一延迟内达到与顶级视觉语言模型相当的定位验证精度。

## 研究问题与动机
1. **既有认知偏差**：现有工作将风险归因于截图到点击之间的规划间隔（planning interval），建议压缩间隔或做像素复核；本文质疑这一前提假设。
2. **实际损失难以量化**：大多数 click-at-coordinate 的智能体会跳过浏览器自动化框架里的"元素可用后执行"守卫，但真实网页上这种跳过造成错误的频率从未被测量。
3. **感知手段选择无依据**：预检需要回答三种不同问题（目标仍在原位？被弹窗遮挡？上一操作是否成功？），但哪类感知适合哪类问题尚无直接对比。
4. **商业页加载行为未测**：智能体主要交互的商业预订/购买网站在截图后是否仍持续加载、何时加载停止，缺乏跨站点数据。

## 核心贡献（创新点）
1. **首次测量真实网页上计划点击过时的基线率**：31 个公共页面约 3,900 次追踪显示，完全加载页面 0.4%、页面刚打开首秒内 17%，风险集中发生在导航后的网络活跃期，推翻"规划延迟是主因"的普遍假设。
2. **像素比对 vs VLM 的直接对比评测**：同一组 4,608 个合成移动页面上的四问题，像素检查以 312 ms、4% 误报检出 82% 过时点击，而 Claude Opus 5.5（2.4 s、12% 误报）仅 83% 检出，首次给出"空间定位用像素、内容解读用小模型"的定量分界。
3. **盈亏公式（break-even formula）**：式 (1) 仅凭规划延迟 C、检查延迟 δ、召回 r、误报 f 即可预测单次检查是否值得，对留出数据 95% 的决策判断正确；式 (2) 支持两种检查之间的成本选择。
4. **开源预检基准生成器**：六个可配置移动页面、精确 6.5 s 计划间隔、基于 DOM 树打 ground truth、冻结阈值后再读标签，附全部先验假设注册记录与原始模型输出。

与已有工作的本质区别：PUSV（文献 [1]）和安全型 atomicity 检测（文献 [11]）对任何屏幕变化都报警，不适合普通网页；本文的像素检查通过排除自变化像素（旋转器、光标闪烁）并设置匹配 margin，把普通页的误报压到 0.5%（vs PUSV 发布版的 21%）。

## 方法详解
- **三问分类**：预检需在点击前回答（1）目标是否仍在计划位置附近？（2）是否有弹窗遮挡？（3）上一操作是否成功？前两问聚焦数百像素区域，第三问关注屏幕语义变更。
- **像素检查设计**：规划时拍摄两张间隔 200 ms 的截图，差异像素（动态 spinner、光标、ticker）从搜索中剔除；在原始位置 ±40 px 窗口内做模板匹配，要求最优匹配显著高于次优；另设覆盖检测和弹窗检测两个子测试；总耗时 312 ms（其中 200 ms 为两张截图间隔），无模型推理。
- **模型检查对照**：Qwen3-VL 2B/4B、SmolVLM2 2.2B、Florence-2 OCR、Claude Haiku 5.5、Claude Opus 5.5，均接收目标区域裁剪+当前全截图+自然语言问题；第 3 问额外输入动作前后两张截图与一句预期效果描述。
- **盈亏公式**：
  - 式 (1)：当 p > p* = (δ/C + f) / (r(k−1) + f) 时检查值得，k 为过时点击的代价（普通点击 k=2，不可逆操作 k=10）。
  - 式 (2)：比较两种检查 A/B 的边际收益与边际延迟/误报成本。
- **实验设置**：
  - RQ1 真实页：31 个允许自动化访问的公共页面（时钟、地震/天气地图、政府站等），三种起始状态（完全加载、滚动后、DOM-ready 首秒），每状态约 1,300 个追踪目标，跟踪 30 s。
  - RQ1 商业页：HTTP Archive 2026 年 10 月抓取，WebPageTest 桌面 Chrome 录制布局偏移与网络请求时序，65 个预订购买首页 + 3,028 个 .gov 首页 + 4,972 个电商软件站点样本。
  - RQ2/RQ3 基准：6 个合成移动页（表单、行情面板、新闻流、协作文档、平移地图、画板），Chromium 暂停时钟保证间隔精确 6.5 s；四类布局两调两留；4,608 个点击对 + 3,600 个动作结果对。
  - 10 个开源智能体规则复现：Anthropic CU、browser-use、OpenAI CUA、Stagehand v4、Skyvern、Agent S3、OpenHands、Playwright MCP、UI-TARS-desktop、magentic-ui，仅复现等待规则不执行端到端。

## 实验与结果
- **RQ1 页面加载是主因**：完全加载页 0.4%（0.5–30 s 不变）；DOM-ready 首秒 17%（95% CI 9.9–24.7 pp 差），之后稳定不再上升。等待规则中仅 Playwright 的 networkidle（500 ms 无请求，中位 1.24 s）将过时率压到 0.46%；固定 0.5/1 s 延迟、load 事件、layout stable 均停留在 2.5–3.1%。
- **10 个开源智能体的现状**：过时率 0.46%（Skyvern）–15.4%（OpenAI CUA，无等待）之间，8/10 超过 1% 先验阈值；"HTML 解析完立即截图"的两者均 >12%；"固定 1 s 延迟"的两者在 9–12%。
- **商业页加载更久**：预订购买首页在 3 s 封顶的 networkidle 后 52.3%（95% CI 40–65）仍在 6.5 s 内发生布局偏移，.gov 仅 7.8%（差 44.5 pp）；15.4% 在 DOM-ready 后 3 s 内未达 500 ms 静默（.gov 63.4%）。完全记录子集内 61% vs 26%（35.1 pp）仍显著。
- **RQ2 像素 vs 模型**：目标位置验证——像素 82% 召回 / 4% 误报 / 312 ms；Opus 83% / 12% / 2.4 s；Haiku 98% / 95%（几乎无效）；Qwen3-VL 4B 66% / 37%；2B/SmolVLM2 接近 0 召回。弹窗检测——像素 72% / 1%；Opus 100% / 7%；4B 95% / 14%。上一操作是否成功——4B 100% / 0%；Opus 100% / 0%；Haiku 几乎全报；Florence-2 OCR 89% / 0%。
- **RQ3 公式与活体回环**：式 (1) 对 3,000 个留出案例 94.7% 的 check/skip 决策正确；式 (2) 选更便宜检查 93% 正确。Haiku 规划器 + 像素检查将过时点击从 65–69% 降到 9–11%；按规划器实测 1.1 s 计费，每步净省 0.2–0.3 s。失败检查后"原地调整"在全部配置下均不安全（错误点击 ≥11%），必须重规划。

## 相关工作脉络
1. **PUSV**（Xu 2026, [1]）：形式化 GUI 智能体的 TOCTOU 攻击，用像素复核保护 6.5 s 规划间隔，但任何屏幕变化即报警，未测量普通页误报——本文像素检查通过排除自变化像素把误报从 21% 压到 0.5%。
2. **Atomicity for Agents**（Jiang et al. [11]）：监控浏览器智能体的页面变化并 halt，同样不适配普通加载页的持续动态。
3. **AOI / 预编译策略树**（[2][5]）：通过更快执行缩短规划间隔，本文证明间隔本身不是主因，缩短无益。
4. **VLM 空间判断局限**（BlindTest [8], DiffSpot [9], VisCritic [13]）：文献已指出 VLM 图像编码器能捕捉精细位置信息但文本输出丢失，本文给出跨模型、跨问题的直接数字对比。
5. **浏览器自动化框架**（Playwright [4]）：wait-for-element 已是工程常识，但智能体社区未系统采纳；本文量化"等待多久"的阈值。
6. **鲁棒性基准**（WAREX [18], StressWeb [19], DynamicGUIBench [20], WebDecept [21]）：注入网络延迟/弹窗/布局偏移，但未测量真实页在智能体截图之后的变化率，也未对比等待策略。
7. **机器人延迟动作**（Zhu et al. [10] 等 [15–17]）：预测自身运动以抵消推理延迟，网页无等效运动模型，解释了为何"调整点击"在此场景不安全。

## 局限性与未来方向
- 31 个真实页均为非商业、允许自动化的公共页，商业页仅通过 HTTP Archive 爬取间接测得"布局偏移率"，过时点击率未能直接验证（换算 Proxy 最高达 4.3× 实测值）。
- 商业页测量仅覆盖桌面首页，未触登录/购物车内的结账页；移动端差距收缩至 12.9 pp 且在完全记录子集内消失，结论主要针对桌面。
- 6 个合成页的过时率约 70%（vs 真实页 0.4%），基准作为压力测试，不反映真实基线。
- 仅用一个 Haiku 规划器，其 70% 自有错误来自任务生成器的相似标签，预检无法修复。
- 4B 模型在"动作是否成功"上取得 100%/0% 的完美分，可能因失败样本偏简单。
- 未来：测量训练数据管道中"动作前帧"的采集时机是否落入页面加载期；扩展至认证应用与持续更新仪表盘；在移动端复现商业页结论。

## 研究启发与可借鉴点
1. **"何时截图"比"多快规划"更关键**：工程上优先实现"networkidle（≤3 s）再截图"一条规则，即可在多数场景下消除绝大部分过时点击，成本低、收益高。
2. **感知手段按问题分工**：空间定位（目标是否还在原位）用像素比对，内容解读（动作结果、弹窗）用小模型/OCR；避免对一切问题都用大 VLM，既省钱又降延迟。
3. **盈亏公式可作为规则引擎**：给定 planner 延迟、候选检查延迟与历史过时率，实时决定 skip/check/re-plan，可直接嵌入 agent 循环。
4. **失败后必须重规划而非调整**：实验一致否定"原地调整"路径，这一结论可直接写成开发硬约束。
5. **合成压力基准的设计思路**：暂停时钟 + 精确间隔 + DOM ground truth + 冻结阈值后读标签，对下游 GUI 智能体的时序评测有复用价值。

## 关键术语表
- **Stale click（过时点击）**：智能体在截图时刻规划的目标坐标，到实际发送点击时该位置对应的元素已移动、消失或被遮挡。
- **Preflight（预检）**：在点击发送前运行的快速感知检查，用于回答目标位置/遮挡/动作结果三类问题。
- **Network idle（网络空闲）**：页面在 500 ms 内无新网络请求；本文推荐作为截图前的等待终止条件（封顶 3 s）。
- **Break-even formula（盈亏公式）**：式 (1) 给出检查的最低必要过时率阈值，仅依赖规划延迟、检查延迟、召回与误报。
- **Self-changing pixels（自变化像素）**：spinner、闪烁光标、ticker 等与智能体动作无关的屏幕动态，像素检查在规划时采样两张间隔截图后将其从搜索中剔除。
- **TOCTOU（Time-of-Check to Time-of-Use）**：检查时刻与使用时刻不一致导致的竞争条件；PUSV 将其形式化为 GUI 智能体的安全攻击模型。
- **DOM-ready**：浏览器完成 HTML 解析的时刻，通常早于图片/字体/数据到达，也是本文明确的风险高峰起点。
- **Live loop（活体回环）**：Claude Haiku 规划器在合成移动页上连续点击 400 步，对比有无预检的端到端表现。

## 可复现要素
- **数据集**：31 个公共页面（真实页）、HTTP Archive 2026-10 抓取（65 预订购买首页 + 3,028 .gov + 4,972 电商样本）、6 个合成移动页（4,608 点击对 + 3,600 动作结果对）；真实页截图因含第三方内容未公开，代码与基准生成器开源。
- **代码**：https://github.com/multimodal-ai-engineering/preflight-bench（基准生成器、页面、检查实现、爬取查询、先验注册、原始模型输出与分析代码）。
- **权重/模型**：开源模型 Qwen3-VL 2B/4B、SmolVLM2 2.2B、Florence-2；云端模型 Claude Haiku 5.5 / Opus 5.5（未开源，但输出已附仓库）。
- **关键超参**：像素搜索半径 40 px、自变化像素判定间隔 200 ms、networkidle 静默阈值 500 ms、封顶 3 s、规划间隔 6.5 s（来自 PUSV 测量）、k=2（普通点击）/ k=10（不可逆点击）。
